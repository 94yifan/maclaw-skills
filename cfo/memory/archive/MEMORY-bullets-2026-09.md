- **守卫W 落盘前置（长任务）**：凡可能因超时被中断的长任务（dreaming、长报告、批量写），把**不可重建的写动作**（MEMORY.md 区块、复盘文件）排在深度分析与取证之前；先落盘、后深挖。依据：9/19 因落盘排在失败前而侥幸保住，9/21 三轮因编辑排在分析后而全丢。
- **守卫X 对账范围按第二写者定标**：变更对账的字段集不由「我关心的字段」决定，而由「另一个写者最常修改的字段」决定。上线对账时先列第二写者的高频写入列并逐一纳入快照；未纳入即为已知盲区，须显式记录。依据：9/24 实测漏检。
- **守卫Y 「已跟踪 ≠ 已提交 ≠ 已推送」三态必须逐态取证**：声明「已备份」的判据不是 `git rev-list --left-right --count` 的 0/0（只证 ref 对齐，工作区改动可不进 diff），而是 `git show HEAD:<path> | grep <改动特征>` 命中（远端 tip 同理）；推送链路另加 ahead 计数归零。补充：挂账项有三种误处置——伪阻塞（不该挂的挂）、伪授权（该自己做的等人）、伪闭环（做了的谎报完成），消解方式同为动作层直证 + 三态逐态归零。
- **守卫Z 可达性负面结论必须带有效期**：凡「外部依赖不可达」类结论（网络/凭证/服务），**有效期到本会话结束**，下轮引用前必须重测一次，重测失败才可沿用，重测成功即当轮处置；写入格式 `<对象> 不可达（实测 YYYY-MM-DD HH:MM，下轮须复测）`。依据：9/27 实测「网络不通」为陈旧结论。
