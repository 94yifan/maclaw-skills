### 错误1：CDP 9333 端口不可用（今日致命错误）⭐⭐⭐

**现象：**
今日 10:05 AM cron 触发，状态为 `error`，爬虫未执行。

**根因：**
- CDP 9333 端口（yifan 用户真实 Chrome，有登录态）已不可用
- 检测结果：`curl http://127.0.0.1:9333/json` 超时失败
- 当前只有 18800 端口可用（openclaw browser，无登录态）
- `/tmp/tea-brand-crawler-v3.mjs` 脚本中写死了 `const CDP_URL = 'http://127.0.0.1:9333'`，未适配端口变化

**修复（具体代码改动）：**
修改脚本，增加端口fallback机制：

```javascript
// 尝试多个CDP端口
const CDP_PORTS = [9333, 18800];
let browser;
for (const port of CDP_PORTS) {
  try {
    const url = `http://127.0.0.1:${port}`;
    browser = await chromium.connectOverCDP(url);
    console.log(`Connected via CDP port ${port}`);
    break;
  } catch (e) {
    console.log(`Port ${port} failed: ${e.message}`);
    if (port === CDP_PORTS[CDP_PORTS.length - 1]) throw new Error('All CDP ports failed');
  }
}
```

**预防：**
- 脚本必须自动探测可用端口，不能写死
- 每次爬虫执行前，在 workspace 写一个端口探测脚本先跑，探测成功后再启动爬虫

### 错误2：state 文件未重置（跨日遗留问题）

**现象：**
`/tmp/tea-crawl-state.json` 内容日期为 `"date": "2026-04-30"`，已爬 18/18 品牌。

**根因：**
脚本在启动时会检查 `state.date === today`，如果不是今天就重置。但今天（5月1日）脚本根本没有运行到检查逻辑——因为CDP连接就失败了，脚本根本没进来，所以state文件保持昨天的状态没变。

**修复：**
```javascript
// 脚本启动时强制清理非今日state
const today = new Date().toISOString().slice(0, 10);
if (fs.existsSync(STATE_FILE)) {
  const s = JSON.parse(fs.readFileSync(STATE_FILE, 'utf8'));
  if (s.date !== today) {
    console.log(`State file is from ${s.date}, resetting for today ${today}`);
    fs.writeFileSync(STATE_FILE, JSON.stringify({ date: today, done: 0, results: {} }, null, 2));
  }
}
```

**预防：**
state文件清理逻辑要放在CDP连接之前，确保即使连接失败也能重置状态。
