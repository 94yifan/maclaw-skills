**问题1：subagent 任务被 gateway reload 中断后恢复不完整**
今天 13:02 触发了一个 subagent 任务（调研老子《道德经》），13:11 被 gateway reload 中断。subagent 被要求从断点继续，但之前已完成的内容没有完整交接，导致子任务可能需要从头确认进度。

根因是 gateway reload 时没有保存完整的任务上下文到共享存储（比如写入文件而非只依赖内存）。subagent 的上下文恢复依赖会话继承，但在隔离模式下丢失了中间态。

修复动作：在 subagent 执行长时间任务时，每完成一个阶段（比如每20章）立即写入文件作为 checkpoint，而非等到任务全部完成才保存。这样即使中断，从文件恢复比从会话恢复更可靠。

以后怎么提前发现：对于超过10分钟的多阶段任务，建立强制 checkpoint 机制——每个阶段完成后必须写文件，否则不允许进入下一阶段。
