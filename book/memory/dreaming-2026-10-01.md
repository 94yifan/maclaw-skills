   - 根因：**自我状态断言的证据在观察边界之外。** run 能观察自己的产物（文件、commit），不能观察自己的生命周期（是否被调度器超时终止）；后者只存在于 cron 遥测里，run 内部无法取证。故关于自身生命周期的完成态断言，在 run 内结构性不可自证——守卫十七要求的「同会话命令输出」在此根本不存在于 run 内。
3. **A3（book 自身，承接）：本 cron 300s 超时连续第 8 轮**（`consecutiveErrors=8`，last_duration≈300150ms）。9/30 槽虽产物幸存，status 仍记 error——`status` 度量 run 结局，`产物存在` 度量交付，二者不同层；用 run status 判「book 是否完成交付」会误读（9/30 即假失败：产物全在、status 报错）。

## B. 规避方案
- 立**规则 16**（自我状态宣称必须取自观察边界外的证据）：凡关于 run 自身生命周期的断言（「本轮未超时/未截断/正常结束/已投递」），禁止由 run 内部产物推导；必须以 cron 遥测（status/durationMs/diagnostics）为证，取不到即写「待外部核」，禁止用「实测」「已验证」等措辞美化。绑决策点：每日 Dreaming 结果校验段 + 执行记录段。
