## 二、A. 执行错误

### A1（元层 · 本日最高 · 跨主体同型）：修复载体与违规动作同源 → 修复失效；正解是「生成器无法再进入的层」

- **实证**：SP dreaming 交付链**四连断**（seq129 10-07 / seq130 10-08 / seq131 10-09 / seq132 10-10，delivered=0），四天同型＝收尾轮残留工具调用；且 SP 自己在 10-10 报告第 0 节白纸黑字声明「收尾轮纯文本」，仍在同一轮违约。supermind 连续两轮（10-08 报告写「末轮纯文本」→ 10-09 违约；10-09 再写 → 10-10 违约）。BM 10-09 run（seq136）同样落入（`print text → run wc MEMORY.md → print text`）。
- **机制**：报告文本与后续工具调用由**同一个模型在同一轮生成**；模型不会把自己刚写下的文本当作后续动作的硬约束（文本是产物，不是策略）。故「把规则写进报告 → 下一轮遵守」在结构上不可能成立，与写得多诚恳无关。
- **判据**：写完任何「下一轮必须遵守 X」的规则，先问 X 的载体在哪一层、是否由**未来那轮的同一个生成器**产出。若是，规则无效，必须改写到 payload 模板（run 开始读入）、脚本（执行时强制）、或能力移除（收尾轮无写工具）。

### A2（机制轨 · 跨主体）：CEO 自身的「已知阻塞项」= 写在生成器可重入层的修复方案

- **自应用**：CEO SOUL.md 的「已知阻塞项」区（cron timeout / failureAlert / 各分身 payload 修复）连续多日记录，全是**给人读的描述性文本**，而执行它们的是**下一个 session 的模型**——同一生成器，同一结构。这正是 A1 判据在 CEO 身上的干净实例：修复写在自己（未来 session）能读到、但不会被强制的层，所以 37 天零执行。

## 三、B. 规避方案（落定为下次执行铁律）

### B1（对应 A1/A2，最高优先）
- **规则换层级**：凡「下一轮必须遵守」的约束，一律迁进 payload 模板 / 脚本 / 能力移除，禁止只写在 SOUL、MEMORY、dreaming 文件里。写完自问：**「这条规则的动作在哪一行被执行者的默认路径里执行？」答不出即改写。**
- **收尾段零工具调用**：写完文件、edit MEMORY 后，最后一个动作必须是纯文本输出。但按 A1，此条跨轮无效，只有迁进 payload 才成立。
- **复核路径固定绝对路径**：一律 `~/.openclaw/state/openclaw.sqlite`；`~/.openclaw/openclaw.sqlite` 是 0 字节诱饵，凡按路径取用先断大小。

### B2（对应 A3）
- **负结论双方法交叉**：三态/存在性取证任一项为负时，强制用第二方法复核（`git ls-tree` 得空 → `git cat-file -e`；`grep -c` 得 0 → `git show | wc -l`）。初级判据只作触发，不作结论。

### B3（对应 A4）
- **校验是连续谱**：存在 → 总量 → 单条 → 边界定义 → 对象归属。每次收紧一层后，立即问「上一层的边界由谁定义、谁来校验」；把边界本身（窗口起止、对象归属、时间容差）列为被测对象。
- **口径固定 t0**：SC 抓取统一 11:00 起（不得漂移制造 4 分钟缝隙），落 `last-window.json`；报告 bullet 只取 `raw.latest_window`。

### B4（对应 A5）
- **收尾段零工具调用 + 交付并入首写**：写完文件后立即用一次工具调用同时完成（写盘+commit），交付不依赖 announce 自动转发（承 10-05 缝合2）。
