# Knowledge Forge（知识熔炼）

同时做两件事：
1. **知识入库**：把新知识结构化，缝进知识图谱
2. **方法论生成**：从知识里长出新的营销模型和方法论

---

## 输入格式

逸凡发来的任何内容（案例片段、文章、数据、洞察、碎碎念）都是输入。

---

## 执行流程（C=A+B 并行）

### 第一步：判断知识类型

| 类型 | 提取什么 | 示例 |
| ---- | -------- | ---- |
| 案例 | 矛盾结构、复用性、情动点 | "某品牌做了一个IP联名活动" |
| 数据 | 指标定义、因果关系、临界点 | "小红书酒水搜索增长2281%" |
| 方法 | 流程步骤、使用边界、升级条件 | "KFS打法的具体操作" |
| 洞察 | 核心观点、反驳点、应用场景 | "用户决策前移了" |
| 名词 | 定义、出身、应用场景 | "A1A2人群是什么意思" |

### 第二步：知识入库（A）

提取实体，追加到 `memory/knowledge-graph.md`，格式：

```markdown
## [实体名称]

**类型**：案例/数据/方法/洞察/名词/概念
**定义**：[一句话]
**关键属性**：[3-5条]

**关系**：
- 导致 → [结果/影响]
- 属于 → [上层分类]
- 类似 → [相近概念]
- 成因 → [原因]

**应用场景**：[2-3个]

**来源**：[来自哪]
**入库日期**：YYYY-MM-DD
```

同时更新 `memory/knowledge-index.md` 的对应分类。

### 第三步：方法论生成（B）

问自己三个问题：

**Q1：这张知识和其他知识能不能拼出更大画面？**
- 在图谱里找相关节点，看能不能组合出新的框架
- 组合示例：KFS + 酒水场景 + 人群决策前移 → "场景截流"模型

**Q2：这个知识能不能提炼成一个可命名的公式？**
- 找核心变量，给变量命名，形成公式
- 示例：内容密度 × 文化锚点强度 ÷ 用户认知成本 = 传播力

**Q3：这个知识指向什么新营销名词？**
- 基于洞察，给一个简洁有力的名字
- 要求：四个字以内、能被不懂的人听懂、能用在提案里

### 第四步：输出结构（面向逸凡的汇报格式）

#### 知识入库部分

用自然段落描述，不要用箭头格式，直接说清楚这个知识是什么、为什么值得关注：

```
【知识入库】

[实体名称]
这是什么：[一句话定义，说给不懂的人听]
为什么重要：[它解决了什么问题，或者揭示了什么新趋势]
怎么用：[举一个具体场景]

```

#### 方法论更新部分（需要共创时）

每个方法论必须包含：
1. **名字**：四个字或两个字，用核心动作命名
2. **公式/核心逻辑**：用自然语言说清楚变量之间的关系，不要用符号
3. **应用场景**：这个方法论什么时候用？（提案的哪个环节、写方案的哪个部分、复盘的哪个维度）
4. **核心词汇解释**：每个关键术语说人话，它想表达什么、不是什么、举例说明
5. **和其他方法的区别**：这个方法论和其他已有的有什么不同，为什么要单独命名

```
【方法论更新】

[方法论名]
它是什么：[用一句话说清楚，不要用符号]
用在什么时候：[提案的XX环节 / 写方案的XX部分 / 做复盘的XX维度]
核心逻辑：[变量A + 变量B = 什么？为什么这样组合？]
关键词汇：[词1-说人话解释，举例 / 词2-说人话解释，举例]
跟现有方法的区别：[如果有类似的方法，说清楚这个新在哪里，不同在哪里]

```

**重要：方法论输出只在需要逸凡确认或共创时，才写这么详细。如果方法论已经成熟，直接入库即可，不需要汇报。**

---

## 关键约束

**生成比存储更重要。** 入库是基本动作，生成新方法论才是核心价值。
不为了生成而生成——必须基于真实知识，有逻辑链，有应用场景。

**汇报说人话。** 所有输出给逸凡的内容，必须：
- 不用箭头格式（→ × ÷ 等符号）
- 每句话说完整，不跳跃
- 每个词汇说清楚它想表达什么
- 有具体场景，不是关键词罗列

**方法论命名规则**：
- 四个字为主，例外可二字
- 动宾结构优先（"场景截流"比"场景截流策略"好）
- 必须能从字面推出含义，不能猜
- 不能和已有营销名词重复（先查知识图谱）
