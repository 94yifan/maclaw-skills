## B. 规避方案（每条对应 A 项，作为下次执行铁律）

1. **同型缺陷横向外扩（对应 A1，SP 侧今日新立）**：①系统状态类陈述写入 MEMORY 前，强制以 `cron_jobs`/`cron_run_logs` 对账；②**dreaming 时对兄弟分身（SC/CFO 等）的 MEMORY 系统陈述做一次抽样对账**，不能只查自己 —— 同型缺陷跨分身出现即为系统性缺陷，须在 SP 侧建立跨分身对账点。
2. **run 内工具禁令（对应 A2，第 6 天，最高优先，仅主 session 可改）**：payload 加「写完报告立即输出正文并结束、不得再发起任何工具调用」「run 内禁止 cron 工具 get/update/remove」「收尾校验类命令默认不跑（可选项加 `|| true`）」三条硬约束。
3. **交付兜底（对应 A2，新增）**：给 tea-daily-report 加交付重试，或「写文件后立即 `message` 发群」，把交付从「run 成功才发生」解耦为「文件写好即发」。
4. **header 存在性校验（对应 A3，新增）**：报告写入后强制校验前 3 行含标题 +「窗口：」+「覆盖：」，缺一即补，不允许无头产出进群。对应 SOUL 推理守卫九「校验存在（最弱档）」。
5. **窗口改造一步到位（对应 A4，第 8 天）**：脚本开头 `const t0 = Date.now()` 一次，全品牌统一 `created_at ∈ (t0-24h, t0]`，header 与 raw `crawlTime` 引用同一 t0；写 `lastWindowEnd`，次日起点取 `max(t0-24h, lastWindowEnd)`；头注释日期改当天。
6. **合并帖逐条分列（对应 A5，第 5 天）**：合并多帖为一个 bullet 时逐条写各自三元组，不加总不给范围。
7. **无动态日期直取 raw latest（对应 A6）**：日期取 raw `latest` 秒级字段，抽奖类另括注「窗口内仅抽奖公示」。
8. **配置类待办显式隔离（沿 9/14）**：MEMORY 里所有「需主 session/逸凡执行」的待办一律标注「仅主 session 执行，cron run 内禁止尝试」。
