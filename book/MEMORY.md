### book-deep-reading Skill 框架（已建提案待固化）

#### 第一步：判断书籍类型
拿到数据后先判断书是什么类型，不同类型用不同内容结构：
- 方法论/操作手册（如《学会提问》）→ 核心流程Step + 概念详解
- 故事/传记 → 关键事件 + 人物分析 + 经验提炼
- 哲学/认知科学 → 核心概念 + 知识体系 + 现实关联
- 商业/案例 → 核心论点 + 案例详解 + 可复制模式
- 文学/社会观察 → 核心主题 + 关键情节分析 + 现实映射

#### 内容标准（逸凡确认的量化要求）
- **总字数**：原书约1/10，8000-10000字
- **核心内容**：核心框架流程 + 重要概念详解——占最大篇幅
- **双源案例**：每个概念配内部案例（书中）+ 外部案例（真实事件）
- **案例4要素**：对象介绍（≥40字，说清「是什么」）→ 具体行为/事件（≥50字）→ 分析与关联（≥60字）→ 学习价值（≥30字）
- **外部案例**：必须真实事件，近5年，不确定的写「待验证」绝不编造
- **金句**：8-10条，不标注划线人数，每条附≥60字思考价值分析
- **延伸思考**：费曼学习法提问3-5个（带具体场景）+ 生活/工作实践设计4-5个（可操作）
- **输出**：直接发 .md 文件到飞书群，不搞飞书文档

#### 思维导图标准
- **结构**：树状（自上而下），不是放射状
- **节点**：完整句子（10-20字），不堆关键词
- **排版**：文字清晰无重叠，间距gap≥8px，浅色背景+圆角卡片+色彩分区
- **技术**：纯CSS flex + SVG + 原生JS，无外部依赖
- **交互**：滚轮缩放 + 拖拽平移
- **必须预览**：截图先本地查看再发

#### 踩坑（必须记住）

2. 数量与书中一致——书中9种谬误就写9种，不多不少

**关键见解：** 在AI Agent的语境下，"用户沉默"不是环境恶化，而是信号指示当前行为模式不匹配当前环境。智慧的表现不是"做更努力一些的等待"，而是**切换行为模式**。

### 串联3：三元模式迁移——从protocol lifecycle到communication lifecycle

Phase 1的三种协议模式（标准/精简/退出）可以重新映射为Phase 2的communication的自适应形态：

| Phase 1 Protocol | → Phase 2 Communication |
|-----------------|------------------------|
| 标准模式（有数据时完整复盘） | 主动对话（有反馈时深度陪读） |
| 精简模式（数据稀疏时收缩） | 轻量触达（无反馈时短频试探） |
| 退出条件（零数据时解绑） | 通道切换（持续无响应时变换渠道） |

**可复用框架：** 任何等待反馈的场景都应该预设三档行动模式（强互动/弱互动/换通道），并给每档设定退出条件和切换条件。

### 串联4：D8+元意义——从"知识缝合"到"系统缝合"

**核心观察：** 当系统处于无新数据输入的状态时，"知识缝合"的对象不应强行指向书的空位，而应该**转向缝合系统自身运行经验**——把AI Agent与用户交互的元经验封装进MEMORY.md，成为未来有数据时处理关系的默认认知框架。

这类似于一本"空书"的语义——当书架是空的，你仍然可以写一本关于「如何管理空书架」的书。Phase 1+2的完整协议演化图谱，就是这本关于「空书架管理」的书。
