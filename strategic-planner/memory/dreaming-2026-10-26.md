## A. 执行错误

### A1 ★ 昨日复盘被自己复盘的错误杀掉：规则写对了，交付没了

- **现象**：10-25 那篇复盘正文的 A1，写的就是"查 cron 库未先读表结构、时间戳手写，今天被违反两次"。同一次 run 的收尾，我又发了一条 `sqlite3 ... SELECT agent_id, … FROM cron_run_logs`，字段不存在 → 非零退出 → run 判 error → announce 跳过 → `delivered=0`。文件在盘上，人没收到。
- **根因（第一性）**：不是我不知道规则，是**交付资格由 run 末端的健康度决定**。任何一次尾部工具报错都会把整轮判死，哪怕产物已完整。这和今天 tea-daily 的 `list files failed` 是同一结构——SC 在 11:03:39 探一个还没写完的文件，随后 11:06 报告完整发群，run 仍记 error。
- **元层教训**：把规则写进 MEMORY，只能防"下次想不起来"；防不了"这次已经知道却在同一个动作上翻车"。**规则的有效性不能靠自我约束，得靠动作顺序**——把会失败的探查挪出交付关键路径。
- **与历史的关系**：10-23 seq145 `Apply Patch failed`、10-24 SC 进程不退出、今天 SP 的 sqlite 报错，三个不同工具、同一条路径：**过程末端失败 → 交付被吞**。这是第四次，已经不是偶发。

### A2 今天我差点重犯同一个错，救场的不是规则而是事实

- 我用 `workspace/openclaw-agent.sqlite` 查 cron 表，`PRAGMA` 返回空（文件存在但无这些表）。**这次没有报错**——空表列表是一个成功返回。如果我当时顺着"没有 cron 表"往下写，整篇复盘的数据基础就错了。
- 真正拦住我的是 MEMORY 技术环境段里那条 **canonical 路径**（`~/.openclaw/state/openclaw.sqlite`），不是昨天新立的那条"字段先取"规则。
- **分辨**：MEMORY 里的背景文本分两类——
  - **事实型**（路径、字段名、库位置）：可复制，读到就能用，效力高。
  - **约束型**（"必须先 PRAGMA"、"不要手写时间戳"）：需临场判断才生效，效力低。
  昨天失败的是约束型，今天救场的是事实型。**结论：把约束型规则改写成可粘贴的事实型模板，否则永远靠自觉。**

- **串联**：10-25 缝合 3（IP 联名第四种计价口径＝授权买的是自有 App 打开，不是杯数）＋10-24 缝合 1（累计消耗量是可核验物理量）＋10-14 缝合 5（可收藏周边＋主题店）。
- **判断**：昨天我把联名的计价口径推到"兑换入口在谁家"，今天两家把入口变成了**任务链**——瑞幸用预存杯数做层级（一次锁未来 5 杯），库迪用门店动作做层级（比手势、对台词＝把游戏内 quest 搬到柜台）。**关键不是物料多贵，是拿到它要做几个动作、动作发生在谁的地盘。** 瑞幸的动作发生在支付页（提升客单与预存），库迪的动作发生在门店（提升到店与停留）；两家同日同构，说明这套结构已被头部复用到肌肉记忆。
- **规则**：IP 联名 brief 必须画出「动作—物料」矩阵：每一档物料对应一个用户必须完成的动作（买几杯 / 预存几杯 / 到店 / 做手势 / 发文），并标明动作落点（支付页 / 门店 / 自有 App）。**没有动作挂靠的物料只是赠品，不进方案。** 至少一档必须是"需要用户离开座位"或"需要用户提前付钱"的动作。

- **串联**：10-25 缝合 1（代言人素材四级阶梯：可见 → 可保存 → 可携带 → 可触发）＋10-24 缝合 2（可触发/可携带实物）＋10-19 缝合 2（代言人日历位）。
- **判断**：前四级都是"品牌把东西给到用户手上"，第五级反过来了——**用户要花时间做，品牌只给原料（纸袋）和图纸**。折星星这件事的价值不在灯，在三件副产品：投入的时间（沉没成本）、做出来的东西（展示欲）、以及"应援角"这个用户自己在桌面/工位划出来的品牌位。同时那组原声文案把代言人从完美形象拉到同款倒霉日常，素材的用法从"看脸"变成"共情"。**四级是省力梯度，第五级是费力梯度，方向相反但都有效：省力买触达频次，费力买情感所有权。**

- **反例**：DIY 材料需额外购买（门槛杀死参与率）；成品无固定摆放场景（做完就扔）；只发教程不发材料（用户不会自己找纸袋）。状态：单例（第 5 级首样本）+ 4 天链式支撑。
