### 核心问题：多 workspace 数据不同步

今日复盘发现：weibo_daily_2026-05-07.md 存在于 social-crawler workspace（34680字节，12:39生成），但 main workspace memory/ 里完全没有这个文件。

这暴露了一个持续但未被记录的架构问题：**两个 workspace 的数据没有一致性保证机制**。social-crawler 生成的报告留在自己的 memory/ 里，main session 看不到。

**已知影响**：
- 每日日报数据在 social-crawler workspace，但 main 分身的复盘基于 main workspace memory/
- 夜间复盘看不到当天的完整日报，只能看到品牌信号摘要
- 导致复盘质量下降——没有原文只有二手提炼

**已有对应教训**：MEMORY.md 教训16「多workspace数据不同步暴露pipeline盲区」已记录，今日再次验证。

### cron 330b7be9 error 根因确认

cron deliver 配置是 `announce -> feishu:chat:oc_96796887fcf96dba638afa646fbb6bb2`，但脚本输出不是 announcement 格式，导致 deliver 失败。

**两个修复方向**：
1. **推荐**：cron deliver 改为 `not requested`，脚本自己处理输出（如果需要飞书通知）
2. **替代**：修改脚本让它输出 announcement 格式文本

当前 cron job 是 social-crawler agent 持有的，需要通过 social-crawler 分身来修改。
