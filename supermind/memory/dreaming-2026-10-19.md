## D. 知识串联（核心）

### 缝合1（主，指标层）：修复一层会关闭对另一层的审查，绿灯是注意力终点，不是质量证明

**今天的数据**：茶饮日报 `a19839ba` 11:00 ok / 304,768ms / delivered=1，是三连败后首次自动送达。同一份报告里，SC 自己的 A2 与 A3 是连续第 2 天重复：采集说明写「接口 ok=1」而 raw 里没有 ok 字段；守恒式只写 `17 = 16 + 1`，漏掉 2 个剔除与 2 个合并项。

**串联**：10-18 缝合1（症状迁移会被误读成问题解决）× 09-19 缝合（日报四连绿被证伪，失败率 32%）× 守卫二十（读数段）。

**新认知**：昨天讲的是症状会换面孔，今天讲的是指标的注意力属性。交付失败是当时唯一的强制审查入口；它一转绿，同一份文件里的口径缺陷就失去了读者。交付层的绿灯在账面上等价于「今天这份报告不需要看」，而实际发生的事是「今天这份报告的错误没人看」。

**判据**：交付状态与内容口径必须各有验收清单，前者转绿不得关闭后者；对外交付同时报两项，即交付状态加口径缺陷数。0 缺陷的日报按未检查审。

### 缝合2（主，挂账层）：挂账项的前提会过期，过期后补做等于打错层

**今天的数据**：dreaming 全部 job 的 `payload_timeout_seconds` 已是 600（9 月清单里的处方），而今日唯一 error 是 196,903ms 的 `Apply Patch failed`，与超时无关。同一周内，10-13 记失败形态迁到收尾工具调用，10-17 迁到自更新重启，10-18 迁到 CPU 与磁盘空转。

**串联**：10-13 缝合（失败形态已从超时迁移，配置修复打错层）× 10-17 缝合1 × 10-18 缝合1（症状迁移）。

**新认知**：10-18 的结论停在「读数要按当日重算」，那是观测纪律。今天走到待办层：挂账不是静态债务，是会过期的期权。等待时间越长，处方与病灶的对应关系越松，而执行时的动作完全一样（照单做），所以假通过的概率随时间单调上升。

**判据**：任何挂起超过一天的待办，执行前先做前提复算，即读一次当前配置与当前错误文本；两者仍指向该处方才动手，否则写「前提已过期」并重新定级。补做动作本身不算进展。

### 缝合3（主，治理层）：观测冗余会伪装成进展，多主体记账不等于有人负责

**今天的数据**：update.once 第 5 天，runs 14,922，日志 40.95MB，24 小时 +11.5MB。SC 今日写「P0 第 2 天未处理」，SP 今日写「宿主 P0 第 3 天未除」，本 agent 10-18 写「需拍板」。三份复盘均格式完整、读数准确、结论一致，三天零次发送。

**串联**：10-11 缝合（三主体独立收敛，卡点从发现转为授权）× 09-14 缝合9（告警通道不得与交付通道同构）× 守卫七（逸凡感知窗口）。

**新认知**：单主体漏报是可见的空白，多主体冗余观测是不可见的空白。每份复盘都在尽责，账面上表现为高频关注，实际执行量为零，而且因为「三方都在盯」而没有人觉得自己该动手。冗余降低的是漏报概率，不是触达概率，两者被混为一谈。

**判据**：同一 P0 被两个以上主体发现时，24 小时内指定唯一触达人（发现顺序第一人），其余主体只引用；触达必须留回执，没有回执的「已上报」按未上报计。授权类事项触达一次即止，不重复催，避免把复盘变成催促流水。

### 缝合4（主，记忆体量）：MEMORY 增长与业务产出反向，零产出主体的记忆膨胀最快

**今天的数据**：SP 620,320B 涨自 09-19 的 458,020B（+162KB/30 天），同期 31 天零项目产出；brain-mining 527,463B；root 190,628B 已破 150KB 线；supermind 80,969B，有产出且有归档机制。

**串联**：09-21 缝合（超时后自动重试等于全量重跑，成本按轮数相乘）× MEMORY 膨胀是 cron 超时的结构性根因 × 09-13 守卫十一（规则必绑决策点）。

**新认知**：这是一个正反馈环。没有业务产出时，复盘成为唯一产出，于是复盘写得更长更细；文件越长，每轮读取与写入成本越高，run 越容易贴顶或中断；失败越多，关于失败的复盘越多；下一轮更长。膨胀不是懒惰的产物，是「唯一产出」被当成了业绩的产物。

**判据**：设缝合唱预算，每轮不超过 3 条主缝合、单轮文件不超过 8,000 字（字符计）；对连续 7 天零业务产出的主体，MEMORY 只归档不新增分析段。体量不是质量指标，可检索才是。

**自我修正（本轮即时发生）**：初稿把预算写成 8KB，而本轮文件是 16,098 字节，当场违反了自己刚立的规则。错在阈值单位与被测对象不同层：中文文件字节数约为字符数的 2.1 倍，用字节定预算等于对中文更严、对英文更松。已改为字符计，这是守卫十四（校验目标不得互斥）在写作层的同型复现：规则若让守规比违规更难，写规则的人自己就会违。

### 缝合5（次，载体层）：规则落地率由载体决定，不由重要性决定

**今天的数据**：SC 10-18 的 4 项改进今日 0 落地，今日落地 2 项都是写进脚本与 skill 的（canonical 抓取脚本、skill 内一条规则）。本 agent 昨日 5 条改进，今日可验证落地 1 条（读已落盘产物，属行为约束），其余 4 条无载体。

**串联**：09-13 守卫十一（规则必绑决策点，脚本大于 MEMORY 大于 dreaming 文件）× 09-17 守卫十八（修复绑在发现它的会话）× 10-13 缝合（复盘改进计划是挂账第四形态）。

**新认知**：可以把载体做成一档排序，转化率从高到低为：脚本里的判断、门禁字段、skill 内步骤、MEMORY 规则段、dreaming 待办。今天有了同一天的对照数据：dreaming 待办 0/4，脚本与 skill 2/2。这个排序解释了过去两个月的多数「连续 N 天未落地」。

**判据**：任何改进项先问载体是什么，答「下次记得」即视为未落地；复盘只统计有载体的项为已落地，其余进入「观察中」，不计入完成率。

### 缝合6（次，一致性层）：跨主体无可比字段，守卫十二在报告层没有落点

**今天的数据**：四份复盘四种结构，同一 P0 只能靠人工 grep。SC 的守恒式漏项、CFO 的待回复项、SP 的待用标签，都不在任何共享字段里。

**串联**：09-13 守卫十二（一致性检查与正确性检查并列）× 09-19 跨分身抽样对账点。

**新认知**：一致性检查要能执行，前提是被比较的对象有共同刻度。四个格式各自内部自洽，横向不可比，于是「每次办得不一样」这种缺陷在报告层永远查不出，只能在结果层等它出事。

**判据**：跨主体复盘至少统一三项：日期、未闭环项 ID、触达回执。抽取靠脚本，不靠人读。
