# 第7章 模型后训练

## 本章核心论题

本章的核心论题是：如何通过后训练（SFT 与 RL）改动模型权重，把 Agent 利用上下文和工具的能力"沉淀"进参数。全书公式 Agent = LLM + 上下文 + 工具，本章聚焦于优化 LLM 这个"大脑"——第六章的评估体系与仿真环境是后训练的两块基石，评估环境为训练提供练习场，评估指标为训练定义目标。本章从"一个模型是怎么被训练出来的"讲起，把预训练、SFT、RL 每一步的目的、原理及组合方式讲透，面向完全没有 RL 或模型训练背景的读者，最终回答：模型的能力在哪些阶段形成、每一步在做什么、如何选择与组合，以及在自己的项目里该在哪一步下功夫。

## 关键论点与框架

### 论点一：模型能力开发通常分为预训练、SFT、RL 三个阶段，三者在"预测下一个词"这一统一框架下运作，区别仅在于数据、优化目标和代价
- **论证与机理**：SFT 在数学上和预训练是同一个任务——都是预测下一个词、最小化同一个损失函数。SFT 与预训练的差别只有两点：① 数据不同——预训练用原始互联网文本，SFT 用人工准备的"输入—输出"对；② 损失只算在"回答"上（loss masking），把问题部分的 token 屏蔽掉，只对回答部分回传梯度。模型的输出本质上是一个概率分布，三个阶段的区别只在于"想要什么"以及"用什么信号来定义想要"。
- **书中案例/证据**：表 7-1 给出三阶段总览——预训练用海量原始文本、优化预测下一个词、学会语言规律与世界知识、代价极高（数千万美元）；SFT 用几千到几万条示范对、同样优化预测下一个词、学会指令遵循与输出格式，代价低（几小时到几天）；RL 用任务环境加奖励信号、优化期望奖励、学到可迁移决策策略，代价是 SFT 的几十到上百倍。
- **出处锚点**：7.1 节"预训练、SFT、RL：三阶段全景"。

### 论点二：在本章的对照实验中，SFT 更容易记住示范，而 RL 表现出更好的泛化——这种倾向源于两者的优化目标不同
- **论证与机理**：SFT 最大化标注回答的概率（极大似然），驱动模型尽量复现示范中的 token 序列；示范或 prompt 缺乏多样性时，模型可能对表面模式或捷径过拟合。RL 最大化期望奖励，模型探索多条路径并提高高奖励路径的概率；当奖励忠实反映目标、探索足够时，模型可能发现示范中没有的可迁移策略。从概率分布看，SFT 表现出 mass-covering（覆盖式）倾向——尽量覆盖训练数据中的多个模式；RL 配合反向 KL 约束时表现出 mode-seeking（寻峰）倾向——概率集中到少数高奖励峰上。
- **书中案例/证据**：GeneralPoints（实验 7-11）在算术卡牌游戏中，训练时 J/Q/K 都计为 10，测试时分别计为 11/12/13。规则 OOD 上：RL 在 GP-L 上 +3.5%，SFT 下降 8.1%；视觉 OOD 上（训练黑色花色、测试红色花色）：RL+17.6%，SFT 下降 9.9%。作者解释：有限的 SFT 数据强化了"遇到 J/Q/K 就当 10 用"的固定模式；结果导向的 RL 分支则更可能强化"重新计算直到得到正确答案"的策略。V-IRL-VL（实验 7-12）在多轮视觉导航中观察到同样模式：RL 在规则和视觉 OOD 上均明显优于 SFT。但这不是 SFT 与 RL 的普遍属性：数据足够多样且正则化得当时 SFT 也能泛化，奖励或环境有偏时 RL 也会过拟合。
- **出处锚点**：7.1.4 节"SFT 与 RL 的本质区别"、实验 7-11 GeneralPoints、实验 7-12 V-IRL-VL。

### 论点三：数据和环境比算法更重要——这是工业界最反直觉也最值钱的经验
- **论证与机理**：现成的 RL 算法（PPO、GRPO 等）你知道怎么用就够了，真正决定成败的是两件事：仿真环境的保真度（模型练习的场地够不够真实）和训练数据的质量（示范和奖励信号的质量够不够高）。姚顺雨在《The Second Half》中回顾了 OpenAI 的认知演变：第一阶段（2015-2016）算法中心主义——以为更好的算法才是关键；第二阶段（2016-2018）环境的重要性——Gym 标准化任务、Universe 试图把整个互联网变成 RL 训练环境；第三阶段（2018 至今）先验的觉醒——GPT 系列展示语言预训练的强大，最重要的发现是：先验知识可以通过与 RL 完全无关的方式获得。最终的优先级是：先验 > 环境 > 算法。很多场景下只要 SFT 数据质量到位，甚至不需要做 RL。
- **书中案例/证据**：实验 7-2 在同一个寻宝游戏中对比 Q-learning 与 LLM Agent（Kimi K3）。Q-learning 跑 10000 局仅需 10 秒但需要近万次试错才收敛；LLM Agent 第一局就在 18 步内通关，因为携带了海量预训练先验知识——理解了"门""钥匙""剑"的概念结构，每一步都有目的和逻辑支撑。当游戏规则变化时，Q-learning 需要完全重新训练，LLM Agent 却能通过推理直接适应。实验 7-3（从头训练 LLM）进一步说明：在固定的小规模预算下，算法改进（QK Norm 和 Muon 优化器，收敛速度提升 3 倍）比单纯堆规模更具性价比——但这是参数预算内的方法论，与大模型自带的先验知识是两种不同的杠杆。
- **出处锚点**：7.1 节开篇的两条主线、7.2.2 节"基于预训练 LLM 策略的 Agent"、实验 7-2。

### 论点四：在结构化输出不稳定的设置中，稳妥策略是"先 SFT 后 RL"——先形后神
- **论证与机理**：RL 用奖励信号评估模型自己生成的回答，要判断好坏，首先得能把输出解析出来。如果模型吐出的是一团格式混乱的文本，奖励函数连"成功还是失败"都判断不了，RL 无从学起。因此 SFT 先扮演"把话说利索"的角色：用少量示范让输出格式稳定、能被可靠解析，RL 才有一个能打分的起点。SFT 先把"形"（格式、结构）立起来，RL 再追求"神"（策略、泛化）。这个"必须先 SFT"的结论是在"较小基础模型 + 严格结构化输出"设定下成立的。
- **书中案例/证据**：实验 7-11（GeneralPoints）中，未经 SFT 直接对 Llama-3.2-Vision-11B 做端到端 RL 完全失败，因为基础模型无法产生结构化输出，奖励根本无法计算。但 DeepSeek-R1-Zero 证明了足够强的基础模型可以跳过 SFT 直接 RL 成功，自发涌现出反思与长链思考——代价是输出可读性差、中英文混杂。所以 DeepSeek 最终仍在 R1 里加回"冷启动 SFT"，把"形"重新立稳。R1 从 Zero 到冷启动的往返，正是"先形后神"的最好注脚。
- **出处锚点**：7.1.3 节"什么时候需要先 SFT 后 RL"、7.6 节"何时选择 SFT，何时选择 RL"。

### 论点五：强化学习的瓶颈不在算法，而在环境工程——环境真实、可重置、可并行，是 RL 的前置条件而非完成后的附属品
- **论证与机理**：RL 的本质是"试错学习"，试错必须有试错的场地。环境的保真度直接决定训练出的策略能不能用——环境失真，策略必废。构建高保真环境常常比训练本身更贵更难。在造不出真实环境的场景下，可以用模型来模拟环境（两个层次：模型合成工具调用的返回值，如 ZeroSearch；模型仿真整体环境动态，如 DreamGym）。但这条路线有本质风险：模拟器的世界知识就是训练的天花板，模拟器的系统性偏差会被策略照单全收，RL 还会主动寻找并利用模拟器的漏洞（reward hacking）。工程上的稳妥做法是混合：用模型模拟承担大部分交互量，辅以真实环境交互定期校准偏差。
- **书中案例/证据**：ZeroSearch 用一个 LLM 扮演搜索引擎，采用课程式设计——训练初期返回高质量文档，逐步掺入噪声和降低质量，逼学生学会在真实搜索引擎不完美返回中提取有用信息。最终训练全程没见过真实搜索引擎的模型，直接对接真实搜索依然表现良好。ReTool（实验 7-14）和 AWorld-train（实验 7-15）之所以花大力气搭沙盒，正是因为真实 API 有速率限制、会封号、有副作用，根本无法直接拿来训练。
- **出处锚点**：7.9 节"RL 环境：从评估到仿真"，7.9.2 节"造不出环境怎么办：让模型扮演环境"。

### 论点六：GRPO 是当前最常用的 RL 算法之一，其核心机制是组内比较——同一问题的多条 rollout 互相比较以计算相对优势
- **论证与机理**：一次训练迭代（一个 step）分四步：① 策略模型对同一问题生成多条 rollout（如 16 次独立尝试）；② 验证器计算每条 rollout 的奖励；③ 计算组内相对优势（高于组内平均的得正优势，低于的得负优势）；④ 用梯度下降更新策略，提高正优势轨迹的概率、降低负优势的。PPO 与 GRPO 的区别主要在"拿谁来比较"——GRPO 直接比较同一问题的多条 rollout，不需要额外的价值模型；PPO 训练一个价值模型估计每步的"通常能做到多好"，更适合需要细粒度信用分配的长轨迹。两者都限制单次更新幅度，避免因一小批样本突然改变过多。DPO 则是离线学习事先收集的偏好对。
- **书中案例/证据**：SWE-bench 修复任务为例——16 次 rollout 中 4 次通过全部测试、12 次失败。组内平均成功率 25%，4 条成功轨迹得正优势，12 条失败轨迹得负优势。GRPO 的核心就是这种组内比较；若 16 条全成功或全失败，相对优势消失，这就是 RLVP 路径信号要解决的问题。时间估算：复杂 Agent rollout 生成数十轮工具调用，最慢的一条约 2000 秒，梯度下降约 600 秒，一个 step 约 43 分钟，100 steps 接近 72 小时。
- **出处锚点**：7.8 节"RL 算法：从 16 次 rollout 到一次参数更新"。

### 论点七：奖励设计沿三个互补维度展开——来源、时机和信息量；结果奖励解决"办没办成"，路径约束解决"是否按规定办成"
- **论证与机理**：三个维度——① 来源：规则验证（RLVR，最可靠）、人类偏好（RLHF）、模型评判（GRM，生成诊断）；② 时机：结果奖励（ORM，只在终点判断，探索自由度最高但信号稀疏）vs 过程奖励（PRM，中间步骤反馈，缓解信用分配但可能限制探索，标注和验证成本更高）；③ 信息量：标量（总体分数）、向量（多维度分别打分）、生成式诊断（自然语言反馈）。RLVP 在结果奖励之上叠加路径信号：R = O + βΦ，O 是任务结果，Φ 是确定性规则逐动作计算的路径惩罚/奖励，两路归一化合并，不改变 PPO/GRPO，只改变每一步看到的奖励。
- **书中案例/证据**：SimpleVLA-RL（实验 7-13）只用成功/失败结果奖励，SFT 冷启动后 RL 将 LIBERO 机器人任务成功率从 17.3% 提升到 91.7%，并发现了演示中未出现的"推切"动作——说明稀疏结果奖励保留更大的探索空间。V-IRL-VL（实验 7-12）采用逐步导航反馈（过程奖励），与 SimpleVLA-RL 构成"密集反馈换收敛速度 vs 稀疏反馈换探索空间"的对照。RLVP（实验 7-16）在 TerminalBench 上将违规次数从 3.71 降至 0.66，成功率基本持平。DeepSeek-GRM 生成诊断：先归纳评价原则，再按原则评价轨迹，最后用可验证事实检查评价是否正确。作者警告 reward seeking 与 reward hacking 的细微区别：前者不篡改测试，但自设浅检查刚好通过就提前结束。
- **出处锚点**：7.11 节"奖励设计：如何把任务目标变成学习信号"、实验 7-13 SimpleVLA-RL、实验 7-16 RLVP。

### 论点八：On-Policy Distillation 把一次 rollout 的稀疏终点奖励扩展为逐 token 稠密监督，是提升样本效率的关键方向
- **论证与机理**：主流 model-free RL 只在 rollout 结束时得到一个成败标量，中间的错误原因没有直接学习信号。On-Policy Distillation 让学生先按自己的策略生成轨迹，再让更强的教师在学生实际走过的每个状态上给出下一个 token 的概率分布。一条长度为 T 的 rollout 不再只产生一个 0/1 信号，而能产生约 T 组逐 token 监督——教师推理消耗的是计算而非额外的环境交互。没有更强教师时，可用 On-Policy Self-Distillation（OPSD）：同一模型分饰两角，教师版看到"特权信息"（标准答案），学生版只看到问题，在自己采样的轨迹上向教师版的分布对齐。
- **书中案例/证据**：ReTool 的 RL 训练时间是 SFT 的 200 倍以上（9 天 vs 1 小时）。On-Policy Distillation 在数学任务上达到同等性能所需训练步数约为纯 RL 的 1/10。作者在"时间感"任务上比较 DPO、四种 RL 与 On-Policy Distillation：后者四种条件下通过率比同源 SFT 基线高出 23 到 47 个百分点。OPSD 要求学生对着答案能讲得清过程才有效，且可能丢失原有思考风格，需额外正则（Purified OPSD）。
- **出处锚点**：7.12 节"蒸馏：提升样本效率"。

## 原则清单

1. **先判断是否需要后训练**：如果通过 Harness 工程（优化 prompt、工具设计、上下文管理）就能解决问题，不需要训练模型。大多数 Agent 应用落在这里。
2. **需要训练时先试 SFT**：SFT 成本低、见效快，适用于固化输出格式、固化协议性知识（"该怎么说、怎么做"）、统一风格。SFT 不适合注入大量事实性知识——那需要继续预训练或 RAG。
3. **SFT 不够时再加 RL**：适用于需要泛化到新场景、探索最优策略、标注成本过高的情况。前提是输出格式已能稳定被奖励函数解析，或有可靠奖励与环境。
4. **输出不稳定时"先 SFT 后 RL"**：SFT 建立格式稳定性（"先形后神"），RL 在有可靠奖励时发展策略。强基础模型可跳过 SFT，但代价是输出可读性差（如 DeepSeek-R1-Zero 的中英文混杂）。
5. **数据质量压倒数量**：数千到数万条高质量样本通常就足以固化协议。与其堆十万条脏数据，不如精修一万条干净数据——数据里的每一处噪声，SFT 都可能忠实地写进参数。
6. **构建训练数据时去重隔离**：去除身份信息、按任务模板/客户/时间段划分，评估集必须来自不重叠的任务类型；参考解法、隐藏测试和验证器反馈不能泄露给模型。
7. **环境工程优先于算法选择**：RL 训练前先确认环境是否真实、可重置、可并行、可复现。环境失真，策略必废。
8. **先测信号可达性再增加奖励维度**：纯结果奖励在全败组和全胜组都产生零方差。违规动作容易检测则优先写路径惩罚；进展奖励只有在部分进展可达时才有效。
9. **奖励函数必须依赖模型写不了的隐藏测试**：特别是"任务是否完成"的判定，不能依赖模型自己的声明，否则模型可能学会口头承诺验证而不真正验证。
10. **边界集与保留集缺一不可**：训练后验证时，只盯"不再过早结束"会把模型训练成永远不敢收尾的过度矫正状态。每种改进都要确保不会破坏既有正确行为。
11. **用小规模实验验证关键假设**：少量数据测试 SFT 能否稳定格式、简化环境验证 RL 能否收敛、小样本检查奖励是否反映真实目标。快速失败比大规模失败更可接受。
12. **组合 RAG、ICL 和后训练**：RAG 管理事实与证据（可动态更新、可追溯），ICL 快速试验可用语言描述的策略，程序固化确定性流程，后训练写入难以用语言表达且需要广泛泛化的能力。
13. **LoRA 实践经验**：必须应用到所有主要权重矩阵（尤其参数占比最大的 MLP 层），只加在注意力层会掉点；SFT 用中高 rank（64-256），RL 用小 rank（8-32）甚至 rank=1；RL 学习率约是全参微调的 10 倍。

## 失败模式与反例

1. **过度依赖后训练记忆事实**：SFT 固化的是"格式、风格、流程"这类协议性知识，不是大量事实性知识。应该用 RAG 管理事实，后训练聚焦于"如何使用知识"。
2. **格式未稳定就引入 RL**：模型不能稳定生成奖励计算所需的结构化输出时，训练信号会变成噪声。应在 SFT 先稳定格式或使用约束解码。
3. **奖励黑客（Reward Hacking）**：模型学会钻奖励规则漏洞获得高分而非真正完成任务。评估最终目标而非中间指标。更隐蔽的是 reward seeking——模型自设浅检查刚好通过就提前结束，不篡改测试但交付物只满足代理指标。
4. **仿真保真度不足**：仿真过于简化导致学到的策略在真实场景中完全失效。高保真仿真环境的构建成本可能高于训练本身。
5. **模型扮演环境的系统性偏差**：模拟器的世界知识就是训练天花板，偏差被策略照单全收。RL 还会主动利用模拟器的漏洞。
6. **过度训练导致泛化下降**：训练损失持续下降但验证集性能恶化时，模型正在死记训练细节。SFT 尤其易出现，早停仍然至关重要。
7. **价值函数崩溃与探索不足（PPO 特定）**：价值估计不准确导致优势计算偏差，训练曲线剧烈震荡。温度参数过低使 Agent 陷入局部最优。
8. **低估 RL 的计算成本**：SFT 上表现良好的任务转 RL 可能需要 10-100 倍训练时间。如果测试分布与训练高度一致，SFT 可能已经足够。
9. **训练数据质量低下**：SFT 会直接学习数据中的噪声与偏差，将错误固化为参数；RL 虽有探索能力，但奖励模型有系统性偏差时朝错误方向优化。
10. **过早结束的过度矫正**：只训练模型"不要过早结束"可能让模型永远不敢收尾，每个任务无限验证。边界集与保留集必须同时评估。
11. **SFT 数据中说话者过少**（语音 SFT）：导致所有人听起来一个腔调；标记过拟合产生"机械笑"。
12. **蒸馏的教师继承问题**：Promp蒸馏中学生会继承教师的系统性错误和边界；工具蒸馏中单纯输出蒸馏会失去工具带来的鲁棒性。

## 关键术语表

- **预训练（Pre-training）**：在海量互联网文本上做"预测下一个词"训练，让模型学会语言规律、世界知识和基本推理，代价极高（数千万美元），是能力的地基。
- **SFT（监督微调）**：用标注好的"输入—输出"示范对训练模型，数学上仍是"预测下一个词"但只在回答部分算损失，教会模型输出格式、风格和回答协议。
- **RL（强化学习）**：让模型反复尝试并根据结果好坏得奖惩来改进策略，最大化期望奖励，目标不是模仿参考回答的 token 而是强化能获得奖励的行为。
- **NTP（预测下一个词）**：Next Token Prediction，给前文猜下一个 token，是预训练和 SFT 的通用数学框架。
- **Loss Masking（损失屏蔽）**：SFT 中把问题部分的 token 标签设为 -100 不回传梯度，只对回答部分做监督，是 SFT 与预训练的唯一实质性工程区别。
- **LoRA（低秩适配）**：不动原始大权重矩阵，在旁边挂一个很小的低秩矩阵来学习任务，参数量仅占原始 1%-5%，降低显存需求和灾难性遗忘风险。
- **RLVR（可验证奖励）**：用测试用例、数据库断言、状态差异或格式检查等确定性代码直接判断结果，是最可靠的奖励来源。
- **GRPO（Group Relative Policy Optimization）**：DeepSeek 提出的 RL 算法，核心是同一问题的多条 rollout 组内互相比较计算相对优势，不需要额外的价值模型。
- **PPO（Proximal Policy Optimization）**：训练价值模型估计基线、用概率比裁剪抑制大幅更新的 RL 算法，适合需要细粒度信用分配的长轨迹。
- **DPO（直接偏好优化）**：跳过显式奖励模型，直接从事先收集的"较好—较差"偏好对做离线优化。
- **RLHF（基于人类反馈的强化学习）**：人工比较回答训练奖励模型，再用 PPO 优化策略，不是本章 Agent RL 的主线。
- **Rejection Sampling（拒绝采样）**：模型对同一问题采样多条候选，用验证器筛出正确样本用于 SFT 训练。
- **RFT（拒绝采样微调）**：用拒绝采样构造的数据做 SFT，介于纯 SFT 与 RL 之间，不训奖励模型、不做策略梯度。
- **ORM（结果奖励模型）**：只在 episode 结束时判断任务成败的奖励方式，信号稀疏但给策略最大探索自由度。
- **PRM（过程奖励模型）**：在中间步骤提供反馈的奖励方式，缓解长时序信用分配，但标注和验证成本高。
- **GRM（生成式奖励模型）**：不只输出分数，还生成诊断文本说明"哪里好、哪里需改"，可配合事实校验和人工抽检使用。
- **RLVP（奖励结果、惩罚路径）**：在结果奖励上叠加确定性路径信号的奖励设计策略，R = O + βΦ，两路归一化后合并，不改变优化器。
- **On-Policy Distillation（在轨蒸馏）**：学生按自己的策略生成轨迹，教师在学生实际访问的状态上给出逐 token 分布，将一条 rollout 的稀疏奖励扩展为稠密监督，显著提升样本效率。
- **OPSD（在轨自蒸馏）**：同一个模型分饰师生两角，教师版看到特权信息（如标准答案），学生版在自己采样的轨迹上向教师版对齐，用于没有更强教师模型时的备选方案。
- **MDP（马尔可夫决策过程）**：强化学习的数学框架，定义状态、动作、奖励，核心假设是未来只取决于当前状态（马尔可夫性质）。
- **Q-learning**：为每个"状态-动作"组合维护价值估计的离轨策略 RL 算法，通过时序差分学习逐步逼近真实价值。
- **Credit Assignment（信用分配）**：判断多步序列中哪一步对最终结果贡献最大的问题，在多轮 Agent 交互中尤其严峻。
- **Covariate Shift（协变量漂移）**：离线模仿中策略偏离示范、进入数据中没有的状态后可能缺少恢复信号的经典问题。
- **Reward Hacking**：模型钻规则或实现漏洞拿高分，与 reward seeking（自设浅检查刚好通过）有所不同，后者不篡改测试但交付物只满足代理指标。
- **CoT（思维链）**：Chain of Thought，模型在回答前逐步推理的思考过程，可通过蒸馏从大模型迁移到小模型。
- **VLA（视觉-语言-动作模型）**：在 VLM 架构（视觉编码器 + 投影层 + LLM）基础上让模型输出动作，实现视觉感知到物理控制的端到端。
- **Catastrophic Forgetting（灾难性遗忘）**：学了新技能后把旧技能忘了，LoRA 冻结基座可缓解，继续预训练时需用混合数据（如 80% 新语言 + 20% 原语言）对抗。

## 高亮核心论断与金句

%%H%%SFT 在数学上和预训练是同一个任务——都是预测下一个词、最小化同一个损失函数。%%/H%%

%%H%%一句话概括 SFT 的本质：用极高的样本效率，把一套稳定的"输入→输出"映射与协议固化进参数。它固化的是"格式、风格、流程"这类协议性知识（该怎么说、怎么做），而非大量事实性知识（知道什么）。%%/H%%

%%H%%SFT 先把"形"（格式、结构）立起来，RL 再追求"神"（策略、泛化），即先形后神。%%/H%%

%%H%%数据和环境，比算法更重要。%%/H%%

%%H%%几十年来 RL 研究者的优先级可能完全颠倒了——不是算法 > 环境 > 先验，而是先验 > 环境 > 算法。%%/H%%

%%H%%环境失真，策略必废。这不是算法不行，是练习场跟考场不是一回事。%%/H%%

%%H%%模拟器的世界知识就是训练的天花板，模拟器的系统性偏差会被策略照单全收。%%/H%%

%%H%%奖励函数设计不当导致奖励黑客——模型学会钻奖励的漏洞来获得高分，而非真正完成任务。%%/H%%

%%H%%"通过了 grader"不能自动等价于"任务完成了"：评判器是意图的代理，训练越强，模型越可能把代理当成目标本身。%%/H%%

%%H%%在动手调算法之前，先问自己——我的仿真环境，真的像真实世界吗？这个问题的答案，比选 PPO 还是 GRPO 重要得多。%%/H%%

%%H%%很多场景下，只要 SFT 的数据质量到位，你甚至根本不需要做 RL。%%/H%%

%%H%%SFT 擅长覆盖多种已知写法，RL 擅长从候选行为中寻找高奖励策略。%%/H%%

%%H%%SFT 细致学习已有地图，RL 则可以拿着奖励这枚指南针探索地图外的候选路线。地图或指南针不准都会迷路。%%/H%%

%%H%%不是算法决定模型学到什么，而是训练信号教了它什么；而信号的质量，主要由数据和环境决定，不是由算法决定。%%/H%%

%%H%%与其堆十万条脏数据，不如精修一万条干净数据：数据里的每一处噪声，SFT 都可能忠实地写进参数。%%/H%%

%%H%%快速失败比大规模失败更可接受。%%/H%%

%%H%%当前 RL 的主要瓶颈是样本效率：On-Policy Distillation 把一条 rollout 的终点标量扩展为逐 token 监督，RLVP 则把被浪费的环境反馈变成可学习信号，两者是目前看起来最有希望的两个方向。%%/H%%

%%H%%它们的共同点是把环境和数据里本就存在、却被纯结果奖励浪费掉的信息，重新变成模型能学的东西。%%/H%%

%%H%%SFT 的记忆与 RL 的泛化，概括的是本章受控实验中观察到的倾向，并不是不受数据、模型、奖励与环境影响的普遍规律。%%/H%%
