## B. 规避方案（每条对应 A 项，落定为下次执行铁律）

1. **入账也必须前置，但方式不同（对应 A1）**：写入可前移到 run 前段，commit 不能（依赖写入完成）。正解 = **「下一轮的第一个动作 = 提交上一轮的全部遗留产出」**——把入账从本轮的尾部，搬到下一轮的头部。尾部永远会被截断，头部不会。
2. **dreaming timeout 300→600 + failureAlert(after:3, announce)（对应 A2，仅主 session/逸凡）**：一次动作同时消除「撞限截断」与「失败无人知」。合入下一次全量清单推送。
3. **可达性结论由引用者复测（对应 A3）**：任何跨主体流转的可达性/可用性结论，引用前本人复测一次；「某 agent 测过」不构成证据。
4. **knowledge-graph 索引随日推进（对应 A4）**：每次 dreaming 的固定动作里加一格「图谱索引是否覆盖到昨日」；月末最后一天做一次全月校核（今日为 9/30，即全月校验日）。
5. **入账清单机制（对应 A5）**：dreaming 收尾固定一格「未提交产出清单」，逐项列文件路径，交由下一轮的头部动作执行。
