## B. 规避方案

**B1 → 守卫AN：骨架必须排在任何读取之前。**
dreaming 落顺序固定为：① `date` ② MEMORY 当日区块 + dreaming 骨架双写 ③ 才读 SOUL / MEMORY / 当日 memory ④ 取证分析。判据明确到位：date 之后的第一条命令必须是写文件，不能是 read。26 秒能写完骨架（本轮实测骨架双写约 3 秒），26 秒读不完 context。

**B2 → 守卫AO：gateway 重启类失败必须当轮回填缺失日。**
每轮开场查上一轮 run 状态，error 含 `interrupted by gateway restart` 就先补写缺失日 MEMORY 区块（零交互声明 + 数据零变化结论 + seq 与耗时），再做当日复盘。今天已按此执行，10/16 区块即本轮回填产物。

**B3 单次失败必须可见：failureAlert after 3 → 1。**
这条 10/15 已提，今天第二次证据且代价是一整天。仍在主 session 手里（isolated cron session 无 update 权限），本轮不再重复推送，直接进 pending。

**B4 耗时类指标对 gateway 重启无预警力，别把它当通用健康度。**
守卫AK 的 80% 高危线只能预警「快撞上限」，本次失败 25,967ms 远低于 480,000ms 线，若只看该线会得出「一切正常」。健康度判定要看 `status` 与 `error` 字段，耗时只作辅助。

**B5 记忆链缺口是可检测的，不该靠人想起。**
判据：MEMORY 存在 `YYYY-MM-DD` 断日 或 `memory/dreaming-YYYY-MM-DD.md` 缺失，且当日 cron_run_logs 有记录 → 即为缺口。今天起用 cron_run_logs 反查，不靠印象。
