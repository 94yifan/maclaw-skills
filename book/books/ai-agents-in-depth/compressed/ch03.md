# 第3章 用户记忆和知识库

## 本章核心论题

处理 Agent 跨会话持久化记忆与知识，分两个尺度——单用户个性化记忆和全体用户共享知识库，共用向量检索、压缩等底层技术。主线：从单次会话扩展到跨会话知识体系——先建用户记忆，再深入 RAG，最后将知识库技术反转回用户记忆增强检索。

## 关键论点与框架

### 1. 用户记忆生命周期是"读取→提取→核验→更新"的闭环

Agent 回答前检索记忆注入上下文，对话后由后台 LLM 提取候选事实，经核验后追加或更新。提取需选择性、抽象化、结构化。

%%H%%提取器可以提出候选，但不能自行把未核验的字符串当成事实；更新策略还应记录来源、时间和冲突版本。%%/H%%

**出处**：3.1 节开头

### 2. 三层次评估框架：基础回忆→多会话检索→主动服务

L1 准确存储检索结构化信息（如会员号）。L2 跨对象跨时期检索相关信息并推理。L3 综合跨会话提供预见性帮助（如预订国际航班时关联护照信息预警过期）。每层 20 用例，LLM-as-a-judge 评分。

**出处**：3.1.1 节，实验 3-1

### 3. 轨迹（流水账） vs 用户长期记忆（档案）

轨迹是一次运行的完整历史，按时间顺序追加且不修改。用户长期记忆跨会话持久化，以键值对与用户 ID 绑定，会被反复改写、合并、淘汰。

%%H%%轨迹是单次会话的完整原始记录，按时间顺序追加且不修改；用户长期记忆则是跨会话提炼出的稳定信息，会被反复改写、合并、淘汰。前者是流水账，后者是档案。%%/H%%

**出处**：3.1.2 节

### 4. 四种存储格式构成记忆粒度渐近线，实践采用混合模式

- **Simple Notes**：最小不可再分事实，关联性丢失。
- **Enhanced Notes**：整段保存含上下文但冗余。
- **JSON Cards**：三层嵌套（类别→子类别→键值对），刚性结构丢失维度。
- **Advanced JSON Cards**：加入 backstory/person/relationship/时间戳。

%%H%%关键且少量的数据用 Advanced JSON Cards 以保证可检索性；大量且非关键的对话事实用 Simple Notes 以降低成本；多数生产系统采用混合模式——同一 Agent 内不同类信息走不同路径。%%/H%%

**出处**：3.1.3 节，实验 3-2

### 5. User as Code：将聚合、冲突发现和约束执行交给确定性函数

"预写日志+检查点"模式：事实追加到只增日志，周期性重建带类型状态。聚合统计、冲突发现（用药与过敏史交叉比对）、约束执行（护照有效期检查）全部由确定性函数完成。

%%H%%带类型的状态把原本需要 LLM"读一遍再心算"的操作交给确定性函数。%%/H%%

**出处**：3.1.4 节

### 6. 记忆设计存在三套正交分类体系：层次、格式、认知类型

长期记忆分情景记忆（具体事件）、语义记忆（抽象知识）、程序记忆（行为流程）。三体系可自由正交组合。

%%H%%三套体系是正交的维度——可以自由组合。选择哪种格式取决于工程需求（简单性 vs 表达力），选择存什么类型取决于业务场景（需要记住事实、事件还是流程）。%%/H%%

**出处**：3.1.5 节

### 7. Mem0 的 v2→v3 演进：写入时消歧→检索时推理

- **v2**：LLM 抽取→向量检索→在 ADD/UPDATE/DELETE/NOOP 中决策。风险：错误 UPDATE/DELETE 不可逆。
- **v3**：一次 LLM 抽取且只做 ADD，冲突事实并存；查询融合语义相似度+BM25+实体匹配+时间排序。LoCoMo 71.4→92.5（+21.1），LongMemEval 67.8→94.4（+26.6）。

%%H%%"住在北京"和稍后的"搬到上海"会作为带时间信息的两条事实并存。查询时融合多种检索信号和时间排序找出当前事实，既避免错误 UPDATE/DELETE 丢失历史，又减少 LLM 调用。%%/H%%

**出处**：3.1.6 节，Mem0 案例

### 8. Memobase：聚焦用户画像，缓冲批处理

用户记忆组织为用户画像（主题-子主题槽位）和事件记忆（时间线）。对话缓冲累积后统一触发记忆提取。

**出处**：3.1.6 节，Memobase 案例

### 9. 记忆压缩三层递进：重要性评分→聚类抽象→语义提炼

评分综合访问频率、时间衰减、情感强度、独特性。聚类将相似记忆分组生成摘要，原始细节存档。抽象从情景记忆中提取一般规律。冲突用版本化。

**出处**：3.1.7 节

### 10. 隐私脱敏应使用本地小模型

基于 Ollama 调用本地 Qwen3 0.6B 实现 PII 检测脱敏，识别身份证号、银行卡号等。JSON Schema 输出，召回率 95%+。

%%H%%选择本地部署而非云端 API 的原因很明确：日志本身可能包含敏感信息，发送到云端脱敏就违背了隐私保护初衷。%%/H%%

**出处**：3.1.8 节，实验 3-3

### 11. 混合检索流水线：稠密+稀疏互补，重排序升质

稠密检索捕捉语义相似性但漏精确关键词。稀疏检索（BM25）精确匹配但不懂同义词。

%%H%%没有哪种单一检索策略在所有场景下都可靠。把稠密、稀疏和重排序组合起来，才是构建生产级 RAG 系统的正确做法。%%/H%%

三阶段：①并行检索；②RRF 融合；③跨编码器深度交互。

**出处**：3.2.3-3.2.4 节，实验 3-5/3-6

### 12. RAPTOR 和 GraphRAG 解决"分块破坏内在结构"的问题

平铺入知识库存在两种缺陷：top-k 截断无法看全貌；跨文档聚合错位。RAPTOR：自底向上递归抽象构建知识树。GraphRAG：实体-关系三元组图谱，支持多跳推理但自然语言转三元组导致语义降级。

%%H%%实践中的推荐策略是分层互补：以完整自然语言保存核心信息（保留语义完整性），辅以结构化元数据进行索引和检索（兼顾查询效率）。%%/H%%

**出处**：3.3-3.3.1 节，实验 3-7

### 13. 文件系统范式（OpenViking）：三层按需加载+Markdown

虚拟文件系统，写入自动提炼为 L0（约 100 tokens 摘要）、L1（约 2000 tokens 核心）、L2（全文按需加载）。

%%H%%"摘要常驻、按需取全文"的思路与第二章 Skills 渐进式披露如出一辙——都是先让 Agent 只看到轻量元信息，确有需要时再逐层拉取完整内容，把 Token 花在刀刃上。%%/H%%

选 Markdown：用户可编辑、Git 版本控制。文件间须建立链接索引。

**出处**：3.3.2 节

### 14. 知识更新：增量 PR 流水线+双 Agent 审核

Proposer Agent 在工作分支提交最小完整 diff；Reviewer Agent 独立审核；迭代至收敛或达预算后转人工。

%%H%%Proposer 和 Reviewer 都必须是 Agent，而不是两次固定的 LLM API 调用。%%/H%%

定期整理：①去重去旧合并；②回原始数据核查旧摘要是否遗漏或将推测当事实；③冲突解决——追溯源头，证据不足保留冲突。

%%H%%两个 Agent 应优先使用能力相近、但来自不同家族的模型。异源互审能增加独立性，但不能替代原始证据：Reviewer 应主要核对证据和 diff，而不是沿着 Proposer 的结论再讲一遍。%%/H%%

三层分离：原始证据层（只增不改）→知识层（可修订）→服务层（可重建索引）。

**出处**：3.3.3.1-3.3.3.2 节

### 15. 智能体化 RAG：Agent 主导的动态迭代探索

传统 RAG 是单次检索→注入→生成的被动管道。智能体化 RAG 将检索封装为工具，ReAct 循环：自主决定查询词→检索→评估是否充分→不足则提炼更精确查询再搜。

%%H%%智能体化 RAG 将搜索和思考通过 Agent 的自主决策有机融合，能在海量非结构化知识中自主探索，通过多轮迭代逼近答案。%%/H%%

司法实验：简单问题非智能体化更快；复杂问题智能体化 RAG 通过分解→并行检索→评估缺口→精确二次检索显著高出。

**出处**：3.3.4 节，实验 3-8

### 16. 上下文感知检索：索引期 LLM 生成前缀"锚定"语义环境

索引阶段为每个文本块生成核心上下文前缀，解决分块后"该公司 Q2 收入增长 3%"丢失指代和背景。

%%H%%这里要和第二章的"上下文感知压缩"划清界限：本节的上下文感知检索发生在索引期，做的是"补前缀、加背景"以提升可检索性；第二章的上下文感知压缩发生在运行期，做的是"按当前任务裁剪、丢弃无关内容"以节省窗口。一个在做加法（补上下文），一个在做减法（去冗余）。%%/H%%

结合 BM25 降低失败率 49%，加重排序器降 67%。

**出处**：3.3.5 节，实验 3-10

### 17. 双层记忆架构：用户记忆与 RAG 的交汇，主动服务的实现路径

将 Advanced JSON Cards（结构化核心事实常驻）与上下文感知检索（按需取回原始细节）结合。旅行场景：发现机票与护照过期日接近→检索确认→给出"护照即将过期，建议加急续签"。

%%H%%主动服务之所以最难，正是因为它要求系统同时握有"全局概览"和"精确细节"两种视角——只靠常驻上下文会因容量受限而丢失细节，只靠检索又会因缺乏全局视野而发现不了跨会话的隐藏关联。%%/H%%

**出处**：3.3.5 节，实验 3-11

### 18. 从"信息检索"到"知识发现"的范式飞跃

司法判例分析（CAIL2018 数据集）：第一阶段 LLM 分析样本自由列出关键因素构建数据模式；第二阶段 one-hot 编码，聚类发现"案件原型"构建"因子重要性层次模型"。

%%H%%Agent 不一定要把知识库当成一个只能检索的静态仓库——它可以先把数据"读懂"，提炼出结构化的决策逻辑，再基于这个逻辑来回答问题。%%/H%%

该模型成为对话式信息收集核心驱动力——按重要性补全判决因素，基于最相似案件原型提供判例支持。

**出处**：3.3.6 节，实验 3-12

## 原则清单

1. **记忆生命周期必须闭环**：检索→回答→后台提取→核验→更新。
2. **分层存储策略**：关键少量 Advanced JSON Cards，大量非关键 Simple Notes。
3. **写入前查重**：新记忆入库前必须先检索已有相关记忆。
4. **日志先行、检查点后行**：原始事实先追加只增日志，审查通过后再结构化。
5. **压缩不等于丢弃**：低于阈值的记忆标记可压缩，原始细节存档二级存储。
6. **冲突不强制收敛**：矛盾信息追溯各自信息源，证据不足保留待确认。
7. **隐私脱敏不上云**：含敏感信息的日志本地脱敏。
8. **检索质量四步验收**：recall@k 验证命中，MRR 验证排序，nDCG 验证整体。
9. **文本块必须带上下文前缀**：分块索引前附加来源背景。
10. **知识写入必须走审核**：Proposer 提 PR，Reviewer 不同家族模型独立审核。
11. **原文保留优先**：完整自然语言保存核心信息，结构化元数据仅用于索引检索。
12. **分层加载 Token**：先加载摘要判断相关性，确有需要再逐层加载。
13. **文件间必须建立链接**：每条知识写入时链接到相关条目，更新索引页。
14. **权限过滤下推到检索层**：敏感内容在检索阶段即过滤。
15. **失效内容标注而非删除**：分块附加版本号、生效/失效时间，检索过滤已失效。

## 失败模式与反例

1. **Simple Notes 信息割裂**：工作信息分解为三个独立事实，丢失内在联系。
2. **JSON Cards 多维性丢失**："周末用 Python 开发个人项目"强制归入单类别。
3. **写入时消歧不可逆风险**：Mem0 v2 错误 UPDATE/DELETE 不可逆丢失历史。
4. **孤立案例片面推理**：Xfinity 规则只召回医生案例，错误推断护士也可享受。
5. **黑猫白猫 top-k 陷阱**：100 案例 90 黑 10 白，top-k 只能看到部分样本。
6. **知识图谱语义降级**：条件判断和时间依赖分解为三元组后全部丢失。
7. **上下文丢失导致检索失效**：分块后"该公司 Q2 收入增长 3%"丢失指代背景。
8. **传统分块的用户记忆失败**：多次修改电汇指令的对话块孤立缺乏上下文。
9. **增量更新全局累积问题**：长期运行后新旧说法并存、摘要偏离原始证据。
10. **过时知识污染检索**：被取代的旧政策与新版一起召回，给出矛盾答案。

## 关键术语表

- **轨迹（Trajectory）**：单次运行中按时间顺序追加且不修改的完整事件序列。
- **用户长期记忆**：跨会话持久化存储，以键值对与用户 ID 绑定，会被反复改写合并。
- **三层次评估框架**：基础回忆（L1）→多会话检索（L2）→主动服务（L3）。
- **Advanced JSON Cards**：加入 backstory/person/relationship/时间戳的记忆格式。
- **User as Code**：用户状态表示为带类型可执行对象，聚合和冲突发现交给确定性函数。
- **情景记忆**：关于具体事件和经历的记忆，记录时间、对象和细节。
- **语义记忆**：从事件中抽象出的一般性知识或稳定特征。
- **程序记忆**：关于行为模式和流程的记忆。
- **RAG**：检索器找相关片段，生成器基于片段产生答案。
- **分块（Chunking）**：将长文档切成适合独立检索的片段。
- **稠密嵌入**：深度学习将文本映射到连续向量空间，语义相近向量距离近。
- **稀疏嵌入**：文本表示为极高维度向量，多数为零，基于精确关键词匹配。
- **BM25**：对 TF-IDF 的修正，引入词频饱和和文档长度归一化。
- **倒排索引**：从词到文档的反向映射表。
- **RRF（倒数排名融合）**：抛开原始得分只看排名的融合方法，得分=Σ1/(k+rank)。
- **跨编码器（Cross-Encoder）**：查询和候选拼接后逐词比对，精度远高于双编码器。
- **RAPTOR**：自底向上递归抽象构建树状层次索引。
- **GraphRAG**：将文档建模为实体-关系三元组图谱，支持多跳推理。
- **上下文感知检索**：索引前用 LLM 为文本块生成核心上下文前缀以恢复语义锚定。
- **智能体化 RAG**：将检索封装为 Agent 工具，通过 ReAct 循环实现动态迭代探索。
- **Proposer-Reviewer 机制**：双 Agent 审核——Proposer 提 PR，Reviewer 不同家族模型独立审核。
- **文件系统范式**：将上下文映射为虚拟文件系统，L0/L1/L2 三层按需加载。
