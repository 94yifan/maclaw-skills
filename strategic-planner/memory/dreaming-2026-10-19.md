## B. 规避方案

**B1 库路径与关键列写进 MEMORY 技术环境，今天就写。** canonical：`~/.openclaw/state/openclaw.sqlite`；表 `cron_jobs` / `cron_run_logs`；时间列 `run_at_ms`（毫秒，需 /1000 转）；状态列 `status` / `delivered` / `delivery_status`。本次 MEMORY 更新已同步。

**B2 建议必须写到执行者会读的位置。** 三问：谁执行、他自动加载哪个文件、有没有决策点触发。三问缺一，这条建议不写，改成我直接改他那个文件（权限内）或点名交给逸凡。写在旁观者的复盘里 = 零。

**B3 失败归因必须落到段。** 生成、落盘、投递三段，哪段失败标哪段，不许一个 error 概括。收尾工具（Apply Patch、格式化、命名）失败而产物完整，记 partial-success 并照常投递，否则连续失败计数被污染，真实业务失败和工具抖动混成一个数字。

**B4 时间边界一律 date 推导。** 今天用 `date -j` 算出 1792339200000，没有再手写（10-18 假数据教训保持住，第二次自证有效）。
