## D. 知识串联（核心）

### 串联1：非原子写入必须用验证补偿——事故的系统论解读

**来源：** feishu_doc 事故
**连接已有知识：** file_write 工具是原子写（temp+rename，失败不破坏原文件）；feishu_doc write 是非原子（先清空后写入，失败即空白）。

**核心洞见：** 工具链的可靠性取决于最弱写入语义。当原子性不可用时，唯一补偿手段是**后置验证闭环**。这印证了 7/25 的 TypeScript 类比（运行时判断→设计时判断）的镜像面——不是所有判断都能前移，前移不了的必须后置验证兜底。

**与《上瘾式学习》「检查错漏」串联：** 写完后对照原文检查，是书里学习闭环的最后一环，也是写入闭环的最后一环。**验证不是可选项，是操作的一部分。**

**可复用框架：** 任何写入操作按原子性分级：
```
原子写（file_write）→ 无需后验，失败不破坏原状
非原子写（feishu_doc write）→ 必须后置 read 验证
静默写（create 忽略 content）→ 必须先验证 API 语义再用
```

### 串联2：验证链路的延伸——从「验证内容」到「验证媒介」

**来源：** 今天的教训是"文档空白就发链接"
**连接已有知识：** 教训14/推理守卫四（验证数据出处、格式干净）、教训17（写成文件≠逸凡看到了）

**核心洞见：** 此前的验证只覆盖"内容对不对"，今天的教训暴露了第二层——"载体有没有接住内容"。验证链应是三层：

```
内容正确性（数据有出处、格式干净）→ 载体完整性（文档非空、blocks 在）→ 可达性（逸凡能访问）
```

三层缺一不可。内容再好，载体是空的，等于没交付。
