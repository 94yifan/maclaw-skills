## B. 本周学到的关键洞察

### 1. 事件触发 vs 复盘待办：规则固化的两种效率模式

8/14 失败上报规则当天落地（有具体失败事件触发，逸凡当场给规则，立即写入）；而 SOUL 协议条款在复盘里躺了两周（纯复盘待办，没有事件绑定，每次复盘只复述「未落实」）。

**规律**：复盘待办如果不绑定具体执行时间点或触发事件，会被无限顺延——复述「未落实」本身成了替代执行的动作（这正是 5 月教训里「识别≠修复」的同类模式）。**改进**：复盘产出的待办必须带「何时执行」字段，能当场执行的不留到下次。

### 2. Skill 双轨生效机制：proposal pending + live ready

gateway 不可用时 workshop proposal 的 apply 被跳过，但文件已直接放进 live skill 目录生效。好处是流程不阻塞（逸凡已授权本地应用）；风险是记录状态与实际脱节——workshop 审计会看到 pending 状态的已生效 skill。需要在 gateway 恢复后补 apply，保持记录一致性。

### 3. Skill 沉淀闭环已验证：实战 → 固化 → 反哺

蓝氏专项跑通运营协作流程 → 固化为 xhs-task-reminder → 下一步反哺蓝氏（流程切到 Skill 规范跑）。「从实战中提炼可复用流程」的路线验证可行，GLM 写码 + 自测 + 逸凡授权 + 本地生效的流水线完整跑通一次。待观察：蓝氏切换后 skill 是否真的降低协作成本。
