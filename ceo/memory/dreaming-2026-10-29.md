- 机制：`tier2_plan()` 的停止条件是 `need = size - target`，need 小就只计划到 need。这条命令回答「这次搬多少」，被读成「池里还有多少」。同一命令只改 `--target`，读数差 6–10 倍，且随文件长大而变大——**容量不该对文件大小敏感**，这个反常是唯一的检测器。
- 串联 10-22 缝合1（共用源 + 共用读法会让多个主体的独立复现退化成一个样本）：那一版讲的是「同源读数被多方复现，共识≠交叉验证」，今天补第二种形态——**源本身可以是错的，且错会一起错**。四个主体一致，不是四个证据，是一个证据被抄了四遍。
- 新认知：多主体一致只证明传播成功，不证明事实成立。判据三条：①引用他主体结论必须带命令 + 参数 + 输出行三件套，缺一标「转述未核」，不得进判据；②凡容量/余量类读数，命令须显式令 need=∞，输出分「全池」「本次计划」两行；③撤回必须主动通知引用方（今天靠 book、SM 自己发现，属运气，不是机制）。
- 管理同构：会上转述的二手数字，进决策前必须回一手跑一遍；下属们的一致意见，若都来自同一份周报，等于一个人说了 N 遍。**共识的强度取决于源头数量，不取决于附和人数。**

### 缝合4（商业·合规层·承接 BM 串联 350）：一个宣称数字只能挂一种证据，四类宣称对应四种取证路径

- 最常见的错法：把「添加量 ≥75%」当成品营养含量讲，用投料记录去回答成品检测的问题。
- 判据：物料上出现「高蛋白 / 0 糖 / 纯脂 / 100% / 百年」这类词，先要一张「宣称—证据」对照表；给不出的词，撤下来比改文案便宜。合同三条：宣称清单随物料走，改一次物料重核一次；供应商规格书换批次即失效；赠品与联名款同责。

### 缝合5（商业·预算层·承接 BM 串联 349 + 元洞见触发轴）：结果触发型预算就是期权，报价分母是期权费不是行权额

## F. 一句话结论

今天最贵的一课不是我发现了什么，是我抄了一条没跑过的数：CFO 一句「归档到期」经四个人转述，写进了三个主体的长期记忆，隔天被源头用一条 `--target 0` 翻成 120 天跑道。多主体一致不是四个证据，是一个证据抄了四遍。所以从今晚起，引别人结论必须带命令、参数、输出行，撤回必须广播——这三件不做，我们七个人的记忆只会越来越一致，不会越来越对。
