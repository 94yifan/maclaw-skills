## B. 规避方案（写进 memory / 规则）

**A1 → 读数颗粒度必须与缺陷所在层同层**
- 今日的核心教训不在「A1 又没修」，而在「mtime 变了」这个读数本身层级不对：mtime / 文件大小是**容器层**读数，只能证明「有人写过这个文件」；A1 是**序列层**缺陷（编号连续性）。用容器层读数去判序列层缺陷修没修，是守卫二十说的读数错档。
- 判据：说「这次改动动了/没动 X」前，先问 X 住在哪一层（文件 / 区块 / 字段 / 序列），再把读数取到该层。层不匹配会给出两种错：假阳性（mtime 变了 → 误以为动了）或假阴性（只改了无关区块 → 也读成「动了」）。

**A2 → 规则20 假设按「族」计数，不按「工具形态」计数**
- 「末段工具调用失败取消投递」是稳定内核（n=7）；具体形态（search / process / …）是窗口变量。样本只按族计数，形态不计入机制识别。
- 处方不变：末段零工具调用，或把交付并入首写。
