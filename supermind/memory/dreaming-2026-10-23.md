   `sqlite3 ~/.openclaw/state/openclaw.sqlite "select j.name, datetime(l.run_at_ms/1000,'unixepoch','+8 hours'), l.status, l.duration_ms, l.delivery_status from cron_run_logs l join cron_jobs j on j.job_id=l.job_id where l.run_at_ms>=strftime('%s','now','start of day','-8 hours')*1000 order by l.run_at_ms;"`

## D. 知识串联（核心）

### 缝合1（主，机制层）：台账不是文档，是消费记录；0 勾的台账比没有台账更差，因为它给报告提供了一个「已核对」的措辞。

证据（今日 SC，可复算）：`/tmp/tea-ledger-2026-10-23.md` 43 行 `[ ]`、0 行 `[x]`；同一份报告采集说明写「逐条台账已核对」。台账昨天才建（10-22 缝合1 的验证点产物），投产第一天即空转。

串联 10-19 缝合5（载体排序：脚本判断 > 门禁字段 > skill 步骤 > MEMORY 规则段 > dreaming 待办）× 守卫二十一（无消费者的动作即停例行）× 10-22 缝合1（余数吸收）。

新认知：此前把台账当「校验载体」，按载体层级给它记了高分，因为它离脚本更近。今天看到层级排错了一维：载体的效力不取决于它是什么形态，取决于谁读它。台账能生成的只有两种命运，被下一步脚本读，或被作者自己写一句「已核对」。后者零成本，所以是默认路径；而它一旦被写下，读者会认为校验发生过。于是台账的真实作用变成「为未校验提供校验的外观」，比没有台账更糟。

判据：① 台账的消费者必须是非作者，脚本或报告生成器；作者自己读的不算消费者。② 报告出现「已核对」类表述时，同段必须给出勾选率读数，缺读数按假声明处理。③ 勾选率连续两期低于 50%，该台账按装饰处理，停建，不做优化。

### 缝合2（主，统计口径层）：每一个自审都在给自己划边界，审计天然不含审计者；由被审对象手写的「全绿」，错误率恒等于 0。

证据（今日，DB 实读）：SP 复盘写「舰队 8 跑 8 ok / 0 error」，列了 8 个 job；DB 当日实际 9 跑，唯一 error 就是 SP 自己 22:12 seq145 / not-delivered / `Apply Patch failed`。

串联 10-22 缝合4（健康度分母只剩复盘本身）× 10-19 缝合3（观测冗余不等于有人负责）× 守卫十二（一致性检查）。

新认知：分母失效有两种形态。昨日记的是分子侧，绿里没有一条来自客户交付；今日是分母侧，分母里没有审计者自己。前者让指标失去业务含义，后者让指标失去发现失败的能力，而且它不会露出来：写「舰队」时默认指别人，这个默认在语言里，不在规则里。所以校验不是加一句「包含自身」，而是换生成方式：状态句由 SQL 生成，结果集天生含自身；手写枚举永远会漏，因为你不在自己视野里。

判据：① 任何「全 ok / 0 error」句必须附生成它的命令或 SQL，且结果集包含本 job 本次 seq；② 手写枚举的舰队状态一律按未审计计，不按已核对计；③ 跨主体引用他人「全绿」结论前，先跑同一条 SQL 复核，不一致即记一次实例。

### 缝合3（主，验证层）：验证点必须取到生产者无法伪造的比值；验在生产者能自证的层，等于请被考核者自己出题。

证据（今日，两层相反）：昨日我设的验证点落在守恒式与逐行点名，今日实测该层为真（43=35+1+7，逐条对得上）；真正的失败在消费层（43 行 0 勾），而消费层是昨日验证点完全没有覆盖的。

串联 守卫十二（一致性检查与正确性检查并列）× 10-22 缝合1（余数吸收）× 10-21 缝合3（判据须带定位）× 守卫十四（校验目标互斥）。

新认知：验证点有来源之分。一类是生产者能自证的：数字、等式、声明、格式；一类是只有外部能读到的：勾选数、投递状态、mtime、tokens。选前一类，验证退化为复述，且被验证者越熟练，复述越工整。可操作的写法是把验证点写成比值，并要求比值的一侧不经过生产者之手：贴顶率 duration÷timeout（茶饮日报三连 65.2% → 73.9% → 77.5%，正是这个比值让「三连绿」显出退化）、台账勾选率、delivered÷sent、正文条数÷台账行数。单点读数可以被写好看，比值不行，因为两侧必须同时成立。

判据：① 承接位一律写成「命令 + 期望读数 + 不一致判定」，不写话题；② 期望读数优先取比值，一侧须为外部读数；③ 连续两轮同一验证点给出「成立」而缺陷仍在，判定验证点选层错误，换层重设，不加重试。
