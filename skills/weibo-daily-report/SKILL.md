# 微博每日监测日报生成 Skill

## 适用范围
每天爬取23个茶饮品牌微博数据后，生成结构化日报。调用此 skill 前确保原始数据已采集完成。

## 数据过滤铁律（2026-08-22 新增）
- **日报只写24小时窗口内（抓取时刻往前推24h）发布的内容**，超窗内容一律不写
- 过滤逻辑必须在抓取脚本内完成：解析每条微博 created_at 为时间戳（Date.parse），与 Date.now()-24*3600*1000 比较，只保留窗口内条目
- 不靠事后人工判断"这条算不算今天的"，抓取时就直接过滤
- 每个品牌同时返回 latest（最新一条微博发布时间），无动态品牌标注"今日无动态（最新微博日期）"，不写"本周无动态"等模糊表述

## 口径与自检铁律（2026-10-19 新增，对应 10-18/10-19 连续两日缺陷）

1. **抓取只用 canonical 脚本** `tea-daily-crawl.mjs`（workspace 根目录，自动按运行日命名输出 /tmp/tea-raw-<日期>.json）。不要复制 `tea-daily-crawl-MMDD.mjs` 旧脚本，旧版会继承已修掉的缺陷。脚本内 WINDOW_END 在开抓前冻结一次，所有品牌同一时间点过滤；输出含 windowStart / windowEnd / crawlTime 与每品牌 ok / total / fetched / error / items.id。
2. **header 逐字引用 raw**：数据窗口写 raw 的 windowStart – windowEnd，抓取时刻写 raw 的 crawlTime，不按发稿时刻或印象反推。
3. **采集说明只写 raw 能读到的字段**：raw 没有 `ok` 字段就不许写"接口 ok=1"；写"23 品牌全部请求成功"必须同时给出错误数。`total=0 且 fetched=0` 的品牌写"接口无返回·待核实"，不写"无动态"。
4. **守恒式必须逐条交代，不是凑数**（2026-10-22 强化）：`窗口内条数 = 正文 bullet 数 + 剔除数（抽奖公示等）+ 合并数（多条合成一条 bullet）`。三个数写进 header 或采集说明，合并项不得静默吞掉。
   - **强制动作**：写报告前先读 `/tmp/tea-ledger-<日期>.md`（canonical 脚本自动生成，逐条列出 id/时间/前 60 字），每一条都要落到「某条 bullet 的素材」「合并到某条 bullet」「剔除＋原因」三者之一，逐行打勾。禁止用总数相减倒推出「合并 10 条」这种数字。
   - **反例（10-22）**：报告写 `38 = 23 正文 + 5 剔除 + 10 合并`，算术完全成立，实际合并只有 8 条，差额 2 条（爷爷不泡茶 10-21 18:01 小狗拯救世界、10-21 14:30 周三茶香 300 元奶茶卡）被静默吞掉——数字是按总数补出来的，不是数出来的。同日库迪 1 条帖被拆成 2 条 bullet（拆分 −1）刚好把窟窿填平，等式反而更「漂亮」。
   - 判据：等式成立不代表无漏报，只有台账每一行都能指到具体 bullet 才算闭合。
5. **23 品牌状态全列**：正文出现、无动态行、接口无返回三条路径必须覆盖全部 23 个品牌，不允许整体缺席。
6. **跨天去重（只比对昨日报告，不读昨日 raw）**：写报告前与 `memory/weibo_daily_<昨天>.md` 比对 id / 正文，重复帖标"昨日已报"或不计入，禁止无标注重复。**禁止为去重去读 /tmp 下昨日 raw**——10-20 报错即由此触发（一步无关读取失败把整轮 run 判 error，群交付被吞）。
7. **品牌内顺序固定**：新品上市 → IP联名/艺人宣发 → 营销活动，不得倒序。
8. **计数口径统一**：header 的"有动态"只统计有实质动作的品牌；仅有抽奖公示的品牌不列入"有动态"，在无动态行注明"仅1条抽奖公示"；窗口内有帖但全部被判"昨日已报"的品牌（如 10-20 霸王茶姬）也归入无动态行，注明"1条昨日已报"。**header 第 3 行写"共 K 条（实质 X，抽奖公示 Y）"**（2026-10-22 补，连续 3 天提过）：K 是窗口内原始条数，X = K − 抽奖公示数，不许只写 K 让读者误以为都是实质动态。
9. **窗口右端不容差**：抓取脚本 `age >= 0`，抓取开始后发布的帖子不进本窗口（会自然落入次日窗口，不丢）。header 声称的 windowEnd 与正文最晚时间必须一致。
10. **接口无返回不得连续挂"待核实"**：某品牌 `total=0 且 fetched=0` 连续达 3 天，必须在 dreaming 做一次 profile 页人工核验（粉丝数/最新帖可见性），给出"停更/限流/需登录"结论并写进日报采集说明，不得无限期沿用"待核实"。
11. **windowEnd 用秒级原值**（2026-10-22 新增）：raw 的 `windowStart` / `windowEnd` 已带秒（如 `2026-10-22 11:00:12`），header 必须原样引用，不许截到分钟、不许套模板里的写死时刻。原因：窗口冻结在秒级，header 只写分钟时，11:00:07 发的帖看起来就是「窗口外混入」，属自造争议。抓取时刻仍用 `crawlTime`（HH:MM）。
12. **专名不得删**（2026-10-22 新增）：帖文里出现的合作方、联名对象、艺人、产地、产品专名，必须原样写进报告；合作性质无法从单帖确认时写「与 XXX 联动（合作性质待核实）」，不许抹名换泛称。抹名等于把一次可追踪的联名机会变成一句没有信息的「系列发布」。
13. **周边归类统一**（2026-10-22 新增）：杯具、盲盒、贴纸、卡片、毛绒、服饰等非饮非食物件一律进【IP联名/艺人宣发】或【营销活动】；【新品上市】只放可饮可食产品。同一物件不许今天算新品、明天算联名。

## 产出标准

### 格式结构（固定三段式，不可改）

**精确Markdown格式要求：**

- 品牌名用 `**品牌名**`（粗体，不是Markdown ## 标题，不用标题层级）
- 分类标签用 `### **【新品上市】**`（H3标题+粗体，不带外层星号/井号包裹）
- 内容一律用 `- ` 列表项，不用段落或编号
- 每条结尾写"对品牌而言，……"做品牌价值判断

**【IP联名/艺人宣发】**
- 写清联名IP/艺人名称、联动形式（主题店/周边/短片等）、合作深度
- 每条结尾加品牌价值判断

**【营销活动】**
- 写清活动内容、时间范围、玩法机制
- **必须有对营销效果的判断分析**——为什么这么做、对品牌有什么用、能否形成差异化

**无动态的品牌**直接写"今日无动态"，保持占位

**品牌间空一行**

### 内容写作原则

1. **新品要详细完善** — 产品卖点、技术工艺、食材溯源都写清楚，不让读者去猜"这产品到底好在哪"
2. **营销活动要有效果分析** — 不只写做了什么，要判断这个动作对品牌有什么用。例如"618预售是上半年大促节点的大流量抢夺""高考送贺卡是低成本的线下门店引流"
3. **品牌价值判断要精准** — 对品牌自身的价值，不发散到行业层面。"对品牌而言，这是XXX"一句说透
4. **不确定的信息不写** — 如上新时间未明确，不编造标注
5. **不发散行业意义** — 行业层面的洞察全部放到末尾的"行业层面信号"部分，不在单个品牌内容里展开
6. **去掉概览汇总表** — 直接进入品牌内容，不在开头或结尾放概览表
7. **去掉微博互动抽奖** — 聚焦品牌营销动作本身，转发抽奖/微博平台互动类内容不再写入

### 行业洞察（3条左右）

所有品牌内容结束后，附：

**行业层面信号（3条左右）**
- 每条一个核心判断，摆数据/事实支撑
- 可以跨品牌对比、找规律、预判趋势
- **关键结论加粗**
