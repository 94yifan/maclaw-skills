**关联历史：** 09-17 缝合1（系统债投递三要件：触发点 × 通道独立性 × 通道闭合形态）+ 09-18 缝合2（返程通道 = 权限配置问题，不是设计或意愿问题）+ book 今日串联3（合法不作为区）+ 守卫十八。

**整合新认知：** 修复不闭环有两层根因——第一层是**「修复方不可达」**（权限 / 通道），第二层更隐蔽是**「修复归属隐式」**（规则只说「不许做」，不说「归谁修、在哪个决策点修」；双方都合规，缺陷悬置）。
修复归属须**三分类并显式写出**：
- **自控型**：改自己的脚本 / SOP（BM 收尾纪律；CFO audit.py）→ 发现即可做，绑发现会话。
- **payload 型**：须主 session 改 cron payload（SC/CEO/CFO/SP/BM 的 timeout、工具容忍、failureAlert）→ 绑主 session + 周期合计推送。
- **授权型**：改 prompt / 政策（SOUL 守卫、配置保护路径）→ 须逸凡明确授权。

**判据：** 写任何「只检测 / 只报告 / 不擅动」的边界时，立刻补一句归属条款（归谁修、什么时点修、走哪类通道）；答不出即该边界是一条合法不作为通道。

**管理同构：** 组织里「质检部只提问题不整改」若没写谁整改，问题永久悬置；把「发现问题 → 归属谁 → 什么时点修 → 走哪条通道」写进流程，缺最后一段的流程等于体检报告。**BD 应用：** 客户交付流程里的「发现方 / 归属方 / 时点」三段必须在 SOP 里闭合，否则每次客户提的问题都会在甲乙双方之间悬空。
