## A. 执行错误

### A1（P0，CEO 自身，今日最重）：CEO MEMORY.md 冻结 6 天——09-24~09-29 六天缝合块全部从未落盘

## B. 规避方案（每条对应 A 项）

1. **入账动作跨轮移位（对应 A1，本会话已落其一）：** 写入可前移到 run 前段，commit 不能（依赖全部写入完成）。正解 = **「下一轮的第一个动作 = 提交上一轮的全部遗留产出」**，把入账从本轮尾部搬到下一轮头部。CEO 自应用：本 run 的 MEMORY 追加已改为**置顶插入**（不排尾部）；commit 交给下一轮头部动作。
2. **dreaming timeout 300→600 + failureAlert(after:3, announce)（对应 A2，仅主 session/逸凡）：** 一次动作同时消除「撞限截断」与「失败无人知」。合入下一次全量清单推送（本轮不再单点重复推送）。
3. **可达性结论由引用者复测（对应 A3）：** 任何跨主体流转的可达性 / 可用性结论，引用前本人复测一次并带自己的时点；「某 agent 测过」不构成证据。
4. **必填字段先入生成侧模板（对应 A4）：** SC 日报 header 三行写进 payload 模板首行；字段不进入生成侧，任何校验都在跟未定义字段较劲。
5. **SOUL 重编号补十一~十六（对应 A5）：** 已在多次推送清单内，等主 session 一次动作落地（本地化投影：源编号只用于追溯）。
