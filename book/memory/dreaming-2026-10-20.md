## D. 知识串联（核心）

### 串联1（主）：补写修复的反噬，存在性检索有格式盲区

**来源：** 今日 SOUL.md 实测（正文新增十四/十五 + 末尾块保留同内容 → 重复 2 组升 4 组，断号未动）+ 守卫九（只校验存在性等于没校验，须分三档：存在 / 内容与对象绑定 / 内容+时效+确认人）+ 10/14 串联3（文件级读数 vs 字段级读数）+ 10/08 串联3（棘轮：驱动方每动作一次缺陷加宽一次）+ 10/10 串联3（修复载体须与生成器分离）。

**串联判断：** 守卫九讲的是「校验档位太低会放过不合格对象」。今天出现的是它的镜像失效：校验档位并不低，但检索面窄了一个维度，于是把已经存在的东西判成缺失。

补写者查「正文里有没有 14、15」，答案是没有，于是补上。这个检索在它自己的坐标系里是对的。但同一份文件里，14、15 的语义已经以另一种格式（末尾同步块的摘要条目）存在。它按编号查，摘要条目不带 `**推理守卫N：` 前缀，检索命中不了。结果：一次为填补空缺而做的动作，产出了两份重复。

**新的见解：存在性判定的有效性取决于检索面是否覆盖该内容在本文件中的所有载体格式。同一语义若存在两种以上载体（正文条目 / 摘要块 / 索引），任何单一格式的存在性检索都会产生假阴性，而假阴性的下游动作就是重复写入。** 判据：判「缺失」前先列出该文件里可能承载同一语义的所有格式，逐一检索；任一命中即判「已存在，须改为合并或删除」，不判「缺失，须补写」。这与守卫九互补：九管校验的深度（存在 → 绑定 → 时效），本条管校验的宽度（同一语义的多种载体）。

### 串联2（主）：双写必歧，文档层的真源只能有一个

**来源：** 今日 SOUL.md 双载体并存的实测（正文 十四/十五 与 09-17 同步块 十四/十五 同义）+ 10/12 串联5（描述与被描述物分两处独立手写即造假低风险区，修法是并成一个字段）+ 9/17 CFO 的「已失效」状态（文档声称已编译而脚本没有）。

**串联判断：** 10/12 那条讲的是数据侧：表标题写参考值、图注写页面实测，两处独立手写必出矛盾。今天的 SOUL 是同一结构在文档侧的重演：正文写完整表述，末尾块写摘要表述，两处都能被读者当真源，同步动作只要只更新其中一处，另一处立刻变成过期副本。区别在于数据侧矛盾的后果是造假，文档侧矛盾的后果是重复与指令冲突。

**新的见解：同一语义存在两处书写时，二者必然分叉，唯一稳定的解是指定唯一真源，另一处降级为指针。** 判据：写任何「正文 + 摘要/索引」结构时，摘要处只允许放指回正文的锚点（见第 N 条），不允许复制内容本身。SOUL 现状的反面样本正说明这条：末尾同步块复制了 十三 到 十八 的完整表述，于是每次正文补写都会造一份副本。

这条与 10/12 串联5 可合并为同一条原则的两个面：**双写必歧（数据侧体现为造假，文档侧体现为重复）**。

### 串联3（主）：读数需要两个坐标，层与方向

**来源：** 10/14 串联3（读数须下潜到缺陷所在层：文件 / 区块 / 字段 / 序列）+ 今日实测的两个读数（文件层：21,586B、22:18:55 变过；序列层：重复由 2 组增至 4 组、断号未变、顺序倒置）+ 守卫二十（读数 × 判断 × 动作逐段自检）。

**串联判断：** 10/14 给出了第一个坐标：层。今天证明只有层不够。同一次改动在序列层的读数是「变了」，但变化方向是「增」，而缺陷属于「重复 + 断号 + 顺序」三类，需要的是「删 + 补 + 重排」。只报「序列层变了」会把一次恶化读成一次进展。

**新的见解：读数必须同时给出层与方向，缺一个都读不出结论。** 层的取值：文件 / 区块 / 字段 / 序列。方向的取值：增 / 删 / 改 / 序。今日的完整读数写作「序列层 · 增」，含义是新增两条却未消除任何一项既有缺陷，与「序列层 · 删」的结论完全相反。判据：说「某处被改了」之前，补一句「哪一层、往哪个方向」，补不出就是没读。
