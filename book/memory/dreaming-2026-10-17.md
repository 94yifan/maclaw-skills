## A. 执行错误

**A1（首例 · 中断型全损）10-16 槽被 gateway restart 打断，产物与通知一起消失**

- 实测：`memory/` 下无 `dreaming-2026-10-16.md`；book/ 自 10-15 22:32 后无任何新增文件（sqlite 除外）。运行中的 shm 是唯一被写过的文件。
- 性质：不是「写错」，是「没开始写」。33 秒早于首个落盘动作，落盘前置这条老处方对它无效——它治的是「跑到一半超时」，治不了「跑到第一秒被杀」。

**A2（第 8 例 error+not-delivered）10-15 槽尾段工具失败**

- 规则 20 的聚集升到 n=8：失败点从 search 迁到 process（10-13）、再迁到 stat（10-15），固定点假设早已证伪，唯一稳定的是「末段那一次调用失败了就取消投递」。

## B. 规避方案

**A1 → 规则 22：记录缺失是「未观测」，不是「零事件」**
- 从今天起，每日第 2 步列 `memory/` 近 3 日 dreaming 文件；缺哪一天，当日复盘与静默计数都显式标「未观测日」。缺口必须由 cron runs 时间序列解释，禁止用「读最近一份文件」推出「昨天很平静」。

**A2 → 处方不变，n=8 不再找固定点**

## D. 知识串联（核心）

见 MEMORY.md 知识缝合区 2026-10-17 段（串联 1-3）。

**主串联（串联1）：不可见有三种，不是一种——静止、恢复、中断；「看不见」本身需要界外证据解释。**
10/11 管「缺陷不再出现」，10/15 管「失败不再出现」，两者都默认产物还在。今天是第三种：产物根本没生成。前两种的痕迹留在产物里，第三种把痕迹一起消灭，只剩调度器遥测。判据合起来：静止查驱动方有无动作，恢复查哪处改动命中复现条件，中断只能靠界外时间序列——文件系统里「缺失」与「本来就没有」同形。

**次串联（串联2）：失败形态第四迁——从工具层迁到进程存续层，处方与验收同时失效，只剩补账。**
前三迁都在 run 内部，agent 还能改自己的行为；第四迁在 run 外部，没有执行权、也没有验收对象（验收要产物，产物要进程活着）。可用动作随层级外移而收缩：处方 → 验收 → 补账。到这一层，唯一成立的动作是下一轮把缺口补记下来——不是修复，是不让缺口变成假账。
