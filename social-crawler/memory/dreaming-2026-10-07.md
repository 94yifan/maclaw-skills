## B. 规避方案（落定为下次执行铁律）

### B1（针对 A1，最高优先·新增）

- **报告增加「实质帖全覆盖」双向对账**：写报告前，逐品牌比对 `raw 实质帖数` 与 `报告 bullet 数`；差值必须能用**合并**解释（如幸运咖 3 条并为 2 条 bullet），解释不了的即为漏报，必须补写。守恒式从"总量守恒"升级为"逐品牌守恒"。
- **skill 铁律 7 补边界定义**：`纯开奖公示（"恭喜@…抽奖平台公示"）剔除 / 含品牌内容 + 抽奖机制的营销帖保留`，并各给 1 个正反例，消除模型自由裁量。

### B2（针对 A4）

- payload 模板首部补 **header 必填三行**：`# 茶饮品牌微博日报 <TODAY>` + `数据窗口：<起> 11:00 – <止> 11:00（抓取时刻 11:00）` + `覆盖：23 品牌 | 有动态 N | 无动态 M`，字段化，禁靠发挥。

### B3（针对 A3）

- payload 加「运行内工具禁令」：运行期禁止 ls/引用未确认路径、禁止自我修改 cron/payload；**收尾校验默认不跑**。
- 加**交付兜底**：写文件成功后立即 `message` 发群，不依赖 announce 自动转发（针对已复现 11 次的「文件完整 + run error + 交付跳过」同一 bug）。

### B4（针对 A2/A3 拆分）

- timeout 300→600（救超时样本）与 isolated 会话 `sqlite3`/`git` 工具可用性排查（救工具失败样本）**分开治**，不要合并成一项。

### B5（针对 A5）

- window 一步到位：`t0` 单点（全品牌共用同一时间窗）、header 引用同一 t0、落 `last-window.json`、脚本头日期动态化、边界帖标注实际时刻。

### B6（针对 A6）

- 跨天 campaign 去重**写进 payload/skill 硬步骤**（不写 dreaming）：同名 campaign 再次出现时标 `(M/D 已报，本日 M/D 帖)` 或只写增量；行业信号层同样去重。

### B7（针对 A7）
