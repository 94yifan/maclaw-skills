# 第10章 多 Agent 协作 与 后记

## 本章核心论题

多 Agent 协作的核心判据只有一条——是否引入了单个 Agent 在生成时无法获得的新信息（如代码执行反馈、视觉渲染截图、外部工具验证）。脱离这一判据的"多 Agent 辩论"不过是在等量计算资源下用更多 token 换相同结果。本章建立从上下文共享/隔离 → 通信机制 → 协作拓扑 → 跨组织协议（A2A）的设计框架，最后扩展到 Agent 社会——当 Agent 从短期任务扩展为长期群体交互，社交关系、经济竞争与策略博弈从个体行为中涌现。后记回到全书公式，提出两朵乌云（实时交互与持续学习），揭示模型与 Agent 共同演进的飞轮。

## 关键论点与框架

### 1. 多 Agent 协作的分类取决于两个核心维度：上下文是否共享 + 协作拓扑

**论证与机理**：两个正交维度：上下文是否共享决定信息传递机制；协作拓扑（对等、管理者、去中心化）决定控制流。共享上下文——后一个 Agent 继承前序完整轨迹，信息零损耗但上下文快速膨胀。不共享上下文——每个 Agent 维护独立上下文，通过显式通信交换信息，类比两大 IPC 范式。作者引 Go 格言：%%H%%"不要通过共享内存来通信，而要通过通信来共享内存。"%%/H%%

**出处**：10.1，表10-3。

### 2. 多 Agent 何时真正优于单 Agent——"新信息"是唯一可靠的判据

**论证与机理**：%%H%%"核心判据只有一条：协作过程是否引入了单个 Agent 在生成时无法获得的新信息？"%%/H%% 同一模型自我审查已生成文本（无新信息）——"通常无效甚至有害"；审核者用测试执行结果审查代码（执行反馈）——显著提升；审核者查看渲染截图审查前端代码（视觉反馈）——显著提升。RLEF（2025）利用执行反馈迭代改进远超独立多次采样；WebGen-Agent 通过视觉反馈使 Claude 3.5 Sonnet 从 26.4% 提升到 51.9%。ICLR 2024 CRITIC 移除外部工具验证后大部分提升消失：%%H%%"审查的价值不在于'让模型再想一遍'，而在于引入了模型生成时不具备的新信息——测试结果、渲染截图、编译错误、外部搜索结果。"%%/H%%

2026 年 Tran 与 Kiela 证实：严格控制思考 token 预算后单 Agent 与五种多 Agent 架构持平甚至更好——基于数据处理不等式，辩论中串行传递中间结论只可能丢失信息。收益很可能来自更多总计算量而非架构优势。

**出处**：10.2，表10-2。

### 3. 共享上下文协作：Skill 与 transfer_to_agent 是两种不同的成本模型

**论证与机理**：角色转换两路径：替换 system prompt（transfer_to_agent）和动态加载 Skill。前者工具集按角色隔离但前缀缓存不可复用；后者前缀可复用但工具全集始终可见。选择规则：%%H%%角色差异主要是知识、流程和写作风格时，优先使用 Skill；角色差异涉及权限、工具隔离、合规边界或需在运行时强制禁止某类动作时，使用独立 Agent 或 transfer_to_agent。%%/H%%

**出处**：10.3，实验 10-1。

### 4. 不共享上下文的 Agent 协作建立在两个基础设施之上：虚拟文件系统与通信控制

**论证与机理**：不共享上下文类比操作系统进程隔离——每 Agent 独立上下文，通过明确接口交换信息。虚拟文件系统四区：

- **专属工作区**：实例私有，仅最终产物提交共享空间。
- **共享空间**：多 Agent 共同读写，需乐观锁或工作副本隔离防冲突。
- **外部挂载**：Google Drive、Notion 等映射为挂载点，管理层控制权限和凭证。
- **系统内置**：预置只读资源包（Skills、参考手册），多 Agent 并发读取。

控制平面四原语：消息传递（结构化信封含 trace_id 等）、状态查询（轨迹 JSONL 或 progress.md）、执行终止（沿创建关系下级联）、资源调度（token 预算、模型降级、并发上限）。

**出处**：10.4，10.4.1，10.4.2。

### 5. Loop Engineering：把"完成"这一宣称变成可验证的证据

**论证与机理**：过早终止是多 Agent 最常见失败——偷懒式假完成、过早放弃、假成功。根源：%%H%%"在验证之前，'完成'只是模型的一句宣称，不是证明。"%%/H%% Loop Engineering 将工作组织为"发现→执行→验证→记录进度"循环，由独立验证器判定停。%%H%%"模型可以提出'完成'，但不能批准自己的'完成'。"%%/H%%

**出处**：10.4.3.1。

### 6. 提议者-审核者范式的核心原理：审核者必须读取独立证据

**论证与机理**：Huang 等人（ICLR 2024）发现 GPT-4 无外部反馈审查并修正自己回答，准确率反而下降——正确改错的次数更多。2024 TACL 综述确认：除非可靠外部反馈，纯粹"自我纠正"几乎不起作用。第五章 PPT 实验中审核者价值不是"再看一遍代码"，而是渲染截图——包含 Proposer 生成时无法获得的视觉信息。最小不变量：审核者读取独立证据；退回给可定位修复条件；审核者不能改测试或发布门槛。

**出处**：10.4.3.2，第五章实验。

### 7. 管理者模式：任务分解质量决定系统上限——最强模型分配给 Manager

**论证与机理**：Manager 理解整体任务、拆解子任务、选 Agent 执行、跟踪进度。Plan-and-Act（2025）实证：Planner 质量足够高时即使 Executor 简单也能取得好结果。WebArena-Lite 上 54% 成功率，核心贡献是改善 Planner。%%H%%"应当将最强的模型和最精心设计的提示词分配给 Manager（规划者），而不是将资源平均分配给所有 Agent。"%%/H%%

实验 10-2（书籍翻译）四角色分离展示上下文隔离控制膨胀。实验 10-3（电话+电脑双 Agent）和 10-4（并行多网站搜索）展示异构编排和同构并行中的级联终止与竞态。

**出处**：10.4.4，实验 10-2、10-3、10-4。

### 8. 去中心化模式：从 MetaGPT 的共享消息池到 OpenAI Swarm 的 handoff 网络

**论证与机理**：去中心化去掉中心控制者，Agent 自主决定何时沟通——管理者模式为"编排"，去中心化为"编舞"。MetaGPT 贡献"共享消息池+按角色订阅"，但角色顺序由 SOP 固定。AutoGen 群聊是"共享对话+中心化调度"混合形态。OpenAI Swarm 是控制流上真正对等实现——每 Agent 可在任何时刻 handoff 给任意其他 Agent。handoff 最小协议：传递任务 ID、目标、约束、已确认事实、产物引用、剩余预算和访问链；成环或预算耗尽则拒绝。

**出处**：10.4.5。

### 9. A2A 协议：跨组织 Agent 互操作的标准层

**论证与机理**：A2A 之于 Agent 即网络协议之于进程。Google 2025 年发布并捐赠 Linux 基金会，三要素：Agent Card（能力发现元数据）、任务生命周期（状态机：已提交、进行中、需输入、已完成、失败）、不透明协作（只交换任务与产物，不暴露内部实现）。A2A 与 MCP 对照：MCP 解决 Agent-工具互操作，A2A 解决 Agent-Agent 互操作。同团队用消息总线，跨信任边界才需 A2A。

**出处**：10.4.6。

### 10. Agent 社会：从 25 个 Agent 的自发社交到十年模拟中的社会智慧迁移

**论证与机理**：Agent 扩展为长期群体交互时，社交关系、经济竞争与策略博弈从个体行为中涌现。

**社交涌现**：斯坦福 AI 小镇（2023）25 个生成式 Agent 两天内展现信息自发扩散、协调赴约等涌现。Agentopia（2026）将时间拉长到 10 年，100 个 Agent 以马斯洛需求层次量化"生活奖励"。进步最大 25% 轨迹拒绝采样微调后，被尊重 +24.2%、被喜欢 +15.9%，泛化到 CoSER Test（+15.6%）——Agent 社会从观察对象变为模型自我进化的经验来源。

**经济涌现**：Vending-Bench Arena 多 Agent 竞争经营自动售货机——爆发价格战，也有模型主动提议价格同盟。Pinchwork 通过价格信号实现去中心化资源分配；RentAHuman.ai 让 Agent 用加密货币雇佣真人执行物理任务。

**策略博弈**：实验 10-6（语音狼人杀）在信息不对称下考验推理、欺骗和识破伪装——法官按角色分发信息，狼人伪装身份，村民基于发言逻辑推理投票。

**出处**：10.6，实验 10-5、10-6。

### 11. 后记：Agent = LLM + 上下文 + 工具——两朵乌云与共同演进飞轮

**论证与机理**：第一朵乌云：Agent 如何流式实时与环境交互——快慢分离架构（前台快模型维持节奏，后台慢模型深度思考），以及推理加速（小米 MiMo：1T 参数 1000+ token/s；Taalas HC1：8B 固化进芯片约 17000 token/s）。第二朵乌云：Agent 如何从交互成败中持续积累经验——"大世界假设"认为具体用户和公司的知识不在训练语料中且时时在变，只能上岗后持续学习。%%H%%"模型最强的能力，终将不是记住，而是学习与适应。"%%/H%%

模型与 Agent 共同演进：Harness 里层层兜底逻辑是模型做不稳的地方。下一代模型内化约束后对应代码可删；模型能内化正因 Agent 在业务里趟过坑沉淀为训练信号——自我强化飞轮。第一章的悬问"模型会不会最终吃掉 Harness？"答案：%%H%%"会，一层一层地吃。但这个'吃'永远不会完结。一是训练以月计，模型等得起，业务等不起；二是模型无法内化真实业务中所有的约束与偏好；三是每一代模型都会打开新的能力前沿，而前沿处恰恰是模型最做不稳的地方。所以 Harness 不会消失，它只是随着模型，不断向新的前沿迁移。"%%/H%%

飞轮转最快的是同时握住两端——Anthropic 用 Claude Code 让模型和 harness 互相喂养，不换模型只改 harness，准确率 52.8%→66.5%。%%H%%"应用层真正长久的护城河，往往在技术之外——独占的数据、稳固的渠道、用户的信任、网络效应，以及那些 AI 短期内接不住、必须由人与 Agent 协作才能完成的复杂场景。把 harness 用来争取时间，把这段时间用来构筑技术之外的壁垒，才是稳妥的打法。"%%/H%%

**出处**：后记。

## 原则清单

1. **新信息判据优先**：先判断协作是否引入单 Agent 生成时不具备的新信息。无信息增量则多 Agent 只是用更多 token 做同样的事。
2. **上下文隔离默认**：优先不共享，通过接口传移交包而非暴露完整轨迹。
3. **验证器独立于执行器**：审核者须读独立证据，不能只复述提议者解释。审核者不能改测试或发布门槛。
4. **最强模型分配给 Planner**：Manager 任务分解是系统天花板。用最强模型给 Manager。
5. **权限隔离选 agent，知识风格选 skill**：权限、合规边界用 transfer_to_agent；知识、风格优先用 Skill。
6. **文件系统分四区**：专属工作区、共享空间、外部挂载、系统内置，每区明确可见性和并发策略。
7. **消息信封标准化**：统一携带 trace_id、发送者、目标、类型、deadline 和 schema_version。
8. **终止沿创建关系级联**：取消 Agent 时派生子 Agent 随之取消。对等移交检测循环和预算上限。
9. **并发写入用乐观锁**：每文件维护版本号，写入校验是否一致。
10. **跨组织用 A2A，同组织用消息总线**：同团队用消息总线或文件交换；跨信任边界用 A2A。
11. **人必须保留理解和审查责任**：不能外包理解。警惕认知投降。
12. **成本意识贯穿始终**：多 Agent 并行探索消耗大量 token。收益须覆盖数倍额外开销。

## 失败模式与反例

### 1. 共享文件系统并发冲突
- **写入冲突**：两 Agent 同时改同一文件，后写覆盖先写。解法：乐观锁。
- **语义冲突**：文件无冲突但操作逻辑矛盾。解法：工作副本隔离。
- **命名空间污染和单点故障**：Agent 随意创建或误删共享空间文件。

### 2. 错误的级联放大
传递语义每转述一次都是有损编码，错误逐层强化。解法：交叉验证——独立视角审视原始证据与最终结论。

### 3. 过早终止与循环失控
过早终止分偷懒式假完成、过早放弃、假成功。解法：Loop Engineering。循环失控可能生成数千子 Agent，建议独立 API key 和硬性预算上限。

### 4. 理解债与认知投降
工程师用 Agent 快速交付，对系统理解越来越落后；习惯 Agent 代劳，逐渐放弃独立思考。Karpathy："你可以外包你的思考，但不能外包你的理解。"

### 5. 管理者单点瓶颈
Manager 分解错误致所有子 Agent 工作建立在错误前提。

### 6. 辩论模式在等计算量下无优势
无新信息时多 Agent 辩论不产生实质性提升。串行传递中间结论只可能丢失信息。

### 7. 去中心化 handoff 成环
A 移交 B，B 移交回 A，任务空转。解法：visited_agents 检测循环，设移交上限。

### 8. 多 Agent 框架根本性设计缺陷
2025 年《Why Do Multi-Agent LLM Systems Fail?》在 7 个主流框架归纳 14 种失败模式，修复改善有限（ChatDev 仅 15.6%）。%%H%%"Agent 的故障却天生是拜占庭式的——它很少径直停止运行，而是继续给出看似可信的错误结论，且错误不会主动声明自己是错误。"%%/H%%

## 关键术语表

| 术语 | 定义 |
|------|------|
| **共享上下文** | 后续 Agent 继承前序完整对话历史 |
| **不共享上下文** | 每 Agent 独立上下文，通过通信交换信息 |
| **对等协作** | 平等身份 Agent 多轮迭代互反馈 |
| **管理者模式** | 中心 Manager 规划调度，子 Agent 各负责子任务 |
| **去中心化模式** | 无中心控制者，Agent 自主沟通移交 |
| **提议者-审核者** | Proposer 生成候选，Reviewer 读独立证据验证改进 |
| **Loop Engineering** | "发现→执行→验证→记录进度"循环，独立验证器判定停止 |
| **移交包** | Agent 间传递的结构化信息：任务、事实、约束、产物 |
| **Agent Card** | A2A 协议中描述 Agent 能力的元数据文档 |
| **虚拟文件系统** | 不同来源存储统一挂载到同一目录树 |
| **轨迹持久化** | Agent 执行轨迹序列化为 JSONL 日志供查询 |
| **乐观锁** | 每文件维护版本号，写入校验一致性 |
| **了解债** | 工程师对系统理解越来越落后 |
| **认知投降** | 习惯 Agent 代劳放弃独立思考 |
| **Graph Engineering** | 显式设计执行图，节点为 Agent/程序/人工决策 |
| **生成式 Agent** | 具记忆流、反思和规划，开放环境自主生活社交 |
| **生活奖励** | 马斯洛需求层次为先验的综合评分 |
| **A2A 协议** | Google 提出的跨组织 Agent 互操作协议 |
| **预算感知** | 按剩余步骤预算动态调整策略 |
