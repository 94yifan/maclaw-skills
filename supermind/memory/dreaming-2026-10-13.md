## A. 执行错误

**A1（P0，连续第 3 日）：本 job 交付链断裂（10-12 seq133 error/not-delivered）。**
- 事实：seq131（10-10）error/95,342ms、seq132（10-11）error/122,993ms、seq133（10-12）error/218,189ms，均 not-delivered、内容全在盘。error 文本分别为收尾工具链（seq131/132）与后台进程失败（seq133 `Process: plaid-rook failed`）。
- 定性：属守卫二十第三段「动作断」——复核能跑、判断能下，收尾那一步把交付吞掉。

**A2（P0，本日新增，最高价值）：同一批 payload 硬约束，三个 job 生效不一致——「payload 文本」不是有效载体。**
- 事实：10-12 16:09–16:10 同批给 8 dreaming job + tea-daily 加同一句「写完文件后禁工具」。10-13 首个生效日：tea-daily-delivered=1 无 error；SP 10-12 seq134 error/75,801ms/not-delivered、10-13 seq135 ok 但 delivery_status 空；本 job seq133 error/not-delivered、耗时 218s（远低于 600s 上限）。
- 定性：payload 里的禁令是同一模型读的文本，属同源生成器（10-10 缝合1 已圈定的无效层）。SC 生效因其 run 尾部天然「写完即止」，dreaming 类 run 尾部天然有复核冲动。

**A3（P1，第 32 天）：配置修复与失败形态错配——超时不是当前主因。**
- 事实：本 job seq133 218s、SP seq134 76s，均远低于 600s 却仍 error/not-delivered。SP 同日在自身复盘给出同结论（timeout 假设被证伪）。
- 定性：失败形态已从超时迁移到收尾工具调用；10-12 的调度/超时修复打的是旧靶。这是缺陷迁移在修复侧的镜像。

**A4（P1，已闭环）：`typeset.py::_parse_md_table` 以子类覆盖绕过源文件（守卫九欠账第 2 例）——本轮就地回源修复。**
- 修前（实测）：方法为 `@staticmethod`，内部用 `ReportTypesetter.__new__(ReportTypesetter)` 造假实例调 `_add_data_table`，而后者依赖 `self.cfg` → 含 md 表格的正文必崩。实测报错：`AttributeError: 'ReportTypesetter' object has no attribute 'cfg'`。
- 修法：去 staticmethod、加 `self`、改 `self._add_data_table(doc, dt)`。
- 修后验证（实测输出）：含表格 md 跑 `convert_str` → `DOCX 生成: True`、`表格数量: 1`、表头 `['品牌','营收','增速']`、数据行 `[['有友','11.82亿','+22.37%'],['劲仔','24.12亿','+16.79%']]` 逐字正确。
- 定性：这是守卫九欠账（黄天鹅 /tmp 绕过第 1 例、王小卤子类覆盖第 2 例）**首次真正回源**，且发生在发现的下一轮。

**A5（P2）：10-12 复盘自列的 5 项「明天做」今日 0 执行。**
