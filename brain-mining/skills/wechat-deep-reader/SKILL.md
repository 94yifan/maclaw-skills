# wechat-deep-reader — 微信公众号文章深度阅读

## 能力定位

一站式读完一篇微信公众号文章：**采集（文字+图片OCR）+ 分析 + 写报告 + 打标签入库 + 支持共创。**

## 前置条件

- Python venv: `/tmp/wechat_venv/bin/python3`
- GLM API Key: `~/.openclaw/config/glm.json`
- Playwright chromium: 已安装
- 脚本: `scripts/wechat_glm_reader.py`

## 完整工作流（6 个阶段）

### 阶段一：采集（调用工具脚本）

收到 mp.weixin.qq.com 链接后执行：

```bash
/tmp/wechat_venv/bin/python3 \
  /Users/yifansmacmini/.openclaw/workspace/brain-mining/scripts/wechat_glm_reader.py \
  "<文章URL>" \
  --model glm-4v \
  --max-images 0 \
  --output-dir /tmp/wechat_reader
```

输出 JSON 到 `/tmp/wechat_reader/<slug>/article.json`。

主要字段：
- `title` — 文章标题
- `article_source` — 公众号名称
- `publish_date` — 发布日期
- `text_content` — HTML 提取的文字
- `images[]` — 每张图，含 `url`, `local_path`, `ocr_text`, `width`, `height`

GLM 只做 OCR —— 把图片里的文字读出来变成文本，不做分析。

### 阶段二：信息提取与打标签

#### 提取信息

从脚本输出的 JSON（text_content + 所有 images[].ocr_text）中提取：

| 类型 | 提取什么 |
|------|---------|
| 核心数据 | 销售额、增速、ROI、CTR、转化率等量化指标 |
| 框架/模型 | 方法论、分析框架、策略模型 |
| 案例 | 品牌做了什么 → 结果 → 可复制点 |
| 工具 | CID、蒲公英、灵犀等具体产品/功能 |
| 趋势判断 | 行业变化方向、消费者行为变化 |

提取原则：只摘录原文信息，不做价值判断。

#### 打标签

| 维度 | 可选值 |
|------|--------|
| 行业 | 茶饮 / 宠物 / 食品饮料 / 数码家电 / 美妆 / 服饰 / 其他 |
| 品牌 | 文章涉及的具体品牌名 |
| 投放方式 | **种草**（=KFS）/ **内循环/闭环电商** / **小红星**（一级外域转化）/ **小红盟**（一级外域转化）/ **CID**（深度外域转化）/ 其他 |
| 内容类型 | 行业解决方案 / 案例复盘 / 趋势洞察 / 方法论 / 品牌动态 |

投放方式层级关系（理解用，打标选具体项）：
```
种草（=普通KFS）
生意：
  ├── 内循环（=闭环电商）
  ├── 小红星（一级外域转化）
  ├── 小红盟（一级外域转化）
  └── CID（深度外域转化）
```

打标原则：
- 没有明确涉及的不硬打
- 多品牌/多行业打最核心的
- 投放方式基于实际内容判断

### 阶段三：写报告

#### 标题分类体系

报告必须按以下标题类别组织：
- **【关键数据】** — 所有量化指标和数据
- **【核心洞察】** — 文章的核心发现和判断
- **【核心框架】** — 方法论、模型、策略框架
- **【打法拆解】** — 操作层面的步骤拆解
- **【案例】** — 品牌案例
- **【工具】** — CID、蒲公英、灵犀等具体产品/功能
- **【复用框架】** — 跨行业可复用的方法论
- **【曼拾切入】** — 曼拾可以直接卖什么方案

#### 重点信息高亮标记

在关键内容处加标记前缀：

📊 DATA — 核心数据
⭐ KEY INSIGHT — 最重要的结论性判断
💡 ACTIONABLE — 可以直接用的策略/建议
🎯 对曼拾 — 曼拾的生意切入点
✅ 适用于 — 什么场景能用
❌ 不适用于 — 什么场景不能用
⚠️ WATCH — 风险点/需要注意
👀 例子 — 辅助理解的案例场景

#### 案例写作规范（每 case 必须严格按照以下顺序）

目标是：**没读过原文的人，看完案例描述就能在脑子里还原出这个品牌长什么样、遇到了什么困境、为什么选这个策略。**

**第一步：产品画像（描述产品是什么、长什么样、在哪卖、什么价位）**
- 让读者看到产品画面感——不是只有品牌名
- 说明品类、价位段、渠道
- 这部分来自文章图片OCR的描述信息

**第二步：品牌处境（遇到了什么困境）**
- 新品牌还是成熟品牌
- 在品类中的位置
- 核心痛点是什么（没信任？没预算？没内容？没流量？）

**第三步：策略选择（为什么这么做）**
- 选择的策略是什么
- 为什么选这个策略而不是常规打法
- 最反直觉或最值得注意的决策点

**第四步：具体执行（做了什么，Step by Step）**
- 每个步骤做了什么动作
- 每步的细节值得注意的点

**第五步：结果（量化数据）**
- 具体数字
- 时间周期

**第六步：案例价值（为什么值得记住）**
  🎯 对曼拾意味着什么
  ✅ 核心可复制点（3条以内）
  ✅ 适合什么客户（具体客户画像）

⚠️ 写作原则：
- 案例不能只列品牌名和数据，必须描述产品画面
- 不能只有结论，必须有前提、有推导、有结果
- 报告正文中的核心关键词必须**加粗**高亮，方便快速定位（如品牌名、核心数据、SKU名称、平台术语等）

#### 报告总体模板

```
## 【关键数据】
（文章的核心数据和结论）

## 【核心洞察】
（核心发现和判断）

## 【核心框架】
（方法论、模型）

## 【案例】
（每个案例按规范写法）

## 【工具】
（营销工具链）

## 【复用框架】
抽象可平移的方法论，每框架写：适用行业 → 怎么做 → 判断标准

## 【曼拾切入】
可提炼的方案方向 + 适合客户 + 曼拾切入点

## 【BD反哺策略】
基于这篇文章的知识，BD负责人可以用什么策略去跟客户沟通、吸引客户签约。
按**不同阶段客户**分类写（每个策略含：适合什么阶段+核心话术+怎么跟客户说）
```

#### BD反哺策略写作规范

目标：BD负责人读完这个板块后，可以直接拿去跟客户聊。

按以下客户阶段分类：

| 客户阶段 | 特征 | 对应策略方向 |
|---------|------|------------|
| 新锐品牌 | 缺认知/缺内容/缺预算 | 帮他们找到差异化切入点，降低起步门槛 |
| 成长期品牌 | 有内容但打法乱/增长不稳定 | 帮他们校准策略，找到可放大的方向 |
| 成熟大品牌 | 有预算/有团队/需要突破 | 帮他们做情绪IP/品牌占位/规模化放大 |
| 内卷赛道品牌 | 老品类/同质化严重/增长乏力 | 帮他们找到新的情绪切口和叙事方式 |

每个策略必须包含：
1. **适合阶段**——这个策略对什么样的客户有效
2. **核心话术**——BD可以用一句话打动客户的话（概括该案例最有力的价值点）
3. **怎么跟客户说**——BD和客户具体沟通时的逻辑和话术
4. **对应曼拾能做什么**——这个策略下曼拾能提供什么服务

#### 写作约束

- 不编造数据
- 不堆原文，先说结论再展开
- 跨行业复用必须有逻辑推导路径
- 核心关键词**加粗**高亮（品牌名、核心数据、SKU名、平台术语等）

### 阶段四：飞书文档写入

每篇文章必须创建飞书文档，格式与知识文章一致。

1. 用 `feishu_doc(action="create", title="〔BM深度阅读〕文章标题")` 创建文档
2. 用 `feishu_doc(action="write", doc_token=token)` 写入目录和核心内容
3. 用 `feishu_doc(action="append", doc_token=token)` 追加详细拆解内容

文档结构同报告模板，注意：
- 每次写入必须使用**完整的 doc_token**（不能截断）
- 先 write 再 append，不要一次写过长内容
- 核心关键词加粗

### 阶段五：知识入库

写入 `knowledge/articles/YYYY-MM-DD_文章标题.md`

```markdown
---
title: ""
source: ""
date: ""
url: ""
行业: ""
投放方式:
  - ""
内容类型: ""
---

## 提取内容

（完整内容摘要）

## 共创笔记

（讨论后形成的判断和理解，待补充）

## 关键洞察

（可复用的行业认知）
```

**索引维护：**
- `knowledge/index/by-industry.md` — 新增文章时追加记录
- `knowledge/index/by-tag.md` — 新增文章时追加记录

### 阶段六：共创讨论

用户可能会提问、纠正、深挖。做到：
- 只回答文章已有的内容，不编造
- 用户纠正 → 立即更新已有文件
- 关联已有 knowledge/ 和 MEMORY.md 中的知识
- 遵循推理守卫：说"之前"必须先核查文件
