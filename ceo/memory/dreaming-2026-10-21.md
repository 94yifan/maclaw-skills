## D. 知识串联（核心）

### 缝合1（主·验证层·承接 SM 10-21 缝合1 + 10-18 缝合1 + 09-19 判据）：健康度的分母不是运行次数，是含判断的运行次数

SM 今天把绿拆成三源：真修复 / 路径侥幸 / 输入为空。这个拆分是对的，但停在了分类，没有给分母。今天的数据正好可以做除法：

- 12 跑、11 ok。若按运行数算，健康度 91.7%，是近期最好的一天。
- 逐条查来源：SC 的绿靠 `tea-daily-crawl-1021.mjs` 副本没抄丢（SC 自证：与 canonical 唯一差异是 CDP 端口）；SM、CFO、book、SP 的绿全部是零输入（SM 第 4 天零产出、CFO 第 2 天零交互、book 静默 D70、SP 第 34 日零任务）；CEO 本轮 ok 也是零输入；BM 的 error 是收尾工具层。
- **有效绿 = 有真实输入 × 存在可失败点 × 通过能指认改动。三项全过的，今天只有 tea-daily（而它的通过原因又被 SC 自己否掉）与蓝氏三个 job。**

→ **新认知：运行数不是健康度的分母，含判断的运行数才是。零输入的 run 只能证明调度器活着，不能证明系统健康；把它算进分母，等于用「今天没事可做」给自己发合格证。** 这与守卫十五同构（样本要过数量与时效双门槛），只是换到了系统层：绿要过「有输入」与「可失败」双门槛。

判据：写「今日 N 跑 N ok」必须同段给出有效绿数；有效绿 < 总量一半的日子，禁止在复盘里写「系统健康」，只能写「今日无异常输入」。

管理同构：一个季度没丢单，先问这季度有没有投标。没投标的零丢单，是零信息。

### 缝合2（主·治理层·本轮最重·承接 10-19 缝合3 + 10-20 缝合3）：同一个 error，在两种交付契约下后果相反

今天两个 error 同族、代价相反：

- **CFO seq144（10-20 22:06）**：status=error，error 文本 `🩹 Apply Patch failed`。但 CFO 逐条取证：补丁失败 4 秒后改 exec 写成功、closeout 跑完、commit f7de2d2 已是远端祖先、最后一条 assistant 消息 stopReason=stop。且它的 `delivery_mode=none`——本来就没有送达契约。**实际损失为零。**
- **BM 22:24**：status=error，error 文本 `🛠️ run sqlite3 → ... failed`，delivered=0，产物 20,585B 在盘。**实际损失＝一整份复盘没到逸凡手里。**

两轮的 status 字段长得一样，一行是虚警，一行是真断。CFO 今天立的守卫AX 用三读数（产物 / 收尾 / 运行）解决了「是不是真失败」，但没有回答「失败了损失什么」——因为损失不在运行里，在契约里。

→ **新认知：失败的代价由交付契约决定，不由状态码决定。判一次失败的代价要三问：① 有没有下游读者 ② 契约是否含送达 ③ 产物是否可复用。三问全否 = 虚警，可归「已恢复」；任一为是 = 真断，必须补发并记账。** 这也解释了为什么同一个 failureAlert 阈值在八个 job 上表现完全不同：它们不是同一个东西。

落地：复盘里写 error 必须带 `delivery_mode` 与 `delivered` 两个字段；只看 status 的失败统计，会把虚警与真断算成一个数，然后按平均数设阈值——这正是 10-18 缝合2 里「该设 1 的设成 3」的成因。

### 缝合3（主·分发/引用层·承接 10-20 缝合1「编号是接口，语义是实体」）：引用是点对点的接口，定位是它的实体

SM 今天抓到一条我没想到的缺陷：SC 22:00 的复盘写「按 10-21 supermind 的判据，缺陷消失必须自证归因」。SM 22:18 才开跑，grep 自己 MEMORY 与 10-20 复盘，**没有这句判据，且该文件在 SC 引用时还不存在**。最接近的是 SM 10-18 / 10-19 的缝合，日期、主体、措辞三处同时漂移。

SM 的定性比我更狠，也更准：这不是编造，是「被正确引用的错误前提」，它比写错更危险，因为引用本身带着交叉验证的外观，对账抓不到。

→ 与 10-20 缝合1 是同一件事的两层：编号是**批量分发**时的接口（一份同步到七个分身，接口必须稳定）；引用是**点对点传播**时的接口（下游转述上游，接口是「谁在哪天说了什么」）。两层共用一个实体要求——可核定位。

→ **新认知：一个判据的传播半径由它的定位精度决定，不由它的正确性决定。正确但指不到位置的判据，每转述一次就漂移一次，且漂移后仍然读得通。** 判据：判据原句必须带出处（文件 + 区块 + 日期）；跨主体引用别人时写对方复盘编号（SC 10-21 A4），指不到位置的一律降级为「印象，待核」，不得用于支撑结论。

CEO 自应用：本区块所有「承接 10-XX 缝合 N」都已带日期与缝合号，缺的是文件级——10-17 及更早的缝合在 `MEMORY.md` 归档区或 `memory/archive/` 下，本轮起补文件名前缀。

### 缝合4（次·商业层·蓝氏实测·新）：执行卡点按动作可控性分层，催办只对可控动作有效

lanshi 今日原文（非推断）：10/15 周会批次 10 条，8 条推进（5 完成 / 3 进行中），**3 条未收口全部是资源投放类**——pro米修斯视频流放量、2.0 笔记全面提量拉大占比、幼猫猫粮加量抢第一。第 7 天按规则升级到逸凡。同一张表里按时完成的是：笔记消耗 200–300 时首轮 CTR/CPC 评估、口碑通放宽新笔记成本限制、搜索日汇报、手机前端刷词反馈——全部是内部可执行动作。

→ **新认知：执行卡点不在人，在动作类型。放量/提量/加量依赖平台竞价、预算规模与大盘竞争（外部裁决），催办只能让它每七天被提一次；内容产出、素材更换、成本放宽依赖内部排期（内部裁决），催办有效。把两类动作放进同一张跟踪表、用同一套催办话术，结果是前者永远显示「进行中」，后者正常推进，而表格看起来只是「有延期」。**

判据：周会跟踪表分两栏——可控动作看完成率（催办）；不可控动作看「资源决策是否落地」，必须写清谁批、批多少、哪天生效。任一未写即视为未决策，不进「进行中」。

曼拾用法：客户侧延期超 3 天且属放量类的，交付物应从执行催办转成资源决策文档（预算档位 / 竞价位 / 目标口径三选一），否则第 8 天、第 15 天都是同一句话。

### 缝合5（次·方法层·来自 book 规则24）：当日是区间不是时点

book 今天自曝了一个很细但会持续犯的错：它 22:30 起跑，「今日」实际截止于 22:30，而 CFO 22:07、SM 22:19 的写入落在截止前 11–23 分钟；若那两个事件晚 11 分钟，同一件事会被记到次日，而两份报告都自洽。

CEO 的窗口是全部 dreaming 里最宽的（22:36 起跑，晚于 22:00–22:30 六个 job），所以最不容易犯。但正因为最宽，容易犯另一种错：把「我读到的最新」当成「今日全部」。今天 tea 11:00 的 587s、蓝氏 19:10 的汇报都在我的窗口内，但 22:30 之后若有人写入，本轮读不到，而明天我引用时会说「昨日无变化」。

→ 判据：「今日无 X」这类断言必须同时写观测端与观测截止时刻。三轴齐（观测端 / 观测单位 / 观测截止时刻）才能说「今天发生了什么」，缺一条的结论不可复算。

## E. Reflection

- **Goal**：零交互日的复盘目标不是总结，是把今天唯一可得的跨主体读数榨干。达成——缝合1、2 是新的，缝合3、5 是把别人的判断推到自己能用的位置，缝合4 是今天唯一一条客户侧实证。

- **Main Mistake**：A3 的读数归属错一轮。数字是真的、归属是错的，这类错在对账时最容易被当成「差不多」放过。
- **Repeat Risk**：A1（读而不输出）与 A3（引用不核时间戳）都是老形态。前者第 2 天，后者与守卫二十同族第 N 次。
- **Principle Update**：健康度按「含判断的运行数」算；失败代价按「交付契约」算。
