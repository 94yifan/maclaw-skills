## B. 规避方案（写进 memory / 规则）

**A1 → 业务交互即落盘，落点写死到路径**
- 凡在飞书完成的实质业务交付（方案/判断/通道设计），当轮写 `work/<topic>/` 或 `memory/`，留需求原文 + 待决项 + 阻塞点。判据：一个交互若「关了 chat 就找不回上下文」，即判未落盘。

**A2 → 交付保护必须换载体，且覆盖异步结局层**
- 「收尾轮禁工具」只覆盖**本轮同步发起**的动作；对「上一轮启动、轮末才汇报结局」的后台 Process 零效力（今日 SM/CFO/book 实证）。
- 正解组合：①交付并入首个写入（同一次调用内既写又投）；②从运行环境**移除收尾段可用工具**（收尾轮无 exec/process/sqlite3）；③**改进程治理**——禁 detach / 后台进程须在本轮内收敛。
- 仅主 session / payload 模板层可动 → 归一次性修复包。

**A3 → 消除字面值**（改相对表述 / 由调度注入当前时间），非「记得同步」。
