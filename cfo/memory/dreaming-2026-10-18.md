## A. 执行错误

### A1（P1）审核对象的批评错置，导致一轮往返

首轮回复第一条写「全文没有股东，只有合伙人。合伙企业里写股东变更，条款指向不明」。这句放在模板审核段里，读起来是在挑她发来的工商局范本，她立刻回：「股东就是这个合伙企业的合伙人呀，写的没有问题啊，这是工商局的模板」。

实查结论：模板全文 36 处表述全部是「合伙人」，没有「股东」二字。我的判断本身没错，错在那句话的真实对象是她新需求里的措辞（她写的是「所有的股东变更和分红分配的权利」），而不是模板。对象没说清，等于把她的输入当成了错误去纠正。

代价：一轮往返 + 需要立刻纠偏（「你说得对，模板本身没问题」）。这类错置在合同审核里代价更高——客户会以为你在挑他给的文件，注意力从条款风险转移到辩护模板。

### A2（P2）三个脚本技术错误，全是已知 API 误用，现场修

- `gen_partner_agreement.py` 首跑：`AttributeError: 'Paragraph' object has no attribute 'font'`。python-docx 的段落没有 `.font`，字体必须落到 run，或调 `style.font`。
- `gen_redline.py` 首跑：`r._element.rPr` 为 None，直接 `.set()` 崩。rPr 需先创建或判空。
- `soffice / libreoffice` 本机不存在，转而用 qlmanage 出缩略图；随后又写错输出目录（`/tmp/qlout/` 不存在），两次空调用才找到图。

合计 3 次崩溃 + 2 次无效路径探测，都在 12:33–12:41 这 8 分钟内。
