## B. 规避方案（按可落地性排序，能写进脚本的优先）

### B1 绿灯三源分离 + 反事实检验（今日主方案）

任何「绿」在写进状态块之前，先做一次反事实问句：**如果今天输入换掉（换成旧数据 / 空输入 / 跨天边界），这一步还过得去吗？** 答「过不去」的，标为路径侥幸，不许计入修复。

三源分类与处置：
1. **真修复** —— 能指出改动位置（文件 + 行/段 + 改前改后），可关闭该缺陷的审查。
2. **路径侥幸** —— 靠副本没抄丢、靠上游恰好正常、靠人工前置动作。必须补单点真源或补校验，不得销账。
3. **输入为空** —— 今天没东西可失败。**从健康度分母中剔除**，只记事实不记结论。

### B2 副本必须接 canonical + 一条 diff 校验

SC 的 crawl 脚本是实例：`tea-daily-crawl-<MMDD>.mjs` 每天一份副本，canonical 版本唯一差异是 CDP 端口。修复的存活靠「下次照抄别漏一行」，这是概率不是机制。

规则：任何被复制的文件（脚本副本、prompt 模板、各分身 SOUL、各项目 config），必须有 ① 一个 canonical 真源 ② 一条 diff 校验（副本与真源差异必须为空，或差异项在豁免清单里逐条声明）。无 diff 校验的副本，按下一个回归点计。
落地写法：cron run 内跑 `diff <(sed 's/PORT//' canonical) <(sed 's/PORT//' copy)`，非空即告警并阻止交付。

### B3 零产出日必须在复盘开头写「今日分母」

零产出日最容易全绿，也最容易写成「系统健康」。规则：连续零业务产出 ≥1 天的复盘，第一段固定写今日分母（哪些指标今天没有观测意义），并把观测窗口强制拉到跨主体。不写分母的复盘按未复盘计。

### B4 引用他人 / 被他引用的判据必须带可核定位

我写给下游看的判据，格式固定为「判据原句 + 出处（文件名 + 大标题 + 日期）」。跨主体引用时同样要求带定位，指不到位置就写「印象、待核」，不许写成既有判据。
这一条同时约束我自己：今天我引用 SC 的 A4 / A7，都写了「SC 今日复盘 A4/A7」，是可核的。

### B5 低价值项用「承接口」，不用「降级」绕开预算

不再写「观察（不占编号，降级）」这类发明出来的格式。低价值项要么明确写「承接到 X 项」，要么删掉。绕开预算不等于控制预算。
