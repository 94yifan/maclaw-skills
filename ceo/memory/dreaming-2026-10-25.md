## D. 知识串联（核心）

### D1（主·治理层）委派同源失效：把修复派给共用同一失效结构的节点，等于给缺陷多加一个受害者

- **证据**：见 A1。委托方与缺陷同源（supermind 自己 10-24 死在收尾回读），到期日 22:00 零分发，当晚 4 个 job 全部死在收尾读/自检，产物 4/4 在盘、交付 4/4 失败。
- **串联**：10-22 缝合1（修复半径由载体决定，不由发现者决定）→ 10-20 缝合1（分发失败两个方向：漏发与重发）→ 守卫二十一（无消费者动作即停例行）。
- **新认知**：分发这件事被我一直当成「通知」处理，实际它是「投放」——要把条款放进执行前必读的那一行。选谁投放，不能只看权限，要看**失效相关性**：接收方与缺陷共用结构时，它自己就在受害队列里，指望它去救别人等于让病人主刀。
- **判据**：委派前两问——①它有能力改吗？②它和这个缺陷共用失效结构吗？第二问答是，改走共享层（payload / 脚本模板，一次改七个），或降级为一次人工动作。
- **管理同构（曼拾）**：某个 PM 连续三次在同一类客户上延期，把「整改这类问题」的任务交给他，整改文件大概率也交不出来——不是态度问题，是他正处在产生问题的同一个结构里。正确动作是总部改流程或换人，不是给当事人加一项自我整改。客户侧同理：把「素材返工率高」交给产出素材的执行同学自己出方案，方案会写成「加强审核」，因为审核是他唯一能控制的一环。

### D2（主·验证层）读数到结论是两段不是一段：语义层与判定层；今天四样本语义层错四次、判定层错零次

- **证据（同日四样本，全部本会话或原文可核）**：
  1. tea seq146：`grep -c '^- \[ \]'` 返回 1，语义是「未勾选 0 行」（合格），被读成「不通过」（不合格）——**方向恰好相反**。
  2. SP seq147：手写毫秒阈值查得空集，语义是「阈值没覆盖到数据」，被读成「今日无 run」。
  3. CFO seq149：归档器 rc=0，语义是「进程跑完」，被读成「已归档」，实际释放 0 字节。
  4. supermind seq147：`list memory/2026-10-25.md` 失败，语义是「相对路径取不到」，被读成「整轮失败」。
- **串联**：守卫二十（读数 × 判断 × 动作）——我今天把第二段「判断」拆成两层：**语义层**（这个读数什么意思）与**判定层**（相对标准合不合格）。四样本语义层错 4 次，判定层错 0 次。也就是说，我们这套体系的阈值、上限、门禁标准基本是对的，错的是把读数翻译成人话的那一步。
- **为什么集中在这里**：业务命令失败时输出是「没了」（一眼看见）；验证命令失败时输出是「一个判决」（长得跟正常判决一模一样）。验证层是整个链路里唯一自己生产结论的层，所以只有它能让错误的结论带着合格的外观上线。
- **判据（三条，已写入记忆）**：①门禁判定值必须来自被打印的数字，退出码只作「执行是否发生」的信号；②`rc=0` 必须跟一个效果读数（释放字节 / 产出文件 / 变更行数），效果为 0 视同失败；③空结果先跑一次无过滤 count 自证分母，再下「无记录」结论。
- **客户侧同构**：客户说「方案收到了」等于 rc=0，不等于采纳（效果读数）；后台显示「计划在跑」等于进程活着，不等于有量（效果读数）；周报写「已优化素材 30 条」等于动作计数，不等于投放效果。

### D3（主·商业层）交付物的一级标准是可转发性，不是完整性

- **证据**：逸凡 12:46 原话（第二次重述同一要求）「不需要赞藏数据，不需要你的额外判断依据写入日报，确保日报是专业的可转发可使用的」。被否的是 11:00 版——那一版信息更全（每条带转评赞、带「对品牌而言」判断、带行业信号段），恰恰因为更全而不可转发：客户拿到要删 21 处才能给老板看。
- **串联**：教训17（逸凡不 access 本机文件，产出必须可交付）→ 09-15 门禁三档（对客确认要留对象/时效/确认人）→ 10-18 交付可见层优先于内容层 → 我一直写的「一条消息说清楚」。
- **新认知**：交付物的价值 = 下一位读者**零删改**就能转发。信息量与可转发性负相关——每加一句「对品牌而言」，就多一个删改动作，多一个删改动作就多一次「算了不转了」。专业不是信息多，是**每一句都能被原样转述**。
- **判据**：交付前问「接收方要转给谁、他需要删掉哪几句」。答不出读者和删改点，就是不达；有删改动作，即判定不达。
- **反向代价**：茶饮日报这类例行交付，读者是客户方的执行层，他要转给市场总监。带数据判断的版本转发率低，客户体感是「你们的日报要加工」，最终表现为「日报没什么用」。这是把内部工作痕迹当成了交付价值。
- **自我应用**：我的摘要消息同样受这条约束。今天起摘要只保留三块——今天发生了什么（带读数）、哪个判断变了、需要逸凡做什么（一件）。
