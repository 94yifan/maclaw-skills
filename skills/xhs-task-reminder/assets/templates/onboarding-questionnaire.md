# 项目初始化问询清单（Skill 第0步 · 两阶段交互版）

> 用途：新项目 apply 本 Skill 时，按两阶段交互完成配置，收齐后才能启用提醒/打标/汇报。
> 设计原则：第一轮只问少量核心问题，拿到后先给方案建议，第二轮针对方案确认修改点。避免一上来十几个问题吓退同事。

## 第一阶段：核心信息问询（群里直接发这 4-5 条）

1. 这个项目叫什么名字？客户是哪家？
2. 项目属于哪一类：投流投放、KFS种草、商务到策略端，还是其他？都不是的话简单描述一下项目是做什么的。
3. 项目上有哪些同事参与？把每个人的名字发我，我登记负责人。
4. 项目有没有分侧？比如蓝氏是分成猫和幼猫两侧。有的话告诉我每侧对应哪位同事，有没有两侧都管的同事？
5. （如果不知道有没有表格）项目现在有没有已建好的飞书多维表格？有的话把链接发我。

## 第二阶段：方案建议 + 确认修改点

### 拿到第一阶段答案后，先输出一版建议方案：

1. 表格方案：标准字段（日期/具体内容/负责人/截止时间/状态/备注/级别/是否日常）+ 按项目类型推荐的分类选项 + 分侧字段（如有分侧）
2. 汇报方案：汇报时间建议（默认 19:10）、汇报维度建议（按项目类型：投流类按搜索/人群/内容/日常，KFS 类按种草/投流/转化，商务类按线索/提案/交付）、分侧出还是整体出
3. 提醒方案：主提醒时间建议（默认 10:55）、特殊提醒任务占位

### 然后逐项确认（基于方案提问，而不是泛泛问）：

1. 表格表头：我建议的字段和分类标签，哪里需要改？要加什么字段、删什么字段、分类选项要增删哪些？
2. 汇报时间：默认晚上 19:10 可以吗？要改几点？
3. 汇报维度：按我建议的这几块分，可以吗？要加哪块、去掉哪块？
4. 主提醒时间：默认上午 10:55 可以吗？
5. 有没有固定时间要提醒的特殊任务？比如每天几点、每两天一次，逐条说：什么任务、多久一次、提醒谁。
6. 有没有每天要做的例行检查？比如评论区巡查、笔记上线检查、内容审核、合同跟进，逐条说：检查什么、几点、谁负责。
7. 要不要客户汇报？汇报对象是客户还是内部？
8. 其他个性化规则：哪些词不能出现在汇报里、特殊节奏、特定沟通要求，现在都可以说。

### 确认完成后：

1. 把答案填入 assets/config-template.json 生成项目 config
2. 按 config 建表/确认表格字段
3. 按 config 建 cron 提醒（主提醒 + 特殊提醒 + 每日检查 + 晚间汇报）
4. 在群内宣布 Skill 启用，说明以后待办/状态更新直接发群里即可

## 交互节奏说明

- 第一阶段 5 个问题一次发完，等回答
- 第二阶段先给方案（表格字段 + 汇报时间/维度 + 提醒时间），再逐项确认修改点
- 每确认完一项即时记录，不攒到最后
- 同事对某问题没答或说随便，按默认方案执行并在 config 里标注，不反复追问
