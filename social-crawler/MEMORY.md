## 技术关键（当前有效流程）

- **抓取方式（2026-08 起主流程）**：主代理直接用 browser 工具 evaluate 抓 m.weibo.cn API，分4批（6+6+6+5），每批间隔5秒。API 字段是 mblog（不是 m），containerid=107603{uid}+page_type=03 稳定返回10条/页。星巴克 custom=starbucks 解析真实 UID 1741514817。
- **24h 窗口铁律（2026-08-22 血泪教训）**：日报只写24h窗口内内容，过滤逻辑（Date.parse(created_at) 与 Date.now()-24h 比较）写进 evaluate 脚本本身，不靠事后人工判断；无动态品牌标注"今日无动态（最新微博日期）"。
- **逐品牌核验**：抓取后先列各品牌最新3条微博核对再写报告，特别是库迪/瑞幸等高频品牌（2026-08-06 漏库迪教训）。
- **CDP 9333**：用户浏览器 session 经常过期；备用 openclaw 沙箱浏览器（ws://127.0.0.1:18800），node 直连 fetch 会被反爬，必须走浏览器同源 fetch（credentials:include）。
- **飞书发群**：用 message 工具分 4-5 条消息发 social crawler 群。
- **存档**：`memory/weibo_daily_YYYY-MM-DD.md`

## 报告格式标准（2026-06-25 更新 — 已固化到 skill）

**关键铁律（逸凡确认）**：
1. **不要概览表** — 直接进入品牌内容
2. **不要微博互动抽奖** — 聚焦品牌营销动作本身
3. 每个品牌写出核心营销动作（新品/IP联名/营销活动），附品牌价值判断
4. 无动态品牌简写

### 格式结构（三段式，不可改）

**【新品上市】** 产品名、核心卖点、技术标签（HPP/NFC/低温萃取等）、食材溯源信息，每条结尾加品牌价值判断
**【IP联名/艺人宣发】** IP/艺人名称、联动形式（主题店/周边/短片等）、合作深度，每条结尾加品牌价值判断
**【营销活动】** 活动内容、时间范围、玩法机制，**必须有对营销效果的判断分析**
**无动态品牌**直接写"今日无动态"，品牌间空一行

### 内容写作原则
1. 新品要详细完善（卖点/技术工艺/食材溯源）
2. 营销活动要有效果分析（为什么做、对品牌有什么用）
3. 品牌价值判断精准（对品牌自身，不发散到行业）
4. 不确定的信息不写，不上新时间不编
5. 行业洞察全部放末尾"行业层面信号"部分

### 汇总 + 行业洞察
- **今日概览汇总表**（品牌 | 新品 | IP联名 | 营销）
- **汇总数据**（总条数 | 覆盖品牌数 | 分类统计）
- **行业层面信号（3条左右）**：每条一个核心判断，关键结论加粗，跨品牌对比找规律
