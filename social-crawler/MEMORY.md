## 技术关键（当前有效流程）

- **抓取方式（2026-08 起主流程）**：主代理直接用 browser 工具 evaluate 抓 m.weibo.cn API，分4批（6+6+6+5），每批间隔5秒。API 字段是 mblog（不是 m），containerid=107603{uid}+page_type=03 稳定返回10条/页。星巴克 custom=starbucks 解析真实 UID 1741514817。
- **24h 窗口铁律（2026-08-22 血泪教训）**：日报只写24h窗口内内容，过滤逻辑（Date.parse(created_at) 与 Date.now()-24h 比较）写进 evaluate 脚本本身，不靠事后人工判断；无动态品牌标注"今日无动态"（不写日期时间）。
- **逐品牌核验**：抓取后先列各品牌最新3条微博核对再写报告，特别是库迪/瑞幸等高频品牌（2026-08-06 漏库迪教训）。
- **CDP 9333**：用户浏览器 session 经常过期；备用 openclaw 沙箱浏览器（ws://127.0.0.1:18800），node 直连 fetch 会被反爬，必须走浏览器同源 fetch（credentials:include）。
- **飞书发群**：用 message 工具分 4-5 条消息发 social crawler 群。
- **存档**：`memory/weibo_daily_YYYY-MM-DD.md`

## 报告格式标准（2026-10-28 修订 — 行业信号段作废我 10-25 的误删，恢复为固定结构）

**铁律（逸凡 2026-10-25 原话：「不需要赞藏数据」，2026-10-26「也不需要时间」；2026-10-28 纠正：他从未要求删除行业信号）**：
1. **零互动数据** — 不写转发/评论/点赞数字、总互动、互动排名、r+c+l 口径。数据只进 raw 与台账。
2. **品牌段零单品牌判断** — 品牌段不写「对品牌而言」「说明」「判断」「这意味着」，只写品牌做了什么。
3. **零内部语言** — 采集说明、守恒式、台账勾选、样本龄、跨天比对不进正文。
4. **行业层面信号必写** — 无动态清单之后固定一节 `**行业层面信号**`，3-6 条，每条 `1. **结论句。**` + 跨品牌事实与判断（至少涉及 2 个品牌），不写互动数字与发帖时间。**过往几个月一直有，属固定栏目，不得擅自删。**
5. **判据** — 品牌段可原样转发给客户不需删改；行业信号段独立成节。

### 格式结构（固定一段式 + 无动态清单 + 行业信号）
header 三行（标题 / 统计区间=日期级 / 覆盖数+条数）→ 品牌段（`**品牌名**` + 【新品上市】【IP联名/艺人宣发】【营销活动】三类事实 bullet，不标发帖时间）→ 一行「今日无动态：品牌A、品牌B」→ `**行业层面信号**` 3-6 条。
- 品牌内顺序固定：新品 → 联名 → 营销
- 无内容的分类不写，不占位
- 不概览表、不汇总表；行业信号段除外（固定保留，见上）

**【新品上市】** 产品名、核心卖点、技术标签（HPP/NFC/低温萃取等）、食材溯源信息，只写事实不写判断
**【IP联名/艺人宣发】** IP/艺人名称、联动形式（主题店/周边/短片等）、合作深度，只写事实不写判断
**【营销活动】** 活动内容、时间范围、玩法机制、赠品与抽奖人数，不写效果分析
**无动态品牌**写成一行"今日无动态：品牌A、品牌B"，不写时间

### 内容写作原则
1. 新品写全事实：产品名/卖点/技术工艺/食材溯源
2. 营销活动写清机制：内容、时间范围、玩法、赠品、抽奖人数、话题
3. 不确定的信息不写，不编时间
4. 零互动数据、零判断（2026-10-25）
