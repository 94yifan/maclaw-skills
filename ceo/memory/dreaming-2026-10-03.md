## B. 规避方案（写进 MEMORY / 编译进脚本，每条对应 A）

1. **代偿读数三问（对应 A5 / A1 / A4，见 D-主缝合1）**：每用一个读数下结论前问——①它直接读的是要判定的对象，还是代理变量？②偏差方向朝哪？③有无第二个独立读数交叉？无独立读数的代理不得用于判定。**具体动作：SC 侧修 MEMORY 或改 skill，二者留一说，停止再挑合规产物的毛病（属 SC payload/skill 型修复）。**
2. **机械挂账动作搭车（对应 A2，见 D-主缝合2）**：登记/回填/销账/编号同步类动作不单列头部槽位，并入本轮必执行的写动作。**CEO 自应用：守卫断号不再每晚单列，并入 F 唯一决定项。**
3. **产物在 / 产物不在 两栏读（对应 A1 / A4）**：跨主体对账同型故障，分「error 且产物在」与「error 且产物不在」两栏，禁止只对 error 率（承接 supermind 10-03 缝合2）。**SP 的第一动作不是分析根因，是照抄已落盘主体的保护点位置（写作前置）。**
4. **交付与 run 状态解耦（对应 A3 / A4）**：产物写好即发（写文件后立即 message），使交付不依赖 run 成功判定；配 failureAlert(after:3, announce) 使失败可见。仅主 session/逸凡可改。
5. **收尾顺序固定（承接 CFO 守卫AF）**：全部写动作（含「已执行/证据」行）→ commit → 非 ignored status 取证 → push → 远端三态取证。证据行必须排在 commit 之前。
6. **可达性按通道探活（承接 CFO 守卫Z 修订）**：结论格式改为 `<对象> 可达（实测 …, 通道=<curl|git push>）`；curl 通不构成 push 可达的证据。
7. **error 先分型（承接 book 规则18）**：见 error 先读 `lastDiagnostics`，按 timeout / tool-failure / other 分列，禁止混记为「超时」。
