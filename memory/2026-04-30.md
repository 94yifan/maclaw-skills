## 第一步：今日错题本

### 错误1：browser.disconnect() 导致脚本崩溃（最严重）

**现象：** 爬虫脚本在 Chromium CDP 连接上调用了不存在的 `disconnect()` 方法，导致 `TypeError`，脚本以 exit code 1 退出，今日日报数据完全丢失。

**为什么错：** 这是代码逻辑错误。`chromium.connectOverCDP()` 返回的 CDPBrowser 对象没有 `disconnect()` 方法——我们连接的是已有的 Chrome 用户会话，不是自己启动的浏览器，不应该断开连接。进程结束时让浏览器保持原状即可。

**花了多久：** 在 Dreaming Noon（12:00）才被发现和修复，影响了当天整个上午的日报产出。

**怎么修复：** 删除 `/private/tmp/crawl-tea.mjs` 中的 `await browser.disconnect()` 调用，改为 `process.exit(0)` 正常退出。

---

**现象：** 10:05 AM 附近，Gateway 连续多次重启尝试（每次间隔5秒），返回 `EADDRINUSE` 错误。Cron 触发时 gateway 可能处于不稳定状态。

## 第二步：根因分析

三个错误追问一层：

1. **browser.disconnect()** — 不是操作失误，是认知偏差。误以为 CDP 连接需要主动断开，而实际上连接已有 Chrome 会话不应该管理其生命周期。

2. **Gateway 重启循环** — 是流程漏洞：配置 reload 的时机没有和 cron 执行窗口做隔离。频繁配置变更触发的 reload 和 cron 触发时机撞车。

3. **日报数据丢失** — 根本问题是"信任 session 自动保存"。这是系统设计假设，没有兜底机制。

**结论：** 今天最大的教训是"脚本必须有自我保护机制"——不能依赖任何外部状态的稳定性，必须在执行过程中主动写文件和报告。

## 第四步：记忆更新

**三条最关键教训（写入 MEMORY.md）：**

1. **CDP 连接不管理生命周期**：连接已有 Chrome 会话（`connectOverCDP`）后，进程结束时不需要调用任何 disconnect 方法，浏览器保持原状即可。这和启动浏览器（`launch`）后需要 `close` 不同。

2. **脚本必须有自我保护**：关键 Cron 脚本必须在执行过程中主动写文件，不能依赖 session 结束后自动保存。崩溃时自动保存机制也会失效。

3. **关键产出要设检查节点**：重要 Cron 触发后，必须在合理时间窗口（如30分钟内）检查产出是否成功，发现问题立刻重跑，不要等到下次人工检查才发现。
