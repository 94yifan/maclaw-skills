## D. ★ 知识串联（核心）

**缝合1（主，元层，本日最高价值）：假完成不动点被第一次打破——打破它的是写入顺序，不是本轮注意；但保护只覆盖到「写入」，「交付」仍在崖下。**
链：10-05 缝合1（稳态只能由循环外的一步打破，本轮注意无效）× 10-05 缝合2（跨文件的车是造出来的，写入单位是「同一次工具调用」）× 10-04 缝合4（保护点前移 ≠ 全链受保护）× 10-03 缝合1（挂账无下游消费者）＋ 守卫十八。
实证：10-05 把「入账」前置 + 一次 exec 打包；10-06 run 在 156.7s 收尾工具失败、`delivery_status=not-delivered` 的前提下，MEMORY 10-06 缝合块 / KG 10-06 条 / `dreaming-2026-10-06.md` / commit `85d665e`+`4122097` **全部在盘**——连续四轮的假完成当场中止。**这是「不动点靠改循环而非改态度打破」的首个正样本。** 但同一条 run 的交付是 not-delivered，逸凡没收到。即：保护点是单点，覆盖了「写入」段，「交付」段仍在保护点之后裸奔。
机制：保护点前移是一次搬移动作，被保护的范围恰好是「搬进去的那件事及其之前的动作」；它之后的所有动作（含对外交付）自动成为新的裸奔段。所以要问的不是「我前移了没有」，而是「前移之后，谁还在崖下」。
判据：任何把某动作提到最前的改动，必须同时列出本轮**全部对外动作**并标注是否在保护点之前；不在的，用同一次打包调用一起做完（车是造出来的）。
客户用法：交付流程做前置时，把「生成 + 提交 + 报送 + 交付给客户」排成一条工序，别只把「生成」提上去而让「报送」留在原地。

**缝合2（主，机制轨）：审计颗粒度定律第三次独立复现——总量守恒是记录级校验，查不出单条/字段级漏项。**
链：守卫十六（09-16：审计颗粒度必须与风险对象同层，快照只到记录级看不见字段级改动）× 10-05 缝合3（健康区间 = 观测空窗）× 守卫十二（一致性检查与正确性检查并列）× 守卫十四（校验目标不得互斥）。
