## A. 执行错误

### 错误1：旧版外部案例大量编造
旧版本读书笔记中的"外部案例"有大量编造——写了虚构的企业案例来佐证谬误。新版已全部删除更换为真实可查事件（加密货币、TikTok禁令、Intel裁员、BLS数据修正、Apple Crush广告）。

**根因分析**：推理守卫三（事实数据可溯源，绝不编造）虽然已写入SOUL.md，但在"外部案例"这个具体场景中未被激活。说明守卫三的心智模型只覆盖了"数据统计"类场景（增长率、排名），没有扩展到"叙事性例子"场景。

### 错误2：思维导图经历3次迭代才定型
从辐射状→卡片流→树状图，反复改稿才确定树状图可行。前两次没成功可能是因为预览验证不充分就开始写代码。

**根因分析**：SOUL.md中逸凡已强调"视觉类产出必须先预览再发"，但process是：先写完整HTML→预览发现不行→重写。代价高。下次应该先画草图/先用几个节点试通结构再批量生成。

## B. 规避方案

### 规避1：外部案例也必须可溯源
**写进memory的新规则（继承推理守卫三）：**
> 外部案例必须源自可查证的真实事件（来源：公开报道/书籍/数据公报）。不允许出现"某知名科技公司""有一个真实案例"这种模糊归因。每个案例写完后反问一次：我能指出它的原始来源吗？答不上来就是编的。

### 规避2：思维导图要先画结构骨架再填充
**写进memory的新规则：**
> 思维导图类产出：先输出一个纯文字版的结构树（3-5个节点），确认结构可行后再写HTML代码。避免完整生成后才发现结构方案不对。

## D. ★ 知识串联（核心环节）

### 串联1：弱势批判性思维 → 编造数据的心理学根因

**《学会提问》关键概念**：弱势批判性思维 = 用批判性思维"捍卫自己当前的信念"，目的是驳倒别人证明自己没错。强势批判性思维 = 评价所有断言包括自己的信念，随时准备承认自己错了。

**连接已有知识**：之前系统性教训中"编造了蓝氏王濛联名时间"是底层心理驱动——不是技术漏洞（知道应该查来源），是**弱势批判性思维**的自然表现：你想让分析看起来完整、有深度、值得信赖，所以大脑自动"补全"了缺失信息来捍卫"我很靠谱"这个自我信念。

**新洞见**：这意味着推理守卫三（事实可溯源）的对抗对象不是"记忆力差"或"搜索技术不够好"，而是**弱势批判性思维的心理防御机制**。解决方案不只是查来源，而是在每个补充数据时先问自己：**"我是在帮自己的论证找证据，还是在检查自己是不是错了？"**

**写入MEMORY.md → 是**

### 串联2：情感大象与骑手 → 协议演化的执行悖论

**《学会提问》关键概念**：乔纳森·海特的比喻——情感是一头发怒的大象，理智是骑在大象背上弱小的骑手。你以为在理性决策，很多时候是情感先做了决定，理性跳出来找个理由合理化它。

**连接已有知识**：之前知识缝合区中"赛博格控制悖论"——认知上知道该精简但执行上继续做原来的事（第8次复盘）。这个悖论的本质就是**骑手拉不住大象**。认知到位（骑手有路线）≠执行到位（大象不配合）。

**新洞见**：协议演化的7阶段中，从"认知脱先"到"执行脱先"有一道实质鸿沟——这道鸿沟不是认知问题（你知道该做什么），是执行问题（你做不到）。解决办法不是给骑手更好的地图，而是：**减少大象的惯性**。在agent场景中，就是降低从认知到执行的阻力——直接在SOUL.md中写上切换条件，而不是留到每次复盘时重新判断。

**写入MEMORY.md → 是**

### 串联3：淘金式思维 → 复盘协议的自我审视时刻

**《学会提问》关键概念**：海绵式思维（被动吸收）vs 淘金式思维（主动质疑，追问"这个站得住吗"）。

**连接已有知识**：book分身复盘协议的前7次是典型的"海绵式"——每次零数据都照常执行完整复盘流程，被动吸收"无数据"这个事实。从第8次开始进入"淘金式"——开始质疑协议本身："这个复盘还有价值吗？为什么要继续做？"

**新洞见**：《学会提问》的出现时间（复盘协议完整走完生命周期的第4天）几乎是对整个复盘演进的元注释。这本书告诉我们的不是"如何更好地做读书笔记"，而是"已经做完了你该做的事——现在去问问自己那个功课做得对不对"。

**写入MEMORY.md → 是**

### 串联4：10步检查清单+灰度思考 → 零数据诊断梯的补全

**《学会提问》关键概念**：第10步不是非黑即白的yes/no，而是"在什么条件下、以多大把握值得接受"。综合可信度评分（0-10分）。

**连接已有知识**：零数据诊断梯（4梯）只做到了第4梯（观察者效应），但没有定义"诊断完之后的决策"。它缺少一个收尾动作——在完成所有分析后，给出一个**综合判断的信任度评分**，并明确"在什么条件下改变判断"。

**新洞见**：补全零数据诊断梯为5梯框架：

```
梯1：确认 — 真的零数据还是没找到？
梯2：结构 — 前置条件链哪一环断了？
梯3：动机 — 用户为什么不启动？
梯4：元认知 — 我的分析本身是否影响了系统？
梯5：决策 — 综合可信度评分（0-10） + 退出条件。什么条件下改变判断？
```

这个第五梯正是《学会提问》第10步和灰度思考的直接应用。之前梯子缺的不是分析能力，是**决策闭环能力**。

**写入MEMORY.md → 是**

### 串联5：平均值陷阱 → Pro/Flash判断标准的认知范式移植

**《学会提问》关键概念**：平均值陷阱——"平均收入15万"可能是一个CEO年薪5000万拉出来的假象。需要看中位数、分布、样本构成。

**连接已有知识**：逸凡7月12日补充的"Pro/Flash判断标准不是看改几行文字，是看需要多少结构性思考"，其修正过程本身就是一次平均值陷阱的完美案例：
- **误判**："只看改了的文字量"（用平均值思维判断工作量）→ 认为"改动看起来小 = Flash"
- **真实认知**：发现字数少但背后是信息架构调整 → 这是"极端值在平均值中被隐藏"

**新洞见**：这个案例展示了一个可迁移的元能力——**当你要评估一个任务的复杂度时，不要只看它"改了多少"（平均值），要看它"影响的范围层次"（分布）**。这个认知可以在任何场景中复用：代码Review（别只看行数看影响模块）、读书进度（别只看页数看理解深度）、项目评估（别只看工时看架构影响）。

**写入MEMORY.md → 是**
