## B. 规避方案（每条对应 A 项，作为下次执行铁律）

1. **payload 模板补 header 必填（对应 A2，根因层，最高优先级）**：在 tea-daily-report payload 的格式模板最前面写死三行——`# 茶饮咖啡品牌微博日报 · <今天>`、`**窗口：<起点> 11:00 ~ <当天> 11:00（24h，crawlTime）**`、`**覆盖：23 品牌 | 有动态 N | 无动态 M**`。**先定义字段，再谈校验**
2. **payload 加「运行内工具禁令」（对应 A1，第 8 天未落地）**：三条硬约束——写完立即以最终回复输出正文并结束、**不得再发起任何工具调用**；**run 内禁止 cron get/update/remove**；**收尾校验类命令默认不跑**（可选项加 `|| true`）。**仅主 session 可改**
3. **交付兜底（对应 A1）**：加交付重试，或加一步「写文件后立即 `message` 发群」，把交付从「run 成功才发生」解耦为「文件写好即发」
4. **header 存在性校验（对应 A2）**：报告写入后强制校验前 3 行含标题 + `窗口：` + `覆盖：`，缺一即补，不允许无头产出进群
5. **窗口改造一步到位（对应 A3，第 10 天）**：脚本开头 `const t0 = Date.now()` 一次，全品牌统一 `created_at ∈ (t0-24h, t0]`；header 与 raw `crawlTime` 引用同一 t0；写 `/tmp/tea-last-window.json`；脚本头注释日期改当天。**唯一必须脚本层修、已挂 10 天的执行项**
6. **同主题重复帖必须落点（对应 A4）**：品牌内同产品线（预告/正式/视频）多帖，**要么合并写明「含预告+正式两帖」，要么逐条引**，不允许静默丢弃；写完核对 `raw = 引用 + 剔除 + 未明引`，未明引必须 0
7. **互动数字呈现定规则（对应 A5，新）**：二选一并写进 skill——①所有有动态品牌统一带三元组，②统一不带、只在行业信号引用处带关键数字；**不允许「随机 1/14 家带数字」**
8. **MEMORY 与系统对账（对应 A6，第 4 天）**：删两条过时陈述，改为「morning-crawl.sh 已从 crontab 删除」「social-crawler 名下 3 个 job 在册，日报有 cron 自动化」；**并立常设动作：任何「系统状态」结论写入 MEMORY 前，以 `~/.openclaw/state/openclaw.sqlite` 的 `cron_jobs`/`cron_run_logs` 为准复核**

10. **跨日一致性检查（对应 A8，第 7 天）**：同一产品/活动跨日口径强制比对；无法从 raw 确认的写「待验证」
