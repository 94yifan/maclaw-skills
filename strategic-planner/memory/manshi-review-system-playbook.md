# 曼拾复盘系统交互 Playbook

版本: v2.0
更新日期: 2026-07-27
用途: 系统执行复盘任务的标准化操作流程
基准模板: OnePage GRARI 框架

---

## 0. 前置问询流程

前置问询必须在任何分析工作开始之前完成。四个确认按顺序执行, 不可跳过。

### 0.1 模板确认

系统收到复盘任务后, 第一件事是确认交付格式:

询问: 本次复盘是否有客户指定的模板或格式要求?

情况A: 客户有指定模板
- 获取该模板文件(PPT/PDF/Word)
- 提取模板结构: 模块名称、页面顺序、数据图表位置、内容要求
- 将模板结构映射到 GRARI 五模块(Goal/Result/Analysis/Review/Insight), 标记覆盖情况和缺失维度
- 进入分支A: 客户模板适配流程(见 2.2)
- 缺失维度以附录或补充分析形式补齐, 不在正文中强行塞入

情况B: 客户没有指定模板
- 使用曼拾 OnePage GRARI 模板作为基准
- 确认报告粒度: OnePage 精简版(给内部/快速汇报) 还是完整报告版(给客户正式交付)
- 进入分支B: OnePage 标准流程(见 2.3)

### 0.2 数据可用性确认

确认模板后, 立即确认数据可用性。按数据准备三确认执行:

确认1: 数据口径
- 总流量 / 自然流 / 广告流是否可区分
- 信息流是否包含视频内流
- 各平台(聚光/蒲公英/灵犀/千瓜)数据口径是否统一
- 搜索指标(SOV/SOC/搜索指数)是否有直客数据(聚光后台仅代子账号维度, 有偏差)

确认2: 数据周期
- 数据是汇总值还是 by-day
- 各数据源周期是否一致(投放周期 vs 数据回传周期可能有延迟)
- 是否有投前 baseline 数据用于对比

确认3: 数据粒度
- 达人维度: 达人ID x 笔记ID
- 投放维度: 账户 x 场域 x 计划 x 笔记 x 创意
- 搜索维度: 关键词 x 人群包
- 人群维度: P人群 / TI人群 / 人群包

### 0.3 交付要求确认

- 交付截止时间
- 交付格式(PPT页面数/Word篇幅/在线文档)
- 是否需要现场汇报(影响内容深度和叙事节奏)
- 是否有客户自定义指标或特殊口径要求
- 是否需要中英文双语

### 0.4 受众适配确认

**本条为前置问询必问项, 不可跳过。**

询问: 这份报告的读者是谁?

三种典型受众及对应适配规则:

受众A: 客户品牌总监/CMO
- 术语深度: 可使用专业营销术语, 无需额外解释
- 数据粒度: 高颗粒度关键指标即可, 不需要逐条笔记的执行级数据
- 结论颗粒度: 战略层结论为主, 关注"我们做对了什么策略决策""这个策略能不能复用"
- 叙事方式: 先给结论再给证明, 金字塔结构
- 篇幅: 精简, 每个观点不超过3页

受众B: 客户媒介执行/投放负责人
- 术语深度: 专业术语需要简要解释或附术语表
- 数据粒度: 需详细到可执行操作的粒度 -- 具体到笔记/人群包/关键词/计划
- 结论颗粒度: 战术层建议为主, 关注"哪个方向好, 哪个方向不好, 下次具体怎么调"
- 叙事方式: 分类分层展开, 每类数据单独讲清楚
- 篇幅: 可较长, 确保操作建议可直接落地

受众C: 内部团队
- 术语深度: 无障碍, 可用曼拾内部术语
- 数据粒度: 最细粒度, 包含所有原始数据
- 结论颗粒度: 完整分析 + 方法论萃取 + 可复用/可改进路径
- 叙事方式: 不做客户汇报叙事包装, 直给问题和教训
- 篇幅: 不限篇幅, 但每个分析必须标注"对客户报告的适配方式"

若同一份报告有多个读者层(如品牌总监过目 + 媒介执行落地), 以最高决策层为正文受众, 执行层信息以附录或标注形式补充。

确认受众后, 将此信息写入项目元数据, 后续所有分析的术语深度和数据粒度均据此校准。

## 1. Schema: 复盘任务数据结构

定义复盘任务需要的全部数据字段。字段按必需/条件必需/可选三级分类。

### 1.1 项目元数据

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| project_name | string | 是 | 项目名称 |
| client_name | string | 是 | 客户品牌名称 |
| period_start | date | 是 | 投放开始日期 |
| period_end | date | 是 | 投放结束日期 |
| budget_total | number | 是 | 总预算(元) |
| budget_kfs_ratio | object | 条件 | KFS分配比例, KOL/Feeds/Search各占比 |
| platform | enum | 是 | 主要平台: 小红书/抖音/双平台/其他 |
| industry_category | string | 是 | 行业类目(用于benchmark查找) |
| project_background | text | 是 | 项目背景和立项原因 |
| project_purpose | text | 是 | 项目目的(为什么做, 与目标的区别) |
| target_audience | enum | 是 | 受众类型: brand_director / media_execution / internal_team / mixed |

### 1.2 KPI 定义

每个 KPI 记录为一条, 按三层分级标注:

| 字段 | 类型 | 必需 | 说明 |
|------|------|------|------|
| kpi_name | string | 是 | 指标名称 |
| kpi_tier | enum | 是 | P0 北极星 / P1 核心过程 / P2 参考 |
| kpi_target | number | 是 | 目标值 |
| kpi_actual | number | 是 | 实际值(如尚未获取, 标记为 null) |
| kpi_unit | string | 是 | 单位(元/%/人次等) |
| kpi_source | string | 是 | 数据来源(聚光/蒲公英/灵犀/直客/客户后台) |
| kpi_benchmark | number | 条件 | 行业基准值(如有) |
| kpi_benchmark_source | string | 条件 | 基准来源 |

P0 北极星指标(2-3个): 与项目目的最直接相关的核心结果指标
- 整体提升销量: 转化率 / CPUV / 长效ROI
- 人群资产提升: CPTI / 特定人群渗透率
- 心智占位: SOV/C

P1 核心过程指标: 反映中间环节效率
- TI 人群效率与互动: CPE / 回搜率

P2 参考指标: 浅层辅助判断
- CPC / CTR / CPM 等

| 淘宝联盟 | 内容互动率/引流率/店铺新访客率/收藏加购率/转化率/店铺新客率 | 电商后链路验证 |

### 1.4 分析维度数据结构

每个分析维度包含以下标准字段:

```
{
  dimension_name: "内容策略分析" | "人群分析" | "竞价策略分析" | "搜索分析" | "品牌广告分析",
  summary_conclusion: string,     // 该维度的策略型三段式总结
  highlight_events: [             // 亮点事件列表
    {

      key_actions: [string],      // 关键动作
      three_force: {              // 三力拆解
        strategy_force: string,   // 策略力归因
        execution_force: string,  // 执行力归因
        management_force: string, // 管理力归因
        objective_reasons: string // 客观原因
      }
    }
  ],
  problem_events: [...],          // 问题事件列表(结构同上)
  data_points: [                  // 支撑数据点
    {
      metric_name: string,
      value: number,
      benchmark: number | null,
      trend: "up" | "down" | "stable",
      so_what: string             // 必须有 So-What
    }
  ],
  recommendations: [string]       // 具体可执行的下一步建议
}
```

### 1.5 动态诊断: 数据可用性分级与 Fallback 路径

**核心原则: 数据不全时不强行输出薄报告。主动切换分析框架, 并提出替代分析方案。数据缺失不是借口, 是切换到更适合当前数据条件的分析框架的信号。**

#### 1.5.1 数据可用性分级

数据准备三确认完成后, 按以下标准对数据可用性分级:

A级(完整可用): 六大分析流所需数据齐全, 所有维度可分析。使用标准 GRARI 框架。

B级(部分缺失): 某个或某几个分析流缺少关键数据。对缺失维度执行 fallback 路径(见 1.5.2), 对可分析维度正常执行。

C级(严重缺失): 多个分析流缺少关键数据, 标准框架无法支撑。此时不强行做 GRARI, 而是基于已有数据创建一个精简分析框架。报告中明确标注"受限于数据可用性, 本次分析侧重X维度, Y和Z维度建议补充数据后做二次分析"。

D级(仅最基础数据可用): 基本只有消耗和曝光。做趋势分析和结构分析, 不做因果归因。明确告知客户数据完整度不足, 结论置信度相应降级。

#### 1.5.2 Fallback 路径: 各维度数据缺失时的替代分析方案

**内容策略分析维度 fallback:**
- 缺失: 笔记维度互动/转化数据 → 替代: 仅分析内容方向分布和封面/标题结构, 做定性判断不给定量的效果排序
- 缺失: 竞品内容数据 → 替代: 用行业大盘内容趋势做参照, 标注"缺少竞品参照, 判断基于行业均值"
- 缺失: 评论区数据 → 替代: 从笔记标题和内容文本中提取关键词做内容方向聚类, 标注"缺少用户反馈验证"

**人群分析维度 fallback:**
- 缺失: 人群包维度数据 → 替代: 仅做整体画像分析, 不做分人群包的效果对比; 标注"人群包颗粒度缺失, 精细化优化建议暂不可提供"
- 缺失: P/TI人群对比数据 → 替代: 仅做TI人群画像, 用行业通用人群画像做粗对比; 标注"缺乏本品牌P人群基线, 差异分析降级为参考性判断"
- 缺失: 灵犀AIPS数据 → 替代: 用投放前后搜索指数变化间接推断人群资产变化; 标注"AIPS数据缺失, 人群资产判断基于间接指标"

**竞价策略分析维度 fallback:**
- 缺失: 计划/单元层级数据 → 替代: 仅分析场域级别的效率差异, 不做计划间的赛马对比; 标注"计划颗粒度缺失, 无法识别最优/最差计划的特征"
- 缺失: 人群包消耗和效果数据 → 替代: 用整体人群画像和内容偏好的匹配度做间接判断; 标注"人群包数据缺失, 人群圈选效果判断为推测性结论"
- 缺失: 分阶段投放数据 → 替代: 将全周期数据做整体分析, 不做测试期/放量期/转化期的阶段性判断; 标注"缺少时段拆解, 投放节奏优化建议暂不可提供"

**搜索分析维度 fallback:**
- 缺失: 关键词维度数据 → 替代: 仅做整体搜索趋势分析, 不做具体关键词的效率排序; 标注"关键词颗粒度缺失, 词包优化建议降级"
- 缺失: 直客全品牌SOV数据 → 替代: 用聚光后台数据做内部趋势对比, 不做绝对值的行业对标; 标注"SOV数据为代子账号维度, 非品牌全维度"

**生意结果维度 fallback:**
- 缺失: GMV/ROI等生意结果数据 → 替代: 用灵犀AIPS增长和搜索指数变化间接论证生意效果; 标注"缺少生意结果验证, 效果判断基于品牌指标而非生意指标"
- 缺失: 淘宝联盟后链路数据 → 替代: 用蒲公英组件点击量趋势做电商意向的间接判断; 标注"缺少后链路验证, 电商转化能力无法评估"

#### 1.5.3 衍生指标创造规则

**标准指标缺失时, 主动创造替代指标。不把"数据没有"当成"不能分析"。**

衍生指标创造三步:

1. 识别: 确认标准指标因什么数据缺失而无法计算
2. 构建: 用已有数据构造一个替代指标, 替代指标必须与标准指标有理论上的正相关关系
3. 标注: 明确标注"此为衍生指标, 与标准指标的换算关系为X, 判断需结合其他指标交叉验证"

已验证的衍生指标映射表:

| 标准指标 | 缺失数据 | 衍生替代指标 | 计算公式 | 局限性 |
|---------|---------|-------------|---------|-------|
| ROI | GMV | RPV(单次观看价值) | 总成交金额 / 总观看次数 | 不含自然成交, 不含复购 |
| ROI | GMV | 进店转化率 x 客单价估算 | 进店转化率(投放) x 类目均客单价 / CPUV(投放) | 客单价估算误差大 |
| 回搜率 | 搜索行为日志 | 搜索指数变化率 | (投后搜索指数 - 投前搜索指数) / 投前搜索指数 | 不排除自然搜索增长 |
| 人群渗透率 | 全品类人群基数 | TI人群增长速度 | 投放周期内TI新增人数 / 周数 | 不反映相对竞争位置 |
| 转化成本 | 转化事件数据 | 深度互动成本 | 消耗 / 深度互动数(收藏+评论+转发) | 深度互动不等于转化 |
| 内容渗透率 | 类目总阅读量 | 笔记阅读增量率 | (投后周期阅读量 - 投前周期阅读量) / 投前周期阅读量 | 不反映在类目中的份额 |

**衍生指标使用铁律:**
- 每个衍生指标必须在报告中明确标注"衍生指标"和局限性
- 衍生指标的结论强度降一级: 标准指标可下"X好/不好"的结论, 衍生指标只能下"X呈现向好趋势"的结论
- 一个方向的判断至少用两个衍生指标交叉验证, 单个衍生指标不能独立支撑结论

## 2. Orchestration: 执行编排

### 2.1 主流程

```
[STEP 0] 任务接收
  └─ 接收复盘任务, 识别客户名称和项目周期

[STEP 1] 前置问询(Gate 1)
  ├─ 0.1 模板确认
  ├─ 0.2 数据可用性确认
  ├─ 0.3 交付要求确认
  ├─ 0.4 受众适配确认
  └─ 输出: 模板选择结果 + 数据缺口清单 + 受众类型

[STEP 2] 数据采集(Gate 2)
  ├─ 根据 Schema 向各角色拉取数据
  ├─ 策略同事: KPI目标值和实际值
  ├─ PM同事: 蒲公英/商业内容中心数据
  ├─ 媒介同事: 聚光/灵犀/直客数据
  ├─ 竞价同事: 聚光竞价数据(人群包/广告位/计划层级)
  ├─ 对缺失数据标记为 null 并记录原因
  ├─ 执行数据可用性分级(A/B/C/D)
  └─ 输出: 结构化数据集 + 数据可用性等级

[STEP 3] 数据验证(Gate 3)
  ├─ 三确认复查: 口径/周期/粒度是否一致
  ├─ 异常值检测: 是否有明显不合理数据
  ├─ 内部一致性检查: 各数据源之间是否矛盾
  ├─ 若数据可用性为C或D级, 在此步确定 fallback 分析框架
  └─ 输出: 验证通过的数据集 + 标注的疑点 + 选定的分析框架

[STEP 4] 分析执行(Gate 4) - 六个并行分析流
  ├─ 流1: 生意指标分析(GMV/ROI/进店成本/淘宝联盟)
  ├─ 流2: 搜索指标分析(SOV/SOC/搜索指数/回搜率)
  ├─ 流3: 口碑指标分析(CPE/CPC/CPM/CTR/渗透率)
  ├─ 流4: 内容策略分析(笔记效果/优质笔记/评论区/UGC/竞品)
  ├─ 流5: 人群分析(四象限/P-TI对比/画像三维度)
  ├─ 流6: 竞价策略分析(三段论/渗透策略/广告位/人群包)
  ├─ 对数据缺失维度激活对应 fallback 路径(见 1.5.2)
  ├─ 对标准指标缺失场景创建衍生指标(见 1.5.3)
  └─ 输出: 各分析流的结论摘要

[STEP 5] 综合洞察(Gate 5)
  ├─ 对每条分析结论执行五条红线检查(见 4.2)
  ├─ 对突出问题执行五问法深挖根因(见 4.2)
  ├─ 执行三力拆解: 策略力/执行力/管理力 + 客观原因
  ├─ 萃取可复用方法论(策略/执行/管理)
  ├─ 输出失败经验总结(策略修改/SOP优化/人员配置/预警机制)
  ├─ 对每条策略型结论执行三层追问自检(见 4.11)
  └─ 输出: 洞察结果集

[STEP 6] 报告生成(Gate 6)
  ├─ 根据模板选择进入对应分支
  │   ├─ 分支A: 客户模板适配(见 2.2)
  │   └─ 分支B: OnePage GRARI(见 2.3)
  ├─ 填充所有模块内容
  ├─ 写作规范: 每段一个中心论点, 段落间有逻辑衔接, 不用模糊措辞(见 4.13)
  └─ 输出: 初版报告

[STEP 7] 质量审查(Gate 7)
  ├─ 任务来源判断: 是自己写报告还是同事已写好的报告?
  │
  ├─ 分支① 检查模式(同事已写完, 用 data-report-review 查缺补漏)
  │   └─ 详见 2.5.1
  │
  ├─ 分支② 重写模式(同事报告大面积崩坏/结构混乱/逻辑断裂/数据错误过多)
  │   └─ 详见 2.5.2
  │
  ├─ 分支③ 自写报告(自己写报告, 写的过程已内置 review, 仅执行最终检查)
  │   ├─ 数据准确性: 每个关键数字追溯到来源
  │   ├─ 逻辑连贯性: 用三层追问替代简单论证链检查(见 4.11)
  │   ├─ 结论质量: 无过度泛化, 置信标注清晰
  │   ├─ 受众适配: 术语和深度匹配受众
  │   ├─ 表达质量: 逐项检查清晰度/段落焦点/过渡自然度/格式一致性(见 4.13)
  │   └─ 执行双重美德论最终审查(见 4.12)
  └─ 输出: 审查通过的最终报告

[STEP 8] 交付
  └─ 按确认的格式和渠道交付报告
```

### 2.3 分支B: OnePage GRARI 标准流程

当客户没有指定模板时, 使用曼拾 OnePage 基准模板。

```
[B.1] 结构初始化

  │   ├─ G: Goal 目标回顾 (10%)
  │   ├─ R: Result 结果比对 (10%)

[B.2] G模块填充

  ├─ why: 为什么这样设定(策略推演的起点)

[B.3] R模块填充

  ├─ 不足汇总: 未达标的指标和关键事件
  ├─ 是否有新增/减少的目标(执行中的调整)
  └─ 输出: R模块(占全篇10%)

[B.4] A模块填充
  此模块占全篇40%, 是核心分析部分。

  做得好的部分:
  ├─ 列出每个亮点事件
  ├─ 描述对应的关键动作
  ├─ 三力拆解:
  │   ├─ 策略力: 策略上的正确决策是什么
  │   ├─ 执行力: 执行中的哪一步做对了
  │   ├─ 管理力: 管理流程上的优化贡献了什么
  │   └─ 客观原因: 有利的外部条件(大盘向好/竞品缺位等)
  └─ 每个亮点必须回答: 为什么好, 做对了什么, 能不能复制

  做得不好的部分:
  ├─ 列出每个问题事件
  ├─ 描述与预期的差距和对应的动作偏差
  ├─ 三力拆解 + 客观原因:
  │   ├─ 策略力: 策略上哪里判断失误
  │   ├─ 执行力: 执行中的疏漏
  │   ├─ 管理力: 流程或沟通的问题
  │   └─ 客观原因: 目标修改/预算降低/大盘变化/竞品投放/品牌限流

[B.5] R(Review)模块填充
  ├─ 回顾最早设定的目的是否完成
  ├─ 从三个维度解释为什么:
  │   ├─ 资源分配维度: 预算/人力/时间是否合理
  │   ├─ 执行维度: 执行质量是否达到预期

[B.6] I模块填充
  此模块占全篇30%, 是方法论的提炼部分。

  做得好的萃取为可复用方法论:
  ├─ 策略层面: 什么策略框架可复用
  ├─ 执行层面: SOP / 媒介选号 / 内容制作 / 投流 / 品牌广告
  ├─ 管理层面: 机动性 / 跨部门协作 / 反馈机制
  └─ 每个方法论回答: 什么条件下适用, 怎么做, 预期效果

  做得不好的提炼为改进经验:
  ├─ 策略制定修改: 下次怎么定策略
  ├─ 执行SOP优化: 流程上怎么改
  ├─ 人员配置优化: 团队能力结构建议
  ├─ 预警和机动机制: 怎样提前发现问题并快速响应
  └─ 每条经验回答: 什么问题, 根因是什么, 怎么改进
```

### 2.5 data-report-review 两分支

#### 2.5.1 检查模式: 同事已写完报告, 查缺补漏

**适用场景: 同事已经写好了一版报告, 你拿到后做质量检查。这不是检查自己写的东西。**

三步输出:

**第一步: 指出具体问题位置**
- 定位到具体段落/数据/图表
- 每个问题标注: 属于五维中的哪个维度(数据准确性/逻辑连贯性/结论质量/受众适配/表达质量)
- 问题描述简洁, 一句话说清"哪里有问题"

示例:
"[位置: A模块 亮点分析 第2段] [维度: 因果关系] 
因果归因不成立: CPM低不能直接说明人群精准。"

**第二步: 给出修改后的内容**
- 给出替换后的完整段落, 不是修改建议, 是可直接粘贴使用的替换内容
- 修改遵循原报告的风格和格式

示例:
"替换为: 在人群精准度上, 本期CTR达3.5%(行业均值2.0%), 且高CTR伴随高CPM(较行业高15%),
说明封面和标题有效打中了精准人群, 在双列信息流的用户选择逻辑下获得了更多系统曝光。"

**第三步: 标注修改理由**
- 每条修改后加一句理由: 为什么这样改更好
- 理由必须讲清逻辑: 原写法错在哪, 新写法对在哪

示例:
"理由: 原写法犯了因果倒置错误(红线1)。CPM低不一定说明人群精准, 在小红书双列信息流中CPM受CTR正向影响,
精准人群的CTR更高所以CPM更高。改为用CTR+CPM联合判断, 论证更严谨。"

**检查模式执行清单:**
[ ] 五维逐项检查, 每个维度至少扫一遍
[ ] 问题定位具体到段落级
[ ] 每个问题给了三个输出: 位置/替换内容/理由
[ ] 替换内容可直接使用, 不需二次编辑
[ ] 报告结尾附检查摘要: 检查维度/发现问题数/修改后状态

#### 2.5.2 重写模式: 同事报告大面积崩坏

**适用场景: 同事报告存在以下任一情况时触发重写:**
- 结构混乱: GRARI五模块不全或顺序错乱, 客户读不出完整故事
- 逻辑断裂: 多个关键结论的因果链条不成立, 修改量超过全文50%
- 数据错误过多: 数据口径错误/计算错误/对比参照物错误超过全文30%

**重写模式不修补原报告, 而是以原报告提供的数据为基础, 按本 Playbook 的 GRARI 框架重新构建。**

重写模式执行流程:
1. 通读原报告, 提取所有可用的原始数据(剔除错误数据)
2. 与各角色同事确认: 原报告中的原始数据是否准确
3. 按 2.3 OnePage GRARI 标准流程从零构建
4. 对原报告遗漏的维度, 按 fallback 路径处理
5. 重写完成后执行自写报告的质量审查(2.1 Gate 7 分支③)
6. 在交付时标注: "报告基于同事原版数据重新构建, 结构调整和结论优化由[执行人]完成"

**判断阈值:**
- 当检查模式发现的问题超过10处, 或连续3个模块的逻辑都有断裂, 自动切换到重写模式
- 不确定是否触发重写时, 做一次快速评估: 把报告每个模块的核心结论读一遍, 如果有超过一半的结论经不起五条红线检查, 触发重写

## 4. 关键规则速查

### 4.1 KPI 三层分级

| 层级 | 定位 | 典型指标 | 判断标准 |
|------|------|----------|---------|
| P0 北极星 | 与目的最相关的核心结果 | 转化率/CPUV/长效ROI/CPTI/人群渗透率/SOV/C | 直接影响项目是否成功 |
| P1 核心过程 | 反映中间环节效率 | CPE/回搜率 | 过程好结果大概率好 |
| P2 参考 | 浅层辅助判断 | CPC/CTR/CPM | 需要结合深层指标解读 |

### 4.2 结论写作五条红线

每一条分析结论在写入报告前, 必须逐条通过:

红线1: 数据与结论必须有因果关系
- 错误: CPM低说明人群精准
- 正确: 人群精准看CTR和CPC; CPM低只能说明系统竞价竞争力低
- 错误: 进店UV大说明引流高效
- 正确: 引流效率看进店率; 进店UV大只能说明跑量好
- 错误: 进店率和转化率优于大盘说明GMV更高
- 正确: 进店率和转化率优于大盘只能说明性价比高; GMV取决于钱能不能花够花完
- 正确: 论证与电商节奏正相关要放大盘搜索趋势
- 正确: 引流率和转化率高表明点击人群精准+电商价格机制符合需求, 不等于市场竞争力和心智占有率高

红线2: 最小暴露负面原则
- 占比恒定时此消彼长是自然现象, 不需要作为问题提出
- 热度下降优先做外部归因(大盘/季节/竞品动作), 而非直接归因于执行失误

红线3: 每个数据都要有 So-What
- 不仅要说数据是什么, 还要说这意味着什么
- 缺乏归因时要追问: 提升原因是什么, 做对了什么
- 笔记铺量+投流放量所有代理商都能做, 要展示曼拾的差异化动作
- 为什么这个组合最优, 必须深挖到成功机理层面

红线4: 结论落点准确具体
- 用五问法深挖根因, 直到无法再追问为止
- 自检: 如果结论可以套用在另一个项目上, 说明不够具体

红线5: 下一步动作必须回溯到前文分析发现
- 不能凭空杜撰建议
- 每个建议必须能从分析部分找到依据
- 建议要结合行业趋势, 不能脱离市场语境

### 4.3 策略型分析三段式格式

凡是策略型结论(非数据陈列), 使用以下结构:

第一句: 一句话总结结论(最核心的判断)
第二到四句: 通过量化数据论证结论
  - 用了什么对比参照物(大盘/竞品/历史/内部)
  - 什么数据支撑这个结论
  - 如果有多个数据, 从最重要到次要排列
最后一句: 未来建议和方向(基于此结论的下一步)

示例:
"本次投放的核心成功因素是精准人群圈选而非广泛曝光。
对比行业benchmark, 我们的CTR高于均值37%, 进店率达到3.2%(行业均值1.8%), 
而CPM仅为行业均值的82%, 说明在高精准人群前提下系统竞价效率提升。
下一阶段建议将已验证的精准人群包作为种子包, 通过灵犀向量相似拓展至2倍量级后放量。"

### 4.4 三力拆解

每个亮点和问题都从以下四个维度归因:

策略力: 策略层面的决策质量。包括目标设定、KPI选择、人群策略、内容策略、KFS比例分配、竞品判断等。

执行力: 执行层面的落地质量。包括达人筛选、内容质量控制、投放操作、数据监控、优化响应速度等。

管理力: 管理流程的保障质量。包括跨部门协作、反馈时效、SOP执行、风险预警、机动调整能力等。

客观原因: 不受团队控制的外部因素。包括大盘变化/季节因素/竞品投放/平台政策/品牌限流/预算变动/目标修改等。

### 4.5 平台指标关系(已修正)

小红书双列信息流:
- 双列信息流是用户选择逻辑, CPM 受 CTR 影响(不是独立指标)
- CTR 高 = 封面标题打中精准人群 = 系统给更多曝光 = CPM 升高
- CPM 高 + CTR 高 不是成本问题, 是人群精准的正向信号
- 判断逻辑: 高CTR+高CPM = 精准(好); 低CTR+低CPM = 泛流量(需优化)

SEM 卡位:
- CPC 与 SOV/C 成反比
- SOV/C 越高, CPC 越低(品牌词竞争度低时该关系更明显)
- 当品牌词SOV/C不够高时, 需加大搜索预算卡位

### 4.6 回搜率定义与计算

- 定义: 用户看过广告流量笔记后48小时内搜索特定词的比率
- 计算: 点击广告后48小时内搜索过回搜词的用户去重人数 / 点击广告用户去重人数
- 维度: by 笔记维度, 不是 by 关键词维度
- 判断: 无行业均值默认0.5%为参考线; 低于0.5%说明种草深度不足; 高于1%说明种草效果好
- 证明: 回搜率是证明种草程度的直接指标

### 4.7 竞品选定原则

竞品选定优先级:
1. 客户指定的死对头品牌
2. 同赛道中花钱最多的品牌(资源对标)
3. 产品类似且受众重叠的品牌(策略对标)
4. 优质赛道品牌(方法论对标)

至少选2个竞品, 最多4个。

### 4.8 分析中的对比参照物

每个数据分析必须有对比参照物, 四选一或组合:
1. 对比大盘(行业benchmark)
2. 对比竞品(同赛道品牌)
3. 对比本品历史(上一个投放周期/去年同期)
4. 对比本品当下内部(拆分内容方向/人群包/词包看内部差异)

### 4.9 内容分析中的好坏定义

不以爆文定义好坏, 以客户目标定义:
- 如果客户目标是回搜, 则回搜率高的笔记是好的
- 如果客户目标是进店成本, 则进店成本低的笔记是好的
- 如果客户目标是站外转化率, 则转化率高的笔记是好的
- 以客户P0目标为X轴或Y轴的判定标准

### 4.10 AI 化表达禁令

报告中禁止出现:
- emoji 标记类符号: 禁止所有 emoji
- 装饰性中文引号: 「」『』
- 装饰性破折号: ——(作为分隔符使用时用短横线 - 替代)
- 装饰性星号: **加粗内容**(如需强调用文字本身的逻辑力量)

允许使用:
- 数字序号: 1. 2. 3. 或 (1) (2) (3)
- 表格和列表结构
- 短横线作为列表标记或连接符

### 4.11 三层追问规范(greko 方法论)

**三层追问是 greko 方法论在复盘场景的落地: 苏格拉底追问法(数据真实性)/柏拉图形式论(本质洞察)/亚里士多德逻辑验证(逻辑严密性)。**

每一条策略型结论在写入报告时必须内置三层追问。

#### 4.11.1 书写规范层: 结论内置三层追问

写所有策略型结论时, 必须过下面三层, 确保结论经得起推敲:

**苏格拉底层(数据真实性追问):**
问自己三个问题:
1. 这个数据的计算口径是什么? 有没有口径陷阱?
2. 对比参照物选对了吗? 换了参照物结论还成立吗?
3. 数据的表面含义之外, 有没有被数据表象误导?

常见的数据表面假设陷阱:
- "CPM降低了, 所以成本优化了" -- 表层假设; 实际上CPM降低可能只是因为流量变泛了
- "搜索指数上升了, 所以种草有效" -- 表层假设; 需要排除自然搜索增长和外部事件影响
- "转化率提升了, 所以内容优化到位了" -- 表层假设; 可能只是因为人群精准了, 不是内容本身的功劳

**柏拉图层(本质矛盾追问):**
问自己三个问题:
1. 这组数据放在一起反映的核心矛盾是什么?
2. 如果去掉所有数字, 这个问题的本质是什么?
3. 数据背后代表的东西是什么? (不只看数据本身, 看数据所指向的底层规律)

示例:
- 高曝光+低互动 = 内容触达了人但没有打动人。本质矛盾: 内容与受众的需求不匹配。
- 高互动+低转化 = 内容好但购买动机弱。本质矛盾: 种草深度够但转化路径断裂(价格/渠道/时机)。
- 搜索指数升+进店率降 = 品牌被记住了但购买决策在别处发生了。本质矛盾: 电商落地页或价格机制有问题。

**亚里士多德层(逻辑验证追问):**
问自己三个问题:
1. 这个结论有没有反例? 有哪个指标跟这个结论相反?
2. 换一个时间周期(比如只看前两周 vs 后两周), 这个结论还成立吗?
3. 换一个人群包(比如只看女性 vs 只看男性), 这个结论还成立吗?

示例:
- "本期CPE较上期优化25%" -- 拆分到不同笔记方向看, 是全面优化还是某个方向拉动的均值? 如果是后者, 结论应修正为"场景化内容方向的CPE优化驱动了整体均值下降, 而非所有方向均有改善"。
- "搜索SOV达到45%, 心智占位良好" -- 拆分到品牌词和品类词, 品牌词SOV可能60%但品类词只有15%。结论应修正为"品牌词心智强但品类词心智弱"。

#### 4.11.2 质检 review 链层: 用三层追问替代论证链检查

在 data-report-review 的逻辑连贯性检查(第五维中的第二维)中, 用三层追问替代简单的"论证链是否完整":

不再问"这个结论的论证链完整吗?" -- 这个问法太模糊, 答了跟没答一样。

改为三层追问:
1. 苏格拉底层: 这个结论依赖的数据前提是否成立? 数据的计算口径、采集周期、对比参照物是否可靠?
2. 柏拉图层: 数据的本质矛盾是否被识别出来了? 结论是否触及了数据背后的底层规律, 还是停留在数据描述?
3. 亚里士多德层: 反例是否被排除了? 有没有指标跟结论方向相反? 拆分不同子维度后结论是否仍然成立?

#### 4.11.3 Prompt 要求层: 三段式写完追加三层自问

每次写完三段式策略分析后, 不是要求把三个问题的答案写进报告, 而是在心智层面过一遍以下自检:

- 苏格拉底自问: 我的数据计算口径对吗? 对比参照物可靠吗? 有没有被数据表象误导?
- 柏拉图自问: 这组数据的本质矛盾是什么? 去掉数字后问题的本质是什么?
- 亚里士多德自问: 有反例吗? 换时间周期或人群包结论还成立吗?

这三个问题不写入报告正文, 是写结论时的内部自检机制。但质检 review 链中(4.11.2)需要显式追问并记录结果。

### 4.12 双重美德论

**双重美德论是 creative-performance-diagnoser2 在报告质量上的核心方法论: 报告正文用亚里士多德美德论(如实), review 建议层用康德义务论(如果...则...)。**

#### 4.12.1 报告正文: 亚里士多德美德论

**原则: 如实地呈现数据全貌。不假装有数据, 不在没有证据时给确信。数据够就是够, 不够就是不够。**

三条操作规则:

规则1: 每个数据维度标注置信度
- 有完整数据支撑的结论: 标注"X数据支持该结论" -- 用肯定语气
- 有部分数据支撑但缺少关键验证的: 标注"此处缺少Y数据, X的结论强度相应降级" -- 用保留语气
- 仅有间接数据支撑的: 标注"基于Z间接推断, 建议补充W数据后做二次验证" -- 用推测语气

规则2: 缺失数据维度必须列在报告里
- 在报告的分析部分末尾, 单列一段"本次分析的数据局限":
- 列出本次无法分析的维度及其原因(不是"没拿到数据"而是"缺少X数据, 导致Y分析无法进行")
- 对每个缺失维度标注: 如果补充了该数据, 可以回答什么问题
- 示例: "本次缺少分人群包消耗和转化数据, 因此无法对人群圈选的精细化效果做量化评估。建议客户补充聚光后台的人群包维度报表后, 可回答: (1)哪个人群包的单次互动成本最低; (2)哪个人群包的TI转化效率最高; (3)高消耗低效人群包的具体特征。"

规则3: 不把推测当成结论
- 缺少直接数据时, 不用"说明""证明""表明"等确定性动词
- 用"呈现...趋势""数据指向...方向""初步判断"等保留性措辞
- 每个用保留性措辞的结论, 后面必须跟一句"建议补充X数据验证"

#### 4.12.2 Review 建议层: 康德义务论

**原则: 正文之外单独出一段, 标注为"review层建议", 给内部策略团队看优化路径。正文内容不做假设, review 层专门做假设。**

操作规则:
- 标注格式: 以"[review层建议]"为段落起始标识
- 内容格式: "如果后续能补充XX数据, 建议验证以下假设: YYY"
- 位置: 放在报告末尾或分析章节末尾, 与正文明确区隔
- 受众: 仅给曼拾内部策略团队, 不给客户看
- 每条建议格式: 假设描述 + 验证方法 + 如果成立则意味着什么

示例:
"[review层建议]
如果后续能补充分人群包的数据, 建议验证以下假设:
1. 假设: 竞品互动人群的CPE低于泛美妆兴趣人群, 且TI转化率高于泛人群
   验证: 对比B组(竞品互动)和A组(泛美妆)的CPE和TI转化率差异
   如果成立: 竞品拦截策略可上升为TA人群圈选的核心策略, 后续投放以竞品人群为第一优先级
2. 假设: 视频流内容虽然互动率高但进店率低于信息流, 视频内容更适合种草而非直接转化
   验证: 拆分视频流和信息流在TI人群增长中的贡献度(TI新增数而非进店数)
   如果成立: 视频流预算定位从"放量转化"调整为"深度种草", 信息流作为主转化阵地
3. 假设: 搜索SOV未达标的核心原因是品类词出价低而非预算总量不足
   验证: 对比行业竞价环境(品类词的竞争度和CPC趋势)与本品牌品类词的出价水平
   如果成立: 不是"加搜索预算", 而是"提高品类词出价系数, 配合否定词优化降低无效搜索消耗""

**review 层建议与正文的分隔规则:**
- review 层不进入客户报告正文
- 如果是内部复盘文档, review 层放在每个分析维度的末尾, 用分隔线或标记区隔
- review 层的假设如果后续被验证, 下次复盘时升级为正文中的确定性结论

### 4.13 表达质量规范

**表达质量是报告专业度的基础。内容再好, 表达混乱, 客户的信任度会打折扣。**

#### 4.13.1 书写时强制遵守

三条强制规则:

规则1: 每段一个中心论点
- 一个段落只讲一件事
- 段落的第一句是中心论点, 后文展开论证
- 不要把多个论点挤在一个段落里
- 反例(违反): "本期CPE 1.2元较上期下降15%, CTR提升至3.5%, 搜索指数增长320%, 整体投放效果超出预期。" -- 四件事挤在一段, 读者不知道你想说什么。
- 正例: "本期互动效率显著提升。CPE降至1.2元(较上期-15%), 根因在场景化封面驱动CTR从2.1%提升至3.5%, 互动量随之放大。搜索心智同步建立, 搜索指数较投前提升320%。"

规则2: 段落间有逻辑衔接
- 上一段的落点和下一段的起点有承接关系
- 三种基本衔接方式:
  - 因果: "以上数据解释了互动效率的提升, 接下来看这些互动是否转化为了生意结果。"
  - 递进: "场景化内容解决了触达效率, 但触达之后的转化需要价格和渠道的配合。"
  - 转折: "搜索指数整体上升, 但拆分品类词和品牌词后发现, 品类词的心智建设明显滞后。"
- 如果两个段落之间没有任何逻辑关系, 说明你需要重新组织内容顺序

规则3: 不用模糊措辞
- 禁止词列表: 应该、大概、可能、看起来、似乎、好像、差不多、也许
- 替换原则:
  - "CPM应该算是比较低了" → "CPM为28元, 低于行业均值35元(低20%)"
  - "大概优化了15%左右" → "CPE从2.3元降至1.95元, 优化幅度15%"
  - "这个方向看起来效果不错" → "场景化内容方向CTR达3.5%, 较测评方向(2.1%)高67%"
- 如果无法给出精确数字, 不要模糊措辞, 而是标注"该维度缺少精确数据, 不在此处做定量判断"

#### 4.13.2 检查时逐项对照(data-report-review 第五维)

检查报告表达质量时, 逐项扫描以下四个子维度:

**子维度1: 表达清晰度**
[ ] 每个句子是否有明确的主谓宾?
[ ] 是否有连续3个以上长句(超过40字)? 如有, 拆短。
[ ] 是否有专业术语未解释(取决于受众类型)?
[ ] 是否有指代不明("这个""那个""其")?

**子维度2: 段落焦点**
[ ] 每个段落是否有明确的中心句?
[ ] 段落内其他句子是否都在支撑中心句?
[ ] 是否有段落包含了互不相关的两个观点?
[ ] 段落长度是否合理(不超过5-6行为宜)?

**子维度3: 过渡自然度**
[ ] 段落间是否存在逻辑跳跃(上一段和下一段完全没关系)?
[ ] 关键结论的转场是否有衔接句?
[ ] 从一个模块过渡到另一个模块是否有总括或预告?

**子维度4: 格式一致性**
[ ] 同层级标题的格式是否统一?
[ ] 数字的呈现格式是否一致(百分比统一为x%还是x.x%? 金额单位统一?)
[ ] 表格格式是否一致(对齐方式/表头样式)?
[ ] 标注和脚注的格式是否统一?
