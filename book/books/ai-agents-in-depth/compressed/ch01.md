# 第1章 AI Agent 入门

## 本章核心论题

拆解核心公式 Agent = LLM + 上下文 + 工具。核心判断：模型能力商品化，竞争优势在 Harness 工程——上下文管理、工具接口、约束、验证与纠正。

## 关键论点与框架

### 1. Agent 的本质公式：Agent = LLM + 上下文 + 工具

**论点**：Agent 由 LLM（大脑）、上下文（眼睛）、工具（手脚）构成——三者缺一则退化为无行动力聊天机器人、盲目循环执行器或文字生成器。

**论证与机理**：三层抽象映射到策略/观察空间/动作空间。Harness 将观察转为上下文、行动转为工具调用。消融实验：去工具定义→丧失行动力；去工具结果→无限循环；去思考→决策矛盾；去历史→重复步骤。

**出处锚点**：§1.1，表 1-1，实验 1-1。

### 2. 扩展观察空间与动作空间是最主要的能力杠杆

**论点**：模型固定时，提升 Agent 任务表现最主要的手段是重新定义观察与动作空间——许多看似需"更聪明模型"的问题只是接口问题。

**论证与机理**：将任务数据纳入上下文或封装为工具，不可解就可能可解。演进本质是从"等模型变强"到"设计更好接口"。Manus 取三类 Agent 空间之并集；OpenClaw 通过 Gateway 让分散文件进入同一观察空间。

**出处锚点**：§1.1.1。

### 3. ReAct 循环：思考→行动→观察的迭代闭环

**论点**：Agent 核心执行机制是 ReAct 循环——思考→行动→观察→再思考，反复直到完成。上下文 = 静态前缀（系统提示词+工具定义）+ 轨迹（动态消息历史）。

**论证与机理**：Model 决定下一步，Harness 组装校验，Environment 产生状态变化。Kimi K3 可连续 200-300 次调用保持一致性；GPT-5.6 引入意图澄清弥合预期差距。

**出处锚点**：§1.1.5，图 1-4，实验 1-2、1-3。

### 4. Harness 工程与 Model–Harness 边界结构

**论点**：Agent = Model + Harness，模型让 Agent"能做事"，Harness 让 Agent"不做错事"。模型能力越强，Harness 反而越关键。

**论证与机理**：Harness 是模型之外的运行与治理层，约束、验证、纠正围绕上下文和工具构建。作者立场"方向认同，节奏务实"。LangChain Terminal Bench 2.0 从 52.8%→66.5%，改的是 Harness 而非模型。

**出处锚点**：§1.2，图 1-1。

### 5. 从提示工程到 Loop 工程的范式演进（五层包含关系）

**论点**：AI 应用工程经历五波范式——提示工程→上下文工程→Harness 工程→Loop 工程→Graph 工程——层层包含而非替代。模型趋同时，竞争优势转移到模型之外的工程实践。

**出处锚点**：§1.2.1。

### 6. 编排模式的选择原则：保持简单，从工作流到自主 Agent

**论点**：遵循"先优化单次 LLM 调用→再考虑工作流→最后才引入自主 Agent"。Agent 系统以延迟和成本换任务性能，需谨慎权衡。

**论证与机理**：工作流代码强制规则但缺乏变通；自主 Agent 根据反馈实时决策但成本更高。订机票——工作流四节点确保"付款前不能预订"；自主模式由 Agent 自行询问偏好。

**出处锚点**：§1.2.5，图 1-6、1-7。

### 7. 护栏分层防御：输入侧、执行侧、输出侧三重防护

**论点**：护栏是 Harness 约束、验证与纠正的核心手段，分三层构建韧性系统。评估需双向测试。

**论证与机理**：输入侧前置拦截，执行侧按可逆性/权限/财务影响评级，输出侧 PII 过滤。区分越狱与提示注入。Anthropic Constitutional Classifiers 以自然语言宪法生成合成数据训练分类器，两级筛查。

**出处锚点**：§1.2.6。

### 8. 模型选型的四个关键维度

**论点**：选对模型往往比优化提示词更有效。四维度——能力（在自身任务评估，不止看排行榜）、策略边界、思考能力（大多数 Agent 任务需 reasoning）、辅助特性（输出速度决定端到端延迟，多模态是硬要求）。

**论证与机理**：闭源领先但受限 API；开源滞后约 6 个月但成本低。同一任务不同入口可能结果不同——须在真实任务上测试。

**出处锚点**：§1.2.4。

## 原则清单

1. **保持简单优先**：直接 API 调用优于复杂框架，多一层抽象多一个盲区。
2. **先优化单次 LLM 调用**：能用提示词和示例解决的，不引入 Agent 系统。
3. **扩展接口优先于升级模型**：先检查观察空间和工具是否覆盖任务需求。
4. **工具设计防呆（Poka-yoke）**：从 Agent 视角设计 ACI，让误用在设计层面就不可能。
5. **通用工具探索，专用工具约束高风险**：代码解释器需沙盒；支付、删数据封装为参数明确、可审计的专用工具。
6. **约束、验证与纠正是架构内置，非上线补丁**：安全贯穿模型、上下文、工具、协作、社会五层面。
7. **建立评估机制才可能有进步**：评估让迭代不再依赖直觉（第六章展开）。
8. **人工干预是"优雅移交"**：超失败阈值或高风险时，控制权和上下文一并移交。
9. **护栏评估需双向测试**：既测拦截率也测通过率，避免误拒绝的隐藏成本。
10. **在名词流行之前就实践**：动力来自对 Agent 能力上限有极高要求的真实业务。

## 失败模式与反例

1. **消融实验四类退化**（§1.1.4）：去工具定义→丧失行动力；去工具结果→盲执行循环；去思考→决策矛盾；去历史→失忆重复。
2. **自主 Agent 死循环**（§1.2.5.2）：无明确停止条件时易死循环，需熔断器自动停试、移交人工。
3. **误拒绝——护栏隐藏成本**（§1.2.6）：降低危险放行率的同时可能拒绝合法但形式敏感的任务。
4. **框架过度抽象**（§1.2.3）：Agent 失败非因模型不够强，而是框架增加不必要抽象层。
5. **模型"策略边界"陷阱**（§1.2.4）：基准具备能力≠产品允许调用，不同入口结果可能不同。
6. **"过早声明完成"**（§1.2.7）：长时运行中模型倾向过早声称完成，需结构化干预。

## 关键术语表

| 概念 | 一句话定义 |
|------|------------|
| **Agent** | LLM + 上下文 + 工具的智能系统，自主规划、调用工具、按反馈调整 |
| **上下文** | 每决策点收到的全部信息：系统提示词、工具定义、对话历史、工具结果 |
| **工具** | Agent 感知或改变外部世界的接口，含定义、调用协议和适配器 |
| **ReAct 循环** | "思考→行动→观察→再思考"的迭代机制 |
| **轨迹（Trajectory）** | Agent 执行过程中不断积累的消息历史 |
| **Harness** | 模型之外的运行与治理层：上下文管理、工具接口、约束、验证、纠正 |
| **约束/验证/纠正** | Harness 三层保障：设边界→判对错→自动修正或回退 |
| **工作流（Workflow）** | 预定义代码路径编排 LLM 和工具的确定性执行模式 |
| **自主 Agent** | 执行路径根据环境反馈实时决定的动态执行模式 |
| **护栏（Guardrails）** | 分层防御机制：输入侧、执行侧、输出侧 |
| **模型即 Agent** | 模型通过后训练将工具调用策略内化为原生能力 |
| **Loop/Graph 工程** | 跨轮次持续运转；将循环和审批组织为显式执行图 |
| **提示注入** | 通过外部数据向上下文嵌入恶意指令，间接操纵模型 |
| **越狱（Jailbreak）** | 用户试图绕过模型安全限制 |
| **ACI** | 从 Agent 视角设计的工具接口（Agent-Computer Interface） |
| **熔断器** | 连续错误时自动停止重试，防系统级崩溃 |
| **消融实验** | 逐步移除组件以判断每个组件贡献的诊断性实验 |
| **思考/推理** | 术语约定：reasoning=思考（推导），inference=推理（部署运行） |
