## 修正：完整Skills使用清单（覆盖整个研报生产流程）

### 我们自己的Skills（方法论+工具层）

1. **data-charts-visualization** → ECharts图表生成。4张品牌对比图（天猫爆款、京东爆款、斤价、回头客），通过CLI `areslabs-data-charts` 传入带品牌名的xAxis data，horizontal bar layout，800x420/380

2. **market-research-pro** → 市场研究框架。竞品五维扫描的整体方法论骨架（市场/渠道→品牌力→产品→趋势→人群这五个维度的选择逻辑来自市场研究方法论），行业格局分析、竞争模式归纳

3. **product-strategy** → 产品策略分析框架。品牌产品力板块的分析逻辑——爆款识别、SKU矩阵、价格带覆盖、猫狗分开分析，以及"品类创新者"vs"系统飞轮者"等竞争模式的命名和判断

4. **service-design-core** → 服务设计方法论。消费者洞察和触点分析体现在趋势与人群板块——用户画像刻画、购买决策路径、品牌接触点（天猫/京东/抖音/线下各渠道的不同角色和消费者行为差异）

5. **research-report-skill** → 研究报告结构规范。六章+附录的整体架构（核心发现→行业格局→竞品扫描→本品深度→差距对比→切入点），以及结论先行的咨询报告写作方法论

6. **browser-automation** / **browser-automation-stealth** → 电商平台数据采集。模拟真人操作采集天猫/京东店铺数据，防止反爬检测

7. **peekaboo** → macOS UI自动化（间接用于浏览器控制辅助）

### 模型层

8. **DeepSeek V4 Pro** → 全部分析内容写作。第三章竞品五维扫描正文、趋势与人群补齐、所有需要结构性思考的判断

9. **GLM 5V Turbo** → 截图审查验证。图表标签正确性检查、文档导出效果验证

10. **GLM 5.2** → docx文档生成脚本（API已配置但余额不足，本次未进入实际生产。原计划用于python-docx/lxml脚本生成）

### 脚本/工具层（非skill，但构成生产链关键环节）

11. **Python脚本（python-docx + lxml + zipfile）** → Word文档操作引擎。三步法：python-docx定位章节边界 → lxml删除+创建+插入 → zipfile重建。这是本次从V10.1到V12的文档修改核心技术栈。

### Skills之间的协同关系

- market-research-pro 定义"分析什么"（五维框架）
- product-strategy 和 service-design-core 定义"怎么分析"（产品方法论+消费者方法论）
- DeepSeek V4 Pro 执行"写出来"（输出分析文字）
- data-charts-visualization 执行"画出来"（输出可视化图表）
- browser-automation 执行"采回来"（输入原始数据）
- python-docx + lxml 执行"装进去"（把所有产出嵌入Word文档）
- GLM 5V Turbo 执行"检查对"（验证输出正确性）
- research-report-skill 定义"整体长什么样"（六章结构+写作规范）

## 附加：本次生产中暴露的Skills缺口

1. **docx自动化skill缺失**：目前没有成熟的docx操作skill，每次都需要手写python-docx+lxml脚本，效率低且容易出错。可考虑固化为skill。

2. **图表→文档自动化管道缺失**：图表生成和文档嵌入是两段独立流程，中间没有自动化连接。目前需要手动复制PNG路径、重新跑文档生成脚本。

3. **电商数据采集标准化缺失**：天猫/京东/抖音的数据采集每次都靠浏览器手动浏览，没有标准化的数据提取模板。
