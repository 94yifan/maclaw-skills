## 2026-07-14 深度读书笔记标准确认（本书分身核心工作流程）

### book-deep-reading Skill 框架（已建提案待固化）

#### 第一步：判断书籍类型
拿到数据后先判断书是什么类型，不同类型用不同内容结构：
- 方法论/操作手册（如《学会提问》）→ 核心流程Step + 概念详解
- 故事/传记 → 关键事件 + 人物分析 + 经验提炼
- 哲学/认知科学 → 核心概念 + 知识体系 + 现实关联
- 商业/案例 → 核心论点 + 案例详解 + 可复制模式
- 文学/社会观察 → 核心主题 + 关键情节分析 + 现实映射

#### 内容标准（逸凡确认的量化要求）
- **总字数**：原书约1/10，8000-10000字
- **核心内容**：核心框架流程 + 重要概念详解——占最大篇幅
- **双源案例**：每个概念配内部案例（书中）+ 外部案例（真实事件）
- **案例4要素**：对象介绍（≥40字，说清「是什么」）→ 具体行为/事件（≥50字）→ 分析与关联（≥60字）→ 学习价值（≥30字）
- **外部案例**：必须真实事件，近5年，不确定的写「待验证」绝不编造
- **金句**：8-10条，不标注划线人数，每条附≥60字思考价值分析
- **延伸思考**：费曼学习法提问3-5个（带具体场景）+ 生活/工作实践设计4-5个（可操作）
- **输出**：直接发 .md 文件到飞书群，不搞飞书文档

#### 思维导图标准
- **结构**：树状（自上而下），不是放射状
- **节点**：完整句子（10-20字），不堆关键词
- **排版**：文字清晰无重叠，间距gap≥8px，浅色背景+圆角卡片+色彩分区
- **技术**：纯CSS flex + SVG + 原生JS，无外部依赖
- **交互**：滚轮缩放 + 拖拽平移
- **必须预览**：截图先本地查看再发

#### 模型使用
- 默认Flash，读书分析不需要Pro

#### 踩坑（必须记住）
1. 数据不能编造——事实要可溯源，不确定写「待验证」
2. 数量与书中一致——书中9种谬误就写9种，不多不少
3. 不能从头重写丢失旧内容——以确认过的版本为底本做增量修改
4. 思维导图先出结构骨架再填充——不要直接写完整HTML
5. 输出前必须预览——截图看好再发
6. 不能创建飞书文档——直接发md文件

**核心洞见：** 这是"把相关当因果"的变体——观察到间隔稳定就假设时间驱动周期，但真实机制可能是事件驱动的（读书进度→产出）。**对逸凡的产出，事件触发（读书进度）是比时间触发（日历节律）更可信的机制假设**——读书是进度驱动的活动，日历不驱动阅读。

**可复用框架：** 任何周期性观察，先问"时间是原因，还是只是伴随变量？"。驱动变量是日历（周期事件）还是事件（进度事件）？识别错驱动变量会导致在错误的时间点做无用的准备。
