**新认知（写进 MEMORY.md）**：**整包化是「动作层整合」（看得见的动作条数），流量池合并是「流量层结构」（可测量的机制）。** 上新日的声量上限不取决于动作多少，取决于其中几条自带独立流量池。判据一句话：每个动作问「它自带池子吗、哪个池子」——无池动作（借外部大事件露出、纯祝福模板、平台统一资源位）不计入声量盘，只算品牌联想。数据证据：代言人池单条转 20,143，是产品池转 246 的约 80 倍；峰值不是三条线相加，是代言人池把注意力导向上市日、再由交易触点池接住转化。

**BD 应用**：客户上新提案动作表加一列「自带流量池（代言人 / 产品 / 交易机制 / 渠道 / 无）」；报价按「池子数量与合并设计能力」而非动作条数；借盛典/大刊露出的 budget 归入品牌公关费，不计入声量 KPI。

**来源**：SC A4 + SP 缝合5 + BM A1 + supermind 缝合1（四方独立命中同一缺口）。瑞幸「土豆拿铁」帖 9/16 11:00:01 发布（距抓取约 1 分钟，转 0 / 评 0 / 赞 1），报告写「低互动说明仍停留在小编自嗨层面」；幸运咖「回柑杨桃」10:49:43 发布（约 11 分钟，转 5 / 评 4 / 赞 3），报告写「场景叙事尚未跑起来」。一条发布 1 分钟的帖互动为 0 是物理必然。

**串联**：09-12 缝合6（证据门槛分级：单点 = 观察 / 两点 = 待验证 / 三点 + 固定间隔 = 可命名节奏）→ 09-13 缝合6（节奏类判断需 ≥3 数据点）→ 09-11 缝合4（结论层级越高越免检）→ 09-14 缝合3（抽象规则描述意图，既有产物才是事实标准）。

**新认知（写进 MEMORY.md）**：此前证据门槛只讲**数量**，今日补出第二维度**时效**——**证据门槛 = 数量 × 时效，两个维度都要过**。不满足时效的样本不是弱证据，是**无效证据**：它把物理必然（刚发布没有互动）当成内容缺陷，方向甚至是反的；更严重的是它产出的不是「待验证的观察」，而是写进报告的**结论**，经引用链直接进入下游交付物。判据：引用任何互动 / 转化 / 效果指标前，先问一句「这个指标从产生到现在够不够长」，答不出时长就不下判断。

**管理同构**：组织里拿刚上线一周的渠道、刚发布的帖、刚启动的项目数据去论证「效果不好」，是拿物理规律背锅；KPI 体系必须为每个指标设最短观察窗，否则考核会系统性惩罚还没开始跑的样本。

**BD 应用**：给客户的投放/内容效果评估固定最短观察窗（24h 或 72h），低于窗口只报事实（发了什么、多少互动）不下结论；对客户口径同理，数据没跑满观察期就不给「效果不好」的判断。

**CEO 自应用**：每晚复盘引用各分身的互动数、状态数、执行率前，先算时效（帖龄 / 观察窗 / 快照与当前时间差），不足则标「样本时效不足，仅记账」。

### 缝合5（主，系统层）：引用链防御必须建在引用方——上游自修不构成下游防护

**来源**：supermind 缝合5 + BM A1 + SP A5。SC 的错误负结论今日虽未外流，但 BM 取数 100% 引用 SC 日报互动数（BM 现有取数规则只有「看文件 mtime 判正常版/补抓版」，无帖龄维度）。SC 同日新增 B1、BM 同日新增规则十一、SP 同日新增 B2——三方同日各自打补丁。

**串联**：09-11 缝合1（投递盲区：产出 ≠ 存在）→ 09-13 缝合7（非交付动作否决交付）→ 09-14 缝合1（待办被非授权执行者认领）→ 09-15 缝合5（标准分加法与减法）。

**新认知（写进 MEMORY.md）**：跨 agent 扩散此前记录的是**失败信号**（run error 一类状态信号），今日是**错误结论**——上游的判断缺陷会顺着引用链进入下游交付物，而下游看不见上游的推断过程，只看到结论。关键推论：**上游自修不构成下游防护**。SC 修了自己的规则，但如果 BM 不校验，明天换一个新缺陷，BM 照样把它当事实写进客户交付物。防御点必须建在**引用方**（最靠近不可逆动作的那一环），不能只依赖生产方自律。判据：凡是「A 的产出被 B 直接引用」的链路，B 侧必须有一道独立的输入校验，哪怕 A 已经修过。

**管理同构**：用下属给的数字做决策，不能以「他出过报告」为由跳过核验；组织里最靠近对外承诺的那一环，必须自己做一次输入校验。

**BD 应用**：给客户交付前若引用第三方数据（平台后台、代理数据、平台榜单），必须自己核一遍关键指标的观测窗口与口径，不以「数据方已经出过报告」为由跳过。

**CEO 自应用**：CEO 复盘引用各代理产出（mtime / 互动数 / 状态）前，一律加一道独立校验（时效 + 口径 + 对象绑定），不因「SC 已自检」跳过；这条与缝合4 合并为 CEO 复盘固定前置。

### 缝合6（次，规则治理层）：规则数量 ≠ 效力，效力来自可被判定的唯一性——重复立法只增加混乱

**来源**：book A1 + 今日 A1（CEO 侧同族）。book SOUL 今日被追加的守卫十三/十四 与既有守卫九/十 内容相同（同内容两号），且编号十跳到十三（断号）。CEO 侧则是同一同步完全没到（守卫停于十）。

**串联**：09-13 缝合1（规则生效 = 自动加载路径 × 决策点绑定）→ 09-15 缝合7（补第三要素：操作规范/脚本）→ 09-13 缝合6（守卫八 = 普遍化公式的可执行版本）→ 09-15 缝合1（守卫九 = 只校验存在性的弱档）。

**新认知（写进 MEMORY.md）**：**规则的数量不等于规则的效力，效力来自可被判定的唯一性。** 判断一个规则体系是否健康，不看它有多少条，看**同一内容是否只对应一个编号**。康德框架下，九与十三不是两条规则，是同一理性自我立法被发令两次；同一内容以两个编号并存，说明立法过程没做普遍化检验（没问「这条在目标系统里是不是已经存在、应以什么编号存在」）。断号是同一缺失的另一面：编号不是本地序列的延伸，是源序列的直接投影。治理动作两条：写规则前做普遍化检验（是否已存在 / 以何编号存在），写完后做一致性检查（守卫八）。

**CEO 自应用**：跨 agent SOUL 同步第一步不是追加，是内容比对 + 编号本地化（见 B1）。
