### 错误1：CDP 9333 上午不可用，下午恢复，未确认触发源 ⭐⭐

**现象：**
- 10:05 AM cron 触发，状态为 `error`（已在 Dreaming Noon 记录）
- 18:19 - 有人运行了脚本 v6.mjs，成功爬取 19/19 品牌，报告 36KB

- **飞书群未收到通知** — v6.mjs 没有发飞书群的逻辑

**根因分析：**
下午 18:19 CDP 9333 已恢复可用。问题：谁在 18:19 触发了脚本？
- cron 任务显示 `idle`（未触发），所以不是 cron
- 最可能：main session 或某个 subagent 手动运行了脚本
- **说明**：脚本本身可以成功连接 9333，但上午脚本没有重试机制就放弃了

**缺失的修复（从4月30日延续，仍未完成）：**
v6.mjs 仍然没有飞书发群逻辑。报告躺在文件里，用户看不到。

**具体代码修复（v7需包含）：**
在 `main()` 函数生成报告后，添加飞书发群：

```javascript
// 报告已写入 /tmp/tea-report-${today}.md
// 现在发飞书群
const reportContent = fs.readFileSync(`/tmp/tea-report-${today}.md`, 'utf8');
const feishuApi = 'https://open.feishu.cn/open-apis/bot/v2/hook/群机器人URL';
await fetch(feishuApi, {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({
    msg_type: 'text',
    content: { text: `📊 茶饮日报 ${today}\n\n${reportContent.slice(0, 4000)}` }
  })
});
```

**预防：**
脚本必须包含飞书发群逻辑，否则每次都要手动发。

### 错误2：脚本版本管理混乱（系统性风险）

**现象：**
目前 `/tmp/` 下有多个脚本版本：
- `tea-brand-crawler.mjs` (旧)
- `tea-brand-crawler-v2.mjs` (旧)
- `tea-brand-crawler-v3.mjs` (旧)
- `tea-crawler-v4.mjs` ~ `tea-crawler-v6.mjs` (今日)
- `tea-brand-crawler-18800.mjs` (仅 18800 端口测试用)

**根因：**
每次修改都创建新文件，cron 触发的脚本路径不明确，导致：
- 不知道哪个是"正选"脚本
- 不同版本在不同时间运行，state 文件混乱

**修复：**
- **统一使用一个脚本路径**：`/tmp/tea-crawler.mjs`（只有一个）
- 每次修改都在同一文件上改，用 `cp /tmp/tea-crawler.mjs /tmp/tea-crawler.bak.$(date+%Y%m%d%H%M%S)` 做备份
- cron 触发固定的脚本路径

### 错误4：上午 cron 失败后无告警

**现象：**
10:05 AM cron 失败（CDP 9333 不可用），没有任何通知。

**根因：**
cron 的 announce delivery 在脚本崩溃时不触发（4月30日已知问题）。

**修复：**
在 main() 入口处加 try-catch，CDP 连接失败时先发飞书群告警再退出。
