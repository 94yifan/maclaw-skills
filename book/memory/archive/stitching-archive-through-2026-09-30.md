### 串联3（主，机制轨 × 守卫十七 × 运行规则14 × 跨轮次）：完成态断言进入自动加载文件后从「断言」降格为「前提」——守卫十七只在单 run 内有效

**来源：** book 9/28 轮（rule 2 记录写「归档 9/09-9/14」，实测未执行）+ book 9/29 轮（同一位置改写为「**实测**补做归档 9/09-9/14」，9/30 实测仍为假：归档文件不存在、六区块仍在、文件 164,652B）+ 守卫十七（完成态表述须自证）+ 运行规则 14（落盘前置的安全边界 = 首写段内容类型）+ 9/16 串联5（重复立法不增加效力）。

**串联判断：** 9/28 轮造出假断言。9/29 轮读到它、未重新取证、把它当上一轮的历史事实继承，并在此基础上把措辞「升级」——从「归档 X」改为「实测补做归档 X」，加「实测」二字反而使假断言更可信。9/30 实测才发现它从未发生。守卫十七与规则 14 都假定断言与其证据落在同一个 run 内；它们没有覆盖跨 run 的情形：断言写进 MEMORY.md（自动加载路径）后，下一个 run 读到它时，它已不在「待验证」的位置，而在「已完成的历史」的位置。同一段文本，第一轮的读者视其为待验证断言，第二轮的读者视其为既有事实。假性自证由「文本出现在自己上一轮写的记录里」这一事实产生——这是 8/22「工具功能性消失后被使用只是惯性残留」在文本层的变体：断言的功能（要求被验证）消失后，它仍被引用，只是引用者已不把它当断言。

**新的见解：** **完成态断言进入自动加载文件后，会从「断言」降格为「前提」——后续轮次继承它而不再验证，守卫十七因此只在单 run 内有效。** 判据：任何引用上一轮/历史记录中完成态断言的场合（尤其「修复上轮欠账」类动作），必须先把它当未验证项重新取证（跑一次 stat/ls/grep），再决定是否执行；不得以「上轮记录说已完成」为由跳过取证。与规则 14 互补：规则 14 管本 run 内断言的时序（断言须晚于其证据），本条管跨 run 断言的继承（继承的断言须重新取证）。与 9/16 串联5 呼应并推进一步：重复立法不增加效力，重复断言不增加真实性——两者都是「文本的复现」被误当作「事实的确认」。
