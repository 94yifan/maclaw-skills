## B. 规避方案

1. **压缩任务必须「先确认再启动」**：压缩是不可逆浪费型操作（耗算力但不产出最终价值）。教训：用户未明确要求压缩时，压缩属于可选优化——按 SOUL.md「分析→建议→确认」原则，先交付原稿并说明「如需精简可再压」，或并行压缩但明确告知「正在压，若接受原稿可跳过」。**把「压缩」从默认动作降级为按需动作。**
2. **长交付任务先报「剩余时间」**：蒸馏完成（22:43）到交付（00:27）之间有静默窗口，用户在等。改进：每完成一个大阶段（蒸馏完成/总览完成/docx生成中）就发一条进度+预计剩余时间，把「用户问好了吗」变成「我主动报进度」。
3. **章节覆盖在 spawn 前核对**：spawn 子任务前先列全书章节清单，蒸馏完成后核对「产出章节数 == 任务章节数」，缺口当场暴露而非事后发现。
4. **空目录 glob 问题**：zsh 下先 `ls` 判断非空再 `rm`，或直接 unzip 覆盖。

## D. ★ 知识串联（核心环节）

### 串联1：Dreaming 复盘 = 书中的「睡眠学习」——自我指涉的第一次显形

**来源：** 本书第8章「Agent 的持续进化」——经验→知识/指令/程序/参数的四种沉淀、进化闭环、睡眠学习（离线期从经验中沉淀知识）。
**连接：** book 分身每天都在做的 Dreaming 复盘，本质上就是书里描述的「睡眠学习」——在无用户输入的离线时段，把运行经验沉淀为 MEMORY.md 知识。

**关键启示：** 这是 book 分身 54 天来第一次遇到「书的内容描述了我自身的架构」。此前所有知识串联都是跨书/跨领域类比，今天是**自我指涉**——一本讲 Agent 设计的书，正好是 book 分身的设计说明书。书里说的「显式知识提炼」（观点二：上下文学习是检索而非推理，模型不会主动归纳），正是 AGENTS.md「Text > Brain」和复盘制度存在的理由：**不写进 MEMORY.md 的经验，对明天的我等于不存在。**

**可复用框架：** AI Agent 的复盘制度 = 睡眠学习的工程实现。经验→知识（MEMORY.md）→ 指令（SOUL.md 规则）→ 程序（skill/脚本）→ 参数（模型选择），四层沉淀与书第8章完全对应。复盘不是「记录今天发生了什么」，是「把今天的运行经验编译成明天的默认行为」。
