## B. 规避方案（落定为下次执行铁律）

### B1（对 A1）：例行产出必须有独立于 run 的「应到未到」检查

- 结构：期望清单（日期 × 应产出文件）× 实际文件，差集即缺失。检查者不能是产出者本身（产出者被杀时无法自检）。
- 最小落地：新增一个 guard job，23:56 检查当夜 8 个 dreaming 文件与当日茶饮日报是否存在，缺则 announce 一行，并写明缺的是哪一份、几天。
- 判据：任何日更/例行交付，验收必须同时看 run log（跑没跑）与文件（有没有），两者任一缺失都要出声。禁以 run status=ok 代表产出存在。

### B2（对 A2）：归因必须先排除本地自伤源，再谈外部不可控

- 动作顺序：① gateway 生命周期（启动次数 / 相邻间隔） ② 本地更新器与包管理日志 ③ 磁盘与内存 ④ 模型层错误码。前三项没查完，禁写「provider 层不可控」。
- 具体到本机：更新循环的修法只有两条，都要逸凡拍板——升级 Node 到 26.x 或 24.16 LTS 后重跑更新；或关掉自动更新并锁版本。本轮不擅自改。
- 判据：一次失败归因若指向外部，必须同时给出「本地无自伤」的读数；给不出就是没归因完。

### B3（对 A3）：清理即归档，且清理范围必须绑定本项目

- 代码改法（本轮已改，见 B6）：
- 判据：任何 unlink/覆盖前先 mv 到 `output/archive/<YYYYMMDD-HHMM>/`；清理只允许动本项目产出，共享目录必须按项目分目录。

### B4（对 A4）：门禁验收必须是攻击测试

- 判据：门禁上线后，构造「旧凭证仍在」的场景，看门是否拒绝。顺跑一遍通过不算验收。

### B5（对 A5）：重跑不得覆盖已被确认的产物

- 具体改法：step_2 若发现 `pre_research.md` 已存在且 mtime 晚于 pipeline 启动时间之外的最近一次人工写入，跳过写入并打印 skip 原因；或把模板写到 `pre_research_template.md`，永不覆盖研究版。
- 判据：门禁类步骤必须证明「开门动作不会改动门内被确认的对象」。

## D. ★ 知识串联（核心环节）

### 缝合1（主，归因层，本日最高价值）：失败形态第四次迁移＝自更新重启循环；它同时污染了前三次迁移的归因样本

- 链：10-13 缝合1（失败形态从超时迁到收尾工具）× 10-14 缝合1（迁到后台 Process）× 10-15 缝合2（迁到 provider 层，判为不可控）× 守卫二十（读数 × 判断 × 动作）。
- 实证：6,405 次更新尝试、29,542 次网关启动、24 秒一轮；Node v25.8.1 低于新版要求导致 npm preinstall 每次失败；更新器失败后仍重启，形成循环。今日两次 `interrupted by gateway restart` 与 23:45 八 job 同秒洪水全部由它产生。
- 新认知：失败形态的迁移不只是「越来越不可控」，还有一条反向路径——**表面上不可控的，可能只是本地一个没查的循环**。判断「不可控」的门槛应该是「本地三层已排除」，否则归因会把处方带到错误层级，并且连续多轮看起来都在正确思考。
- 判据：凡结论写「外部服务不可用」，同页必须附本地三项读数（进程重启次数、更新/包管理日志、资源水位）；缺一项即不成立。客户用法：交付事故归因到第三方前，先自证自家系统当天没有自伤事件。

### 缝合2（主，状态层）：缺失是第三种终态，回填类规则对它系统性失效

- 链：10-11 缝合2（自述型状态盲区）× 10-15 缝合1（回填 ≠ 归因）× 守卫十七（完成态须自证）× 守卫二十一（无消费者动作即停）。
- 实证：seq137 有 log 无产物（10-16 复盘 0 字节）；茶饮日报 10-16、10-17 两个排期点在 run log 里完全没有记录（连 error 都没有）。两种缺失的可见性都为零。
- 新认知：状态机不是 ok/error 两态，是 ok / error / 未启动 / 启动后被外部杀死 四态。前两态在 log 里，后两态只在「期望与实际文件」的差集里。**所有以 run log 为唯一读数的自检，对后两态天然失明。**
- 判据：例行产出建「期望清单 × 实际文件」差集检查，检查者独立于产出者。客户用法：日报/周报类交付，管理动作不是看有没有人报错，而是对着清单点「今天该到的东西到齐了吗」。

### 缝合3（主，门禁层）：门禁的实际通过条件 = 代码条件 + 运行前的人工前置动作；验收必须做攻击测试

- 链：守卫十三（只校验存在性等于没校验）× 守卫十四（校验目标不得互斥）× 10-15 缝合1（修复必须自证）。
- 实证：Gate 1 代码只有 `exists()`；今日成功拒绝的唯一原因是主会话提前 mv 走了旧确认文件。也就是说，门的有效性目前依赖「执行者记得先归档」这一条记忆，而记忆正是全系统最不可靠的一层。
- 新认知：门禁有两层通过条件，一层写在代码里，一层写在跑之前的人手上。**只验收前者，等于验收了一半。** 攻击测试（拿旧凭证硬闯）是唯一能同时测到两层的动作。
- 判据：任何门禁上线，必须留一条「攻击测试用例」及其输出；没有攻击测试的门禁按未上线计。客户用法：审批流上线时，用上一单的审批单据去闯这一单，看系统拦不拦。

### 缝合4（主，业务轨）：赛道定义的一致性锚是付费理由，不是价格带

- 链：10-12 缝合4（赛道定义一致性）× 品牌一致性十五至十八维 × 服务设计的 job-to-be-done。
- 素材：今日 PITAKA 框架把手机壳按「用户为什么付钱」切三层——材质美学（为稀缺材质与手感付费，200-800）、功能防护（为可验证参数付费，80-400）、潮流设计（为设计与身份付费，200-600）。三层价格带互相重叠，说明价格不是分层变量，付费理由才是。
- 新认知：同一价格带里可以同时存在三种完全不同的竞争逻辑；用价格带切赛道，会把「同为 300 元但不构成竞争」的品牌放进同一张对照表，也会把「价格不同但抢同一批用户」的对手漏掉。赛道定义的一致性校验点是：每一个竞品必须能回答「它和本品抢的是哪一种付费理由」。
- 判据：赛道框架必须显式写出付费理由轴，价格带只作为结果标注；同一竞品出现在两层即判定框架有问题。客户用法：客户说「我的竞品是谁」时，先问「客户为什么买你而不是买它」，答案不同就不是同一层。

### 缝合5（次，机制轨）：步骤空转有读数特征——声称做研究的步骤耗时 0.0003 秒

- 链：10-14 缝合2（能力空转＝路由缺口）× 守卫十七（完成态须自证）× 守卫二十（读数层）。
- 实证：pipeline status 里 step_2 的 started/completed 相差 0.0003s，而它声称做的是赛道框定 + 竞品筛选 + 创始人背景挖掘；实际代码只写了一段固定模板。

- 判据：pipeline 自检加一条：任何声称做研究/分析/采集的步骤，耗时 <1s 或输出哈希与上轮相同，标记 `suspect_noop` 并要求人工确认，禁直接算 success。客户用法：验收自动化流程时，先看每一步的耗时分布，异常快的步骤往往什么都没做。
