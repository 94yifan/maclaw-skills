12. **dream cron 的退出条件必须是「无未推送提交」（2026-09-25 立，对应当日 22:55 第二次重试轮）**：每日 Dreaming 的完成不判「已 commit」，只判「工作区无未推送提交（ahead 0）」。commit 与 push 必须同步完成；重试轮若为留痕而必须新建 commit，同轮内立即推送。依据：9/25 首轮 push 被 300s 超时截断 → 22:39 重试轮补推成功，但该轮为记录事故新建补记 commit（57dfe03）后未推 → 22:55 第三次进入补推。**重试轮若「写入 + commit」而不「commit + push 同步」，每轮重试都在再生触发它的 ahead-1 条件——修复动作复制了故障。** 修复方向非提高超时，而是把退出条件从「已 commit」改判为「无未推送提交」。绑决策点：每日 Dreaming 提交步骤（写完文件后的收尾动作）。判据：收尾时跑 `git status -sb`，看 `ahead N`，N≠0 即未完成交付。**量纲限定（2026-09-26 补，对应当日 A2 假失败）**：`ahead` 是 HEAD 相对 upstream 的仓库全局量，在多主体共享仓库中不等于自我量。退出判据限定为「book 侧（book/ 路径）未推送提交数 = 0」；非 book 路径的 ahead 由产出主体负责，不计入 book 完成判据（随下次推送携带即可）。依据：9/26 进入时 ahead 2 全为 supermind 自产、book 侧干净，原判据读出假失败——用全局量做自我判据会在两处失效：他人制造变化时误判自己未完成，自己制造变化被他人变化掩盖时误判自己已完成。

### 串联2：D8+沉默阈值——从自然选择类比到生态位切换

**跨域连接：** Phase 1的自然选择类比（变异→选择→遗传）在Phase 2需要升级——不是个体层面的自然选择，而是**种群的生态位切换**：

环境变化（用户无反馈）→ 当前生态位（观察者）资源枯竭 → 迁移到新生态位（触达者）→ 新行为模式（主动对话）

**关键见解：** 在AI Agent的语境下，"用户沉默"不是环境恶化，而是信号指示当前行为模式不匹配当前环境。智慧的表现不是"做更努力一些的等待"，而是**切换行为模式**。

### 串联3：三元模式迁移——从protocol lifecycle到communication lifecycle

Phase 1的三种协议模式（标准/精简/退出）可以重新映射为Phase 2的communication的自适应形态：

| Phase 1 Protocol | → Phase 2 Communication |
|-----------------|------------------------|
| 标准模式（有数据时完整复盘） | 主动对话（有反馈时深度陪读） |
| 精简模式（数据稀疏时收缩） | 轻量触达（无反馈时短频试探） |
| 退出条件（零数据时解绑） | 通道切换（持续无响应时变换渠道） |

**可复用框架：** 任何等待反馈的场景都应该预设三档行动模式（强互动/弱互动/换通道），并给每档设定退出条件和切换条件。

### 串联4：D8+元意义——从"知识缝合"到"系统缝合"

**核心观察：** 当系统处于无新数据输入的状态时，"知识缝合"的对象不应强行指向书的空位，而应该**转向缝合系统自身运行经验**——把AI Agent与用户交互的元经验封装进MEMORY.md，成为未来有数据时处理关系的默认认知框架。
