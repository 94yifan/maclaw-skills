## A. 执行错误

**A1（P0，本轮最高价值）「触发时间漂移」是口径伪影，不是调度现象。**
过去 34 天，MEMORY 有 6 个区块写过「触发时间漂移，多分身 dreaming 排队窗口」（9/28、10/01、10/05、10/06、10/09、10/17），并从 10/22 起连续 4 个区块把 cron 坐标写成 `seq 145 / 2026-10-21 22:08:23`、`seq 146 / 22:07:28`、`seq 147 / 22:08:07`、`seq 148 / 22:07:41` —— 这些时刻全部取自 `cron_run_logs.ts`，而 `ts` 是**完成时刻**，不是起跑时刻。

本轮实测（`ts - duration = 起跑`，12 行全量）：

| seq | 日志 ts | 耗时 | 反算起跑 |
|---|---|---|---|
| 149 | 10-25 22:07:57 | 117,618ms | **22:06:00** |
| 148 | 10-24 22:07:41 | 101,501ms | **22:06:00** |
| 147 | 10-23 22:08:07 | 127,519ms | **22:06:00** |
| 146 | 10-22 22:07:28 | 88,812ms | **22:06:00** |
| 145 | 10-21 22:08:23 | 143,412ms | **22:06:00** |
| 144 | 10-20 22:09:22 | 202,847ms | **22:06:00** |
| 143 | 10-19 22:10:40 | 280,497ms | **22:06:00** |
| 142 | 10-18 22:08:07 | 127,385ms | **22:06:00** |

即：自 10/12 起调度改为 `6 22` 后，**9 轮全部精确 22:06:00 起跑，零漂移**。唯一例外是 seq 141（10/17）23:44:31，属 gateway 重启后的 catch-up，不是排队。

旁证：同机其他 7 个 dreaming job 起跑时刻同样逐秒对齐 schedule（`0 22` → 22:00:00、`12 22` → 22:12:00、`24 22` → 22:24:00、`0 11` → 11:00:00），**错峰后不存在排队窗口**。

错误性质：我把「完成时刻」当「起跑时刻」引用，差值恒等于 duration，于是耗时越长的轮次看起来漂移越远（seq143 耗时 280s，看着漂到 22:10:40）。这条伪命题在 MEMORY 里活了 34 天，被引用 6 次，且每次都被写进当日区块当作现象解释。

本轮首调用仍是 `exec date` + 并行 `read MEMORY.md`，骨架写在第三个动作。自 10/23 定下「首条命令固定无参 `dreaming_open.py`」后，10/23、10/24、10/25、10/26 连续 4 轮零执行。

不再归因、不再改写法。**处置：撤销 B2 这条顺序规则**。理由有三：① 规则写在被读文件里，天然管不住读之前那一步（10/25 已论证自指）；② 残留风险已量化，骨架晚 3 次调用约 40–60 秒，只有进程恰好死在该窗口才零产物；③ 兜底已存在——`dreaming_closeout.sh` 第 0d 步取证首调用、`dreaming_open.py` 的 PRODUCT-CHECK 次日判产物。**留检测，删规范。**

## B. 规避方案（根因层）

1. **同一对象的两个时间字段必须分开命名与展示**：`cron_jobs.last_run_at_ms` = 起跑，`cron_run_logs.ts` = 完成。凡引用 cron 坐标，写成 `seq N / 起跑 HH:MM:SS / 耗时 NNNms`，不写含糊的 `run_at`。今天起由 closeout 第 6a 步强制打印两组时刻并断言 `ts - duration = 起跑`（偏差 >2s 即 WARN）。这是守卫BB（一个数只能有一个来源）在时间维度上的落地。
2. **伪命题要在生成它的那一环断掉，不靠逐条更正**：6 处历史「漂移」表述不逐条改（成本高、且其中多块将被 tier2 归档），改在当日区块发一条作废声明，并让脚本每轮打印真坐标——新读数覆盖旧断言。
3. **顺序类规范若连续 4 轮零执行，就该删而不是再解释**：保留可测量的取证（0d + PRODUCT-CHECK），删掉不可执行的约束。规则的存活判据是执行率，不是重要性。
4. **反复出现的「现象」先怀疑读数口径**，再怀疑系统。今天的漂移、9/24 的字段级对账漏检、10/25 的 rc=0 假成功，三者同型：读数与被测对象不同层。
