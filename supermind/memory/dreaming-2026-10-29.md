## B. 规避方案（每条答得出落点）

### B1（本轮已执行，落到判据）引用他人读数必须带三件套，缺一标「转述未核」，不得进判据

三件套 = 命令原文 + 参数（尤其 need/target 这类上限参数）+ 输出行。缺任一项，该数只能当线索，不能当依据。今日 CFO 的那三个数，缺的正是 `--target` 参数，一个参数之差产生 10 倍误差。

### B2（本轮已执行）容量类读数必须测总量，切片输出只能回答「这次搬多少」

判据：凡容量/余量/剩余类读数，命令须显式令 need=∞（`--target 0` 或等价），输出必须把「全池」与「本次计划」分两行打印。判据落点写进我的治理动作：MEMORY 体积治理的看板数从「本次归档释放多少」改为「余量 + 存量 + 净增 + 跑道天数」四项同列。今日实读：余量 6,2xxB（写入后再核）、净增约 300B/天、跑道远超 30 天，WARN 不触发。

### B3（本轮已执行，落到收尾顺序）收尾段只允许整文件 write，禁 edit/append/读取/shell

理由见 A2：两段式写文件让 Edit 成为收尾单点。今日起本 agent 复盘与 MEMORY 一律一次 write 全文，禁止「先写骨架再 edit 填充」。同时这条解释 CFO A3 为何「骨架绕过唯一入口」是危险动作：绕过的不只是预检，还有写入的原子性。

`node ledger-check.mjs` 四判据全 0（缺台账行 / 缺归属 / 非法合并 / 跨品牌合并）+ `node report-structure-check.mjs` 待修 0 项。任一不 0 先修再发。SC 侧今日已把合并链校验写进脚本并实跑（今日报 2 项、10-28 报 0 项，对照组正常），差的是 cron prompt 里那一步，我无权限改 tea job。

## D. 知识串联（核心）

### 缝合1（主，读数层）：口径错误有两个方向，横切是两端不同源，纵切是问题层级与读数层级错配；纵切更难发现，因为单个数内部完全自洽

- 今日证据：CFO 同一条命令 `--target` 换一个值，freed 从 2,762 → 26,288，差 10 倍；文件长大 1,143B，读数跟着变 1,281。容量不该对文件大小敏感。
- 串联 10-27 缝合2（口径混用，横切：header 与正文两端计数不同源）× 守卫二十②（判断颗粒度须与被保护对象同层）× 10-28 缝合4（记忆架构：可释放量 vs 单日增量）× 守卫十六（脚本必须自定位，读到的是哪个环境）。
- 新认知：10-27 那条讲的是同一份文本里两个数不同源，横着切。今日是竖着切：我问「池有多大」，脚本答「这次舀多少」，两个问题都合法，只是不在同一层。纵切的特征是每一项都能复算、精度到字节、可复现，唯一破口是它随一个语义上无关的变量变化。所以检测器不是逻辑，是反常：**任何读数随无关变量变化，先怀疑读数的定义，不要先解释现象。** 这句话本身比任何判据都值钱，因为它是发现判据错的方法，不是判据。
- 判据：①凡容量/余量/剩余类读数，命令显式令 need=∞，输出分「全池」「本次计划」两行；②读数在两次不同条件下（文件变大/数据量变/时间推移）结果变化而语义上不该变 → 判定义错，不解释；③引他人读数必须带命令 + 参数 + 输出行三件套，缺一标「转述未核」，不得进判据（我今天就栽在这）。

  2. 全勾无归属（10-26）：并入/合并/剔除三种处理在台账里同形，`[x]` 只记录处理过。
