## 五、知识串联（D·核心）

### 缝合1（主·商业层·新）：免租期是价格工具，不是优惠

**实证：** 今日租赁条件 232㎡ / 4.2 元/㎡/天 / 8 个月免租 / 保证金 101,442 / 全包 3.86 元/㎡/天（CFO 复盘原文）。本会话算术：名义年租金 4.2×232×365＝355,656 元；若按 3 年租期摊 8 个月免租，等效 3.27 元/㎡/天（4.2×28/36）。**租期长度 CFO 复盘未载，标待核。**

同一份合同出现 4.2 / 3.86 / 3.27 三个单价，差异全部来自口径：名义价、全包价、摊薄价。谈判桌上最容易被混用的就是这三个数。

**串联：** 10-17 缝合4（权益密度：品牌用可拿走的权益换注意力）＋ 10-18 缝合6（激励第三层：约束从金额转向法律关系）。

**新认知：** 免租期是房东让出的权益，它的价格不在租金里，而在租期长度、物业费调价权（5.1 无上限）、恢复原状（16.1）、解约权（14.1b）、押金与滞纳金（4.5 千分之五/日）里。权益越厚，换走的东西越贵。消费者端叫权益密度，B2B 端叫租约结构，机制同一条。

**判据：** 看到「免租 X 个月」先做三步——①按实际租期摊成等效单价 ②列出换取条件 ③算退出成本。三步缺一，免租期就是账面优惠。

**管理含义：** 曼拾第一次签这种量级的固定成本承诺，判断标准不该是「每月多少钱」，而是「最坏情况一年要付多少、多久能退出」。

### 缝合2（主·治理层·新）：删掉的条款都是「锚」

**实证：** 备案版合伙协议比对，三处实质变化全部是删锚——出资违约责任整条删除、期限由十年改为不约定期限、合伙人名册由附件改为正文内嵌写死。同时 5 处条款冲突（8-4 与 15.2 优先购买权、16.1 与 20.8 恢复原状等）。

**串联：** 10-18 缝合6（第三层问 GP/退出定价/回购）＋ 10-15 缝合3（改锚点必生空洞与重叠）。

**新认知：** 锚不是装饰，是争议发生时的默认解。违约责任是代价锚，期限是时间锚，名册附件是身份锚。删锚让文本更干净、更容易过审，但把全部解释成本推给签字之后，而那时筹码已经换手。

**判据：** 审重大合同不看加了多少条，看删了哪些锚。五项任一被删或改成「另行约定」即标红：违约责任 / 期限 / 名册与附件 / 定价机制 / 退出触发。每删一个锚，必须写清替代机制；写不出，就是留给未来的一次被动谈判。

**管理含义：** 备案版不是「不能改」，而是改的时候要知道删掉的是什么。删锚常常不是恶意，是「这条写不清，先删了过备案再说」——而这类妥协永远在签字后兑现。

### 缝合3（主·元层·跨主体 n=3）：已交付是产生端自评

**实证：** CFO 10-18 那轮 `finalStatus=success`，但 `didSendViaMessagingTool=false`、`messagingToolSentTexts=[]`，逸凡次日第一句「这个没发我」；book 10-18 报告在盘、已 commit、`delivered=false`；BM seq145 产物在盘、`delivered=0`。三件产生端都成功，接收端都为空。

**串联：** 10-15 缝合1（成败判定与 run 状态解耦）＋ 守卫十七（完成态须自证）＋ 10-18 缝合1（假缓解）。

**新认知：** 交付有三个互不传递的成功定义——run 成功、产物落盘、接收端可见，而系统只记录第一个。任何「已发送」结论必须绑定接收端凭证（message_id / 附件 URL / 用户回执），拿不出只能写「已生成」。

**判据：** 写「已交付」的同一句里必须有接收端 id；没有就改写为「已生成，送达待确认」，下一轮开场回填。

**管理含义：** 内部说完成和客户真收到是两件事。组织的默认假设应该是「没看到回执就是没发生」。

### 缝合4（次·机制层·承守卫十）：待办表的「等别人」是合法终态

**实证：** `pending-ceo.json` 四项，1 done、2 blocked、1 planned 跨轮未动。表建成首日即出现合法挂账。

**新认知：** 任何状态机只要存在一个「不需要我做任何事」的合法状态，未完成就会自动流向那里；状态词必须自带到期与升级，否则只是把遗忘文档化了。

**判据：** 状态三件套——依赖对象 / 最晚时点 / 超时升级动作，缺一即视为挂账。

### 缝合5（次·系统层·承 10-18 缝合1·第 2 次实证）：没出事不是好消息

**实证：** update.once runs 10,630 → 14,969（24h +4,339，约 20 秒一轮）；日志 29.5MB/65,261 行 → 41,075,852B/637,926 行；`last exit code=1`；Node v25.8.1 仍不在要求区间；今日网关零重启、8 次运行仅 2 次工具型 error。

**新认知：** 这套系统现在的稳定，由一次持续失败维持——更新死在 npm 阶段，走不到重启。稳定性的来源若是某个环节持续失败，它随时会以另一种方式收回。

**判据：** 连续 3 日只要根因计数仍在涨，无论症状如何，P0 不降级。

### 缝合6（次·管理层·CEO 自应用·新命名）：没有名字的问题没有归属

**实证：** 今日 4.5 小时业务中，法律风险有归属（CFO，17 条 + 27 处），面积计算有归属（CFO），经营口径无归属、无人提；CEO 连续 4 日零交互。
