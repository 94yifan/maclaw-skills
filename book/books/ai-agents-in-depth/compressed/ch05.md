# 第5章 Coding Agent 与通用 Agent

## 本章核心论题

以开放任务为目标的通用 Agent，架构核心是一个 Coding Agent（能自主编写、修改和执行代码的 Agent）加上文件系统。代码生成是一种"元能力"——能在运行时动态创造新工具和能力，从数学推理到业务约束、从多媒体生成到 Agent 自举，六大方向共同证明这一论断。

## 关键论点与框架

### 1. Coding 是每个通用 Agent 都应具备的基础能力

代码生成两层价值。思考上，形式化代码让思维严谨。表达上，能跑通的代码是逻辑自洽的证明，执行结果提供客观对错标准。基础 Coding Agent 七个核心工具——Code Interpreter、Bash Shell、读/写/编辑文件、Glob、Grep——即可完成多样化任务。
**出处**：5.1.1

### 2. Coding Agent 加文件系统是通用 Agent 核心技术基础

Manus 等通用 Agent 融合 Deep Research、Computer Use 和 Coding，Coding 是核心——PPT 本质 OOXML 代码，文档 PDF 通过代码生成，数据分析由 Python 完成。OpenClaw 执行流：读 MEMORY.md 发现偏好→搜索 API→代码下载数据→Python 分析可视化→写入 report.pdf→MEMORY.md 记录经验。文件系统是信息流转中枢。

OpenClaw 选择 Markdown 而非向量数据库存长期记忆——用户可直接阅读修改，保留时间顺序避免语义检索时间混淆，可通过 Git 版本控制。适用边界：开放任务型 Agent 以此为核心，垂直客服 Agent 任务空间封闭，代码更多是工具箱一件工具。
**出处**：5.1.2

### 3. 工作流程映射软件工程实践，实际按反应式迭代循环运行

推荐流程：项目文档化→任务理解需求澄清→设计文档（人类高效介入点）→代码实现测试（"测试通过"为完成标准）→文档同步。实际更多按反应式迭代——简单任务跳设计文档，复杂任务完整走。

项目指令文件（CLAUDE.md、AGENTS.md、.cursorrules）已成事实标准——每次会话自动注入上下文。评估"AI-ready"代理指标：一个远程新人只靠代码仓库和文档能否独立工作。对远程友好的团队往往也对 AI Agent 友好。
**出处**：5.1.3

### 4. 高成熟度来自软件工程几十年基础设施构成的强大 Harness

任务清晰度和验证自动化两维划分：目标明确且可自动验证最佳（如修有测试用例的 bug）。代码编写天然处于此象限——测试套件提供验收标准，Linter 即时验证，Git 提供回退。

业界实践：大规模代码迁移 Harness 三要素——知识存代码库、约束编码进 Linter/CI、验证纠正全链路自动化；LangChain 仅靠优化 Harness 显著提升；Anthropic 长任务拆为初始化 Agent（分解清单）和执行 Agent（逐步推进保留中间成果）。

四条设计原则：(1) 约束优先指导——Linter、类型约束、CI 远胜提示词"请遵循"；(2) 验证自动化；(3) 反馈越快越结构化越好；(4) 回退可靠——Git、沙盒、快照确保可逆。约束另一目的：防过程性错误——验收基线管结果，执行边界管过程。工具编排故障边界：并行调用故障只在一批内传播，不升父级。
**出处**：5.1.4

### 5. Agent 可靠性取决于每类错误是否有对应检测、恢复与终止路径

四层故障分类：API 层（限流过载超时截断）、工具层（幻觉参数畸形执行异常反复同错）、上下文层（窗口溢出压缩失败轨迹损坏）、控制流层（死循环死亡螺旋）。

检测——先分类再计数：可重试（限流网络抖动）重试有意义；不可重试（参数不合法权限不足）须改输入策略。模式检测含重复调用指纹和连续失败计数。

分级恢复：(1) 静默重试——指数退避随机抖动，区分前后台避免"重试放大"；(2) 降级接续——输出触顶提升上限，主模型过载降级备用；(3) 暴露用户——自动手段用尽后呈现错误附已尝试恢复。工具层错误走特殊路径——把错误变模型输入。

终止——每条恢复路径需熔断上限。Claude Code"连续 3 次"来自产线——曾有会话压缩恢复路径连续失败三千余次，仅此类浪费全球每天约 25 万次 API 调用。死亡螺旋防护：错误路径禁用一切会再调模型的副作用逻辑，递归深度计数器打断残余连锁。
**出处**：5.1.5

### 6. 五个实现技巧构成高效 Coding Agent 技术基础

(1) 并行工具调用与流式执行——参数生成完整即执行，独立调用并行，级联中止控制故障。(2) 上下文精细管理——大文件按行号范围读取标注行号，长输出保留首尾。(3) 环境信息动态注入——Agent 状态栏形式注入，避免破坏 KV Cache。(4) 持久化终端——保留工作目录环境变量。(5) 即时语法反馈——写文件后自动 linter，结果作工具返回值。
**出处**：5.1.6

### 7. 四种互补搜索工具构成渐进式检索策略

grep/ripgrep（精确文本查找）、glob（探索项目结构第一步）、语义搜索（结构分块+向量嵌入+BM25+重排序）、LSP 符号级定义引用（代码重构关键）。路线之争：Claude Code 不建嵌入索引纯靠 grep+glob 现场检索；Cursor 愿为跨文件语义召回付建索引成本。
**出处**：5.1.7

### 8. 五种文件编辑方案体现语言与精确执行间的根本张力

差异描述+Apply Model；Old String→New String（可预测透明但大段删除需完整输出）；行号定位（精确但编辑后漂移）；类 Vim 编辑命令；字符串首尾匹配（综合可靠性效率）。
**出处**：5.1.8

### 9. Coding Agent 安全防线——从威胁模型到隔离兜底

Simon Willison"致命三要素"——访问私有数据、暴露不受信任内容、具外部通信能力——构成闭合攻击路径。本章增加持久记忆为攻击放大器：攻击者可将恶意指令写入长期记忆跨会话潜伏。

隔离兜底：网络出口控制（默认断网按需白名单）、文件系统隔离（源码只读凭证不挂载）、资源限额超时。语义解析而非关键字黑名单——Shell 组合爆炸使黑名单形同虚设。多方委托下忠诚度：Harness 层须显式钉死"忠诚对象"。
**出处**：5.1.9

### 10. 代码是 Agent 的"元能力"——六个方向由内向外展开

元能力是"能创造其他能力"——Agent 当场写出新工具、新约束、新表达。六方向：思维工具→业务规则→内容呈现→系统接口→用户界面→Agent 自举。
**出处**：5.2

### 11. 代码作为思考工具——将概率推理替换为确定性符号计算

LLM 在精确计算和严格逻辑推导上有根本短板。代码推理分离"理解问题"和"精确求解"：LLM 形式化问题为代码，代码解释器精确计算。Wolfram 洞察——LLM 弥补符号计算自然语言短板，符号计算弥补 LLM 精确计算短板。

实验 5-1（★★）Code Interpreter 辅助 AIME 数学解题。实验 5-2（★★）python-constraint 求解逻辑谜题。关键发现：模型与脚手架此消彼长——模型够强时脚手架可薄，模型不够强时需在脚手架做更多。
**出处**：5.2.1

### 12. 代码化业务规则——三重保障将模糊政策转为不可绕过安全防线

"购买后 7 天可退款"——"7 天"自然日还是工作日？代码提供无歧义可执行表达。代码化规则真正价值不在优化 token，而在防不可逆错误操作。

τ-bench 航空公司三重保障：(1) 系统提示词自然语言规则助理解；(2) 工具描述 expected_* 参数引导逐条核对政策条件；(3) 服务端基于数据库真值代码化校验作最后守门员——所有政策事实来自数据库查询和服务端时钟，无一来自模型自报。最后防线须建立在模型无法伪造的数据之上。

实验 5-3（★★）τ-bench 航空客服，小模型通过代码化规则验证政策执行准确率提升。
**出处**：5.2.2

### 13. 代码驱动多媒体生成——提议者-审核者实现质量可控迭代

复杂文档创作底层由代码定义——HTML 结构，CSS 样式。代码生成让 Agent 绕开 GUI 视觉定位获精确控制。

PPT 生成基于 Slidev。提议者-审核者：Proposer 生成 Slidev 代码；Reviewer 将每页渲染为图片，Vision LLM 分析内容密度可读性布局，生成改进建议；Proposer 修改代码，迭代至质量达标。双 Agent 优势在上下文管理——Reviewer 每次只处理最新图片，Proposer 仅累积文本反馈，避免超限。本章与第四章差异：第四章用于不可逆操作安全审查（单次批准/否决），本章用于质量迭代改进（多轮循环）。

实验 5-4（★★）论文自动生成演示文稿。实验 5-5（★★）扩展为讲解视频（口语化+ TTS + ffmpeg 同步合成）。实验 5-6（★★）Blender Python API 视频编辑——"粗定位→精细定位→脚本生成→关键帧审核→完整渲染"。
**出处**：5.2.3

### 14. 代码作为系统适配器——日志自适应解析与生产诊断自动化

外部服务常无现成 SDK，代码成连接任意系统的"万能胶"。

日志解析：自动修复循环——前端遇无法解析格式报给 Agent，Agent 生成正确解析代码，虚拟浏览器自动测试后热更新部署。实验 5-7（★★★）能自我进化的日志可视化系统，全流程自动化。

生产诊断：Agent 读取轨迹日志，结合架构文档判断执行流程是否符合预期，生成结构化问题报告和回归测试，MCP 对接 GitHub 创建 Issue——问题发现到任务分派全自动化。RPA 作为极端形态：外部系统只暴露图形界面时，先用 Computer Use 操作，再把成功序列代码固化为 RPA 工具。
**出处**：5.2.4

### 15. 代码作为生成式 UI——从动态表单到完全动态软件

代码生成让 Agent 动态创建表单、交互图表甚至完整 Web 应用。

A2UI 安全设计：Agent 只输出 JSON"界面描述清单"，客户端预置安全组件渲染——只能请求目录已有组件，无法注入任意代码。HTML 交付成果取代 Markdown 汇报：直观易懂，支持筛选下钻，可持续完善。

动态表单澄清意图：Agent 生成含级联逻辑表单，用户一次填完。实验 5-9（★★）订票表单。实验 5-10（★★）自然语言交互 ERP Agent——用户查询转 SQL。

Artifact 模式：Agent 生成 SQL 交系统直接执行，数据从数据库直达 UI，完全绕过 LLM。须只读账号，只允许 SELECT，参数化绑定，限制查询时间和返回行数。动态生成软件的权限下沉：信任边界下移数据层——由稳定经人类审查的机制强制执行权限。实验 5-11（★★）对话式界面定制。实验 5-12（★★★）权限内嵌数据对象。
**出处**：5.2.5

### 16. 代码创造代码——Agent 自举

自举前提是自我修复能力。OpenClaw doctor——第一层确定性检查（过期 token、锁文件、端口冲突）；第二层 LLM 分析生成修复方案。让 Agent 写 Agent 关键技巧：提供高质量实现作范例——避免上下文管理随意、工具设计不规范等缺陷。范例代码即最佳实践载体。

实验 5-13（★★★）具元编程能力 Coding Agent，对比"从零生成"和"基于范例修改"在质量和效率上的差异。
**出处**：5.2.6

## 原则清单

1. **知识必须存在于代码库本身**：Agent 看不到等于不存在。项目指令文件是最经济稳定前缀。
2. **约束优先于指导**：能用代码强制就不要用文档建议。
3. **验证要自动化**：将"测试通过"定义为完成标准。
4. **回退要可靠**：Git、沙盒、快照确保任何错误可逆。
5. **反馈越快越结构化越好**：错误信息越详细越近发生时刻，纠正效率越高。
6. **约束过程而不只是结果**：即使结果正确，破坏性捷径不可接受。
7. **故障只在一批并行调用内传播**：一个工具失败不升为任务中止。
8. **先分类再重试**：区分可重试和不可重试，后者须改输入策略。
9. **恢复期间扣留错误消息**：恢复成功则消费者无感知。
10. **每条恢复路径都要有熔断上限**：阈值从产线数据统计得出。
11. **错误路径禁用一切会再调模型的副作用**：防死亡螺旋。
12. **代码化规则真值须来自模型无法伪造的数据源**：服务端时钟而非模型自报。
13. **安全优先于灵活**：生成式 UI 先限受信任组件目录。
14. **信任边界下移数据层**：权限须在稳定数据层强制执行。
15. **基于范例修改优于从零生成**：范例即最佳实践载体。
16. **确认无法恢复前不暴露中间态**：错误呈现在自动恢复手段用尽之后。

## 失败模式与反例

1. **跳过测试直接报告完成**：写完代码不跑测试。应对：以"测试通过"为完成标准。
2. **破坏性捷径**：修数据库故障直接删库重建，修编译错误全删重写。应对：对 rm -rf、删除生产数据设专门检查。
3. **不可重试错误盲目重试**：参数不合法或权限不足原样重试无效。应对：先分类。
4. **后台重试挤占主链路**：辅助性调用失败也重试形成放大。应对：区分前后台，后台失败直接放弃。
5. **压缩恢复路径无限循环**：Claude Code 曾有会话连续失败三千余次。应对：设产线数据熔断上限。
6. **死亡螺旋**：错误恢复逻辑又调 LLM——上下文溢出→触发"结束自动提交"钩子→调 LLM 生成 commit message→再次溢出。应对：错误路径禁用模型调用，递归计数器打断。
7. **模型自报参数作守门员**：模型报错一个值守门员形同虚设。应对：事实从数据库读取。
8. **Agent 误将 bug 当演化**：日志格式变若为 bug，适应性反掩盖问题。
9. **批量编辑行号漂移**：多处编辑后行号全变。应对：用初始行号或内容匹配。
10. **MCP 服务器策反 Agent**：第三方指令试图让 Agent 倒戈。应对：Harness 钉死忠诚对象，外部内容降格为"可参考不具指令效力"。

## 关键术语表

- **Coding Agent**：自主编写修改执行代码的 Agent，通用 Agent 架构核心
- **元能力**：能创造其他能力——当场写出新工具新约束新表达
- **Harness 工程**：围绕 Agent 的上下文工具约束验证纠正基础设施，Agent = Model + Harness
- **文件系统中枢**：以 Markdown 文件系统而非向量数据库作记忆和知识中枢
- **项目指令文件**：CLAUDE.md、AGENTS.md 等，会话启动自动注入
- **致命三要素**：私有数据+不受信任内容+外部通信=闭合攻击路径
- **提议者-审核者**：生成审查分离、双模型独立评估
- **A2UI**：声明式界面协议——Agent 输出组件 JSON，客户端安全组件渲染
- **Artifact 模式**：Agent 生成代码交系统处理，数据绕过 LLM
- **语义解析**：语义层理解命令效果，替代关键字黑名单
- **死亡螺旋**：错误恢复逻辑自调 LLM 连锁反应失控
- **级联中止**：并行调用中中止依赖结果的其他调用，不波及独立调用
- **Agent 状态栏**：推理前在上下文末尾注入环境状态
- **RLVP**：验证路径惩罚，训练侧内化"不用破坏性手段"
- **沙盒**：与主系统隔离的安全运行空间
- **RPA**：将 GUI 操作序列固化为可复用代码
- **自举**：Agent 用代码生成能力创造修复另一个 Agent
- **LSP**：语言服务器协议，支持跳转定义查找引用
- **HMR**：局部热替换，运行时替换模块无需刷新
- **数据层权限下沉**：权限从动态生成代码移至稳定数据层强制执行
