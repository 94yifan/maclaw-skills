# 第8章 Agent 的持续进化 与 第9章 多模态与实时交互

## 本章核心论题

Agent 的核心悖论：零样本解决从未见过的复杂任务，一万次重复后仍可能重犯首日错误。第8章论证在模型外围构造"评价→归因→更新→验证→发布"的自主进化闭环，按经验性质路由到知识、指令、程序或参数四种载体。第9章将闭环扩展到语音、GUI和物理机器人三个实时交互场景，揭示交互架构与智能上限是两条独立能力轴。

## 关键论点与框架

### 1. 保存经历不等于从经历中学习

**论证：** 一百条轨迹存进向量库可帮检索，不会自动完成跨案例比较。学习发生在系统主动完成"评价、对照、归纳、验证"之后，而非日志写入磁盘那一刻。第三章沉淀"用户与世界是什么样的"，本章进一步沉淀"在什么条件下该怎样行动"。

**出处：** 8.1节开头。

### 2. 三层轨迹验证：结果、过程、质量依次门控

**论证：** 结果验证"是否办成"，过程验证"是否按规定办成"，质量验证"是否办得合适"。结果和过程是硬门，通过后质量才有决策权。验证须保留结构化诊断而非压缩成标量，后续才能路由。

**证据：** 客服 Rubric 七维度，重点看承诺—行动一致性：轨迹评价检查是否真调用了退款工具且成功，而非只看文本中"已提交退款"。

**出处：** 8.1节。

### 3. 四种更新方法，由经验性质决定路由器

**论证：** 路由依据——事实→知识文档，可语言化策略→Prompt/Skill，可精确执行流程→程序，高维感知与隐式策略→模型参数。四种不互斥。路由逻辑：`if factual → KNOWLEDGE; elif expressible_as_language_rule → PROMPT/SKILL; elif deterministic_or_hard_safety → PROGRAM; else → MODEL_PARAMETERS`。

**证据：** PreAct 重复任务 8.5–13 倍加速。Alita 发现缺字幕能力后封装 youtube-transcript-api 为工具。

**出处：** 8.2节、实验8-5。

### 4. 从更新产物到更新"更新方法"——五层搜索尺度

**论证：** 优化对象逐层扩大：单条规则→结构化上下文→工作流→Harness→优化器代码。偏内层易归因回滚，默认选择；局部修改长期无效才升外层。评价器、权限边界、留出测试始终不可修改。ACE 上下文维护为带标识符条目集合，增量更新去重。MCE 分内外循环：内层优化产物，外层修改搜索和过滤。

**出处：** 8.2.5节。

### 5. 双循环架构：在线执行与离线进化分离

**论证：** 在线执行只完成任务记录证据；离线循环聚合轨迹、诊断根因、生成提案，通过验证门槛发布新版本。分离防止一次偶发成功或恶意输入立刻改写长期能力。

**证据：** Voyager 在 Minecraft：自动课程生成器选目标，迭代提示带回错误至代码，验证后入技能库——3.3 倍独特物品、2.3 倍探索距离、里程碑最高快 15.3 倍。

**出处：** 8.3节。

### 6. 发布协议须区分三类验证集，不可用平均分绕过否决

**论证：** boundary_set 检查修复触发问题，retention_set 防旧能力回退，safety_set 守住安全边界——不能合成平均分绕过 veto。需区分 Harness 更新能力（产生修改）和受益能力（正确使用修改）。

**出处：** 8.3.2节。

### 7. 三层安全边界

**论证：** 第一道：LLM 摘要不可当指令执行，按 schema 提取主张。第二道：新能力经沙盒和权限检查后服务真实流量。第三道：Agent 可改 Prompt/知识库/工具，不能改验证器、测试用例、发布门槛、审计日志和版本备份。

**出处：** 8.3.4节。

### 8. 睡眠学习：空闲期整合、遗忘和能力保鲜

**论证：** 周期：触发（无在线任务时）→定向（读能力和边界）→采集整合（找新信号、合并重复、标记冲突、生成补丁）→验证审批→修剪索引（长期不用标过期归档）。与第三章一致：先保存不可变证据，再离线生成整理结果。

**出处：** 8.3.5节。

### 9. 语音交互三种范式：轮流说话→同一模型听想说→持续听说决策

**论证：** 级联流水线（VAD→ASR→LLM→TTS）延迟累积、副语言丢失。端到端 Omni 延迟低保留情绪但依赖轮次。全双工持续听说决策，支持重叠打断，把"该谁说话"变持续决策。主线：摆脱 VAD 对发言权的猜测。

**出处：** 9.1.1节。

### 10. 认知时序的三种分工

**论证：** 方案一（快慢分离）：快模型建议购买，慢模型后发现缺功能，前后矛盾。方案二（快交互慢提醒）：后台向状态栏建议，更稳定但间接。方案三（Step-Audio R1）：MGRD 防"文本代理思考"——用歌词负面词代替声学分析；MPS 双脑架构让构思和表达流水线并行。

**出处：** 9.1.5节。

### 11. Computer Use 的感知-决策-行动循环，核心在每步重新确认现实

**论证：** "看懂界面"与"完成任务"是不同能力层次。动作空间含 GUI、bash 和文件编辑，不可逆操作需批准。Anthropic 协议：鼠标含 move/click/drag/scroll，键盘模拟 12ms 间隔。

**出处：** 9.2节。

### 12. 视觉定位三条路线：结构化索引优先

**论证：** DOM/Accessibility Tree 最精确，输出 ID 即可。Set-of-Mark 分割模型切候选区叠加编号，适用 Canvas/WebGL/游戏。纯坐标预测依赖分辨率，须按宽高比选目标分辨率避免压扁。

**出处：** 9.2.2节。

### 13. 观察接口解耦：把帧叙述成持久文字是关键

**论证：** AOI 含三部件：帧间关键帧捕获、音量门控转写、帧叙述成持久文字。反直觉发现：真正起作用的不是"选哪几帧"而是"把帧叙述成文字"——文本才是 LLM Agent 最擅长的模态。八个模型无需重训 +17~+48 个百分点。

**出处：** 9.2.3节。

### 14. 世界模型让 Agent 实现推测执行

**论证：** 人类先预测后果再操作。世界模型编码当前状态预测候选动作变化，规划器执行前比较。预测是"如果这样做可能发生什么"的可比较结果，非确定答案；越远误差越大，真实观察是最终事实。

**证据：** Photon-1 用 3 万小时 H200 GPU 预训练 computer use 世界模型，每帧压缩为离散 token 自回归预测。

**出处：** 9.2.4节、9.3.6节。

### 15. 移动端 Computer Use：生态壁垒比技术更难

**论证：** 技术差异在动作空间（无障碍 API 替代鼠标坐标），非主瓶颈。真正卡住的是商业模式冲突：Agent 直奔目标绕过所有变现链路，结构性利益冲突。CAPTCHA 只是表层对抗。

**出处：** 9.2.5节。

### 16. XLeRobot 桌面实验串

**论证：** 五实验同一任务揭示差距。硬件非瓶颈——几百美元 XLeRobot 人类遥操作可完成连续多步桌面任务。Agent 自主控制在感知、失败恢复上与人类闭环存在差距。

**出处：** 9.3节、实验9-7至9-11。

### 17. VLA 控制的取舍：动作分块在平滑性与反应速度之间

**论证：** 大模型推理 1–10 次/秒 vs 控制器几十到上千次。动作分块：模型一次生成小段未来动作，控制线程高频执行。"预测—执行—抢占"每步检查安全事件和变化，可中断重规划。

**出处：** 9.3.4节、9.3.5节。

### 18. 交互架构与智能上限是两条独立的能力轴

**论证：** 理解和生成决定"会什么"及智能上限；交互能力决定能否把智能转化为任务结果。三个场景面临相同的"感知—决策—行动—反馈"延迟问题。

**出处：** 9.4节。

### 19. 可验证闭环的边界：当"完成"不等于"进步"

**论证：** 开放式科研中评价信号慢、正确答案不唯一。四次端到端尝试三次失败，暴露三类问题：实现漂移、认识论过度乐观、隐性判断力不足。应对：结论与证据分离、保留负面结果、维护多样性、人类在更高层介入。

**出处：** 8.3.3节。

## 原则清单

1. 不把原始轨迹当正式知识——保留三层：不可变原始轨迹、单次分析、跨轨迹归纳。
2. 三层验证器结构化诊断，结果和过程是硬门，验证不压缩成单一标量。
3. 经验按自然表示路由：事实→知识库，语言化策略→Prompt/Skill，确定约束→程序，隐式能力→参数。
4. 更新都是最小 diff、带来源的提案，不每轮重写整份 Prompt。
5. 待验证版本同时在边界集和保留集验证，安全集守住边界，不合成平均分。
6. 安全机制（验证器、测试用例、发布门槛、审计日志、版本备份）位于不可修改范围外。
7. 网页和工具输出的 LLM 摘要属不可信证据，不能当指令执行。
8. 在线执行与离线进化分离——首要职责是完成当前任务并追加证据。
9. 持续学习至少含记住、迁移、更新和保持四个环节。
10. 长期评估观察回退、泛化、token 效率、安全性、工程质量五类。
11. 区分 Harness 更新能力和受益能力分别评估。
12. 语音 partial 转录只触发可撤销抢跑，最终转录和副作用有明确提交边界。
13. Computer Use 优先 DOM 定位，不可得回退视觉标注或坐标预测。
14. 观察接口解耦——帧叙述成文字比加截图更重要。
15. 机器人任务顺序和眼前动作分开处理，一次工具调用只做一件事，超时立即重观察。
16. VLA 动作分块需要"预测—执行—抢占"骨架，每步检查安全和变化。
17. 世界模型预测只能帮选动作，不能替代真实观察——"能生成视频"≠"能指导机器人动作"。
18. 仿真到真机须处理背景、光照、遮挡、摩擦、噪声和延迟等多维差异。
19. 被证据推翻的知识定期修剪但保留来源和回滚版本。
20. 在反馈模糊的开放任务中，人的高层判断比逐步骤接管更难自动化也更有价值。

## 失败模式与反例

1. **将保存日志当学习**：轨迹存库不会自动完成跨案例归纳，学习只在"评价—对照—归纳—验证"后发生。
2. **单一满意度替代结构化诊断**：用户因违规退款满意，不拆分维度则学习信号被污染。
3. **把反思当证据**：反思可参与草案但不是证据——只有与环境相符、跨轨迹支持的内容才能进入正式经验。
4. **动作成功≠任务完成**：按钮都点了字段为空。须独立状态验证。
5. **快/慢思考前后矛盾**：快模型建议购买，慢模型发现缺功能——两实例独立思考。
6. **文本代理思考**：用歌词负面词代替声学分析。MGRD 筛选真正引用声学特征的思考。
7. **开环执行把局部失败带到末尾**：抓取失败后继续执行后续步骤。须每步重观察。
8. **VLA 过时观察**：物体移动后模型依据旧画面。需抢占检查。
9. **实现漂移**：科研 Agent 方案变难时退回训练数据中的普通实现。
10. **认识论过度乐观**：把噪声解释为发现，失败和阴性结果被忽略。
11. **坐标分辨率不匹配**：非等比拉伸压扁画面连带偏坐标判断。

## 关键术语表

- **持续进化闭环**：在线记录→离线诊断→提案→验证发布→灰度观察→回滚的自主循环。
- **三层轨迹验证**：结果（环境真值）、过程（权限/动作序列）、质量（Rubric评分），下层通过上位才有决策权。
- **轨迹评价 Rubric**：预定义逐维评价量表，要求引用证据输出结构化诊断。
- **经验知识库 vs 用户知识库**：前者提取"在什么条件下该怎么做"，后者提取"用户与世界是什么样的"。
- **系统提示学习**：基于失败轨迹生成最小 diff Prompt 补丁。
- **Agentic Harness Engineering**：组件、经验、决策三层可观测；编辑前声明影响，下轮验证。
- **睡眠学习**：空闲期触发，读经历、比较结论、合并冲突、提案运行回归。
- **级联流水线**：VAD→ASR→LLM→TTS，延迟累积、副语言丢失。
- **端到端 Omni**：同一模型听音频、生成回复、输出语音，延迟低仍依赖轮次。
- **全双工**：持续听说决策，支持重叠打断，发言权变持续决策。
- **MGRD**：筛选真正引用声学特征的思考，防文本代理思考。
- **MPS 双脑架构**：构思脑产思考片段，表达脑即时生成语音，流水线并行。
- **控制标记驱动 TTS**：LLM 输出 THINKING/EMO/SPEED，TTS 映射为停顿、韵律、语速。
- **Set-of-Mark（SoM）**：分割模型切候选区叠加编号，模型报编号即可。
- **结构化元素索引**：从 DOM/Accessibility Tree 枚举可交互元素。
- **纯坐标预测**：GUI 截图和坐标配对训练，文字映射到坐标。
- **AOI**：解耦观察与动作，含关键帧捕获、门控转写、帧叙述为文字。
- **Computer Use 世界模型**：编码桌面状态，预测候选动作后果。
- **VLA**：接收画面和技能指令，输出连续/离散动作序列。
- **动作分块**：模型一次生成小段未来动作，控制线程高频执行。
- **机器人世界模型**：学习状态+动作→下一状态映射，比较候选检测偏差。
- **生态壁垒**：Agent 绕过广告变现链路，结构性利益冲突比技术更难。
- **Harness更新 vs Harness受益**：产生修改 vs 正确使用修改，可能被不同模型能力限制。

## 高亮核心论断与金句

- %%H%%Agent面临的能力悖论：它可以零样本解决从未见过的复杂任务，却可能在处理了一万次相似任务之后，第二天仍然犯下第一天的错误。%%/H%%

- %%H%%保存经历不等于从经历中学习。学习发生在系统主动完成"评价、对照、归纳、验证"之后，而不是发生在日志写入磁盘的那一刻。%%/H%%

- %%H%%第三章的用户记忆主要沉淀"用户与世界是什么样的"，本章的经验学习则要进一步沉淀"在什么条件下应该怎样行动"；前者让Agent记得更多，后者才让它从聪明变得熟练。%%/H%%

- %%H%%错误的评价一旦进入长期知识、系统提示或训练数据，影响会跨越后续任务不断放大。%%/H%%

- %%H%%结果正确并不代表过程正确。删除失败的测试用例也能让测试通过，口头承诺用户"我们会在7天内退款"也可能得到暂时的满意反馈。%%/H%%

- %%H%%验证器负责给出评价和证据，至于应修改Agent的哪个部分，则应由独立的诊断与进化模块决定，避免同一个模型既当裁判又直接改写规则。%%/H%%

- %%H%%流程记忆必须同时具备动作前验证、动作后验证和独立回放验证。否则系统很容易得到一种危险的假象：每个按钮都点过了，但某个字段其实为空，任务从未真正完成。%%/H%%

- %%H%%能确定执行的约束应该进入程序，而不是继续堆在Prompt里。%%/H%%

- %%H%%搜索空间越大，可信根（评价器、权限边界和留出测试必须位于可修改范围之外）越重要。%%/H%%

- %%H%%持续进化的上限，最终取决于系统能否评价它真正关心的目标，而不只是最容易测量的代理指标。%%/H%%

- %%H%%单元测试全部通过，只证明当前可观察行为满足测试，并不证明代码库在数月后仍易于维护。%%/H%%

- %%H%%交互能力与智能上限并不直接相关，它主要决定模型能否在真实环境中把已有的智能有效地转化为任务结果。这和人的聪明程度与岗位表现之间的关系是类似的。%%/H%%

- %%H%%贯穿三种范式的主线是：如何摆脱"轮流说话"和VAD对发言权的猜测。级联和Omni仍要划分轮次，只有全双工把"该谁说话"变成模型的持续决策。%%/H%%

- %%H%%真正起作用的不是"选哪几帧"，而是"把帧叙述成能长期留存的文字"——文字才是LLM Agent最擅长处理的模态。%%/H%%

- %%H%%Agent的每一次操作都在侵蚀其商业模式的根基。这意味着Computer Use面对的不仅是CAPTCHA等技术层面的对抗，更是一个结构性的利益冲突。%%/H%%

- %%H%%对于这个任务，硬件本体不是瓶颈，算法才是瓶颈。%%/H%%

- %%H%%语言模型知道"杯子"是什么，并不代表它知道摩擦、接触、液体晃动和电源线会怎样改变未来状态。%%/H%%
