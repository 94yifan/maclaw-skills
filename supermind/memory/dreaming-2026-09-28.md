3. **负面结论带有效期（守卫Z，沿用）**：外部依赖不可达类结论写 `<对象> 不可达（实测 YYYY-MM-DD HH:MM，下轮须复测）`。

- **机制**：两条都为超时问题而生的规则在同一份文件里冲突 ——
  1. 落盘前置（保数据）要求整份报告在 run 前段一次性写出；
  2. 守卫十七（保诚实）要求完成断言后紧跟本会话证据。
  当报告里既含事实、又含「本轮将做/已做」的动作陈述时，第 1 条把第 2 条挤出局：报告写完了，动作还没做。
- **修法**：把报告拆成两段写 —— 第一轮只写「已验证事实 + 待办动作（将来语气）」；动作执行后追加「动作 + 证据输出」。**完成态表述的写入时点由「动作是否已完成」决定，不由「报告是否已开始写」决定。**
- **判据**：任何 run 的第一轮写入里，出现「已完成/已修复/已回填」类词的地方，必须能当场指向同文件内上一行的命令输出；指不出即改写为待办语气。
- **客户用法**：交付文档里承诺「已完成」的每一项，落笔前必须已存在于交付物中；进度报告不以完成时态描述未执行动作。
