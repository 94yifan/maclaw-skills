### 重要教训

**1. 飞书 API 不支持 Markdown 表格：** v1 用 feishu_doc write 输出 Markdown 时表格全转成了列表，导致逸凡看不到任何数据对比。以后给逸凡的复盘报告优先用 DOCX，其次 Markdown 文件。

**2. my.feishu.cn 个人域名文档无法通过 API 读取：** 四步法文档（my.feishu.cn/wiki/MODiwJ2JFiUktfkOGozcD8pTn9d）飞书 API 返回 403，web_fetch 被登录页拦截。需要 Chrome CDP 远程调试或逸凡手动截图。

**3. 吸黏拽是 SEM 选词策略模型，不是全报告框架：** v2 错误地把吸黏拽放在第一章作为全报告框架，逸凡纠正后移回第三章搜索投放分析内。吸黏拽只在搜索投放分析中使用。

**4. data-report-review 检查模式是审同事报告的，不是自审：** 逸凡明确了分支：检查模式是同事写好后帮忙查缺补漏+给修改内容；重写模式是报告大面积崩了直接重写。我自己的报告不需要额外启动这个 skill。

**5. 文件大小限制：** 蓝氏 v3 DOCX 44MB 超过飞书群聊限制，需要压缩至 6MB 才能发送。后续生成带截图 DOCX 时需控制图片分辨率。

**6. OnePage 是出品基准，不是"参考风格"：** 培训手册需要把 Part 1-4 结构打散重排为 GRARI 五模块（G-R-A-R-I），每个模块对应教怎么写，而不是简单的标题替换。
