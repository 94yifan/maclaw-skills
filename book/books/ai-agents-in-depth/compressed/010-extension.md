# 延伸思考与自检

## 费曼式提问：检验你是否真的读懂了

1. **用一句话向一个不懂技术的朋友解释**：为什么"给 Agent 更多上下文"比"换一个更强的模型"更能提升表现？如果讲不清楚，说明你对第1-2章的核心等式还没吃透。
2. **说出三个"检索而非推理"的日常例子**：书中用"100 个笼子 90 黑猫 10 白猫"证明模型不擅长主动归纳。你能在生活里找到模型"查得到但数不清"的同类场景吗？这决定了你的 Agent 该在哪一层补上"提炼"。
3. **假如你的公司要做一个 AI 客服 Agent**：按照第2章的缓存架构约束，你会怎么设计系统提示词和动态信息的存放位置？如果答不上来，回到 2.3 节 KV Cache 那三条核心结论。
4. **解释"隔离优于压缩"**：为什么说子 Agent 上下文隔离比压缩更釜底抽薪？压缩和隔离各自的代价是什么？
5. **第8章说"完成不等于进步"**：你如何判断自己的 Agent 系统是在进化，还是在空转？书里给的尺子是什么？

## 决策规则（if-then 格式）

- **IF** 你发现 Agent 频繁重复执行已完成的操作或前后决策矛盾 **THEN** 检查是不是去掉了思考过程或历史消息（消融实验四类退化之一），而不是先换模型。
- **IF** 你准备在系统提示词里加动态内容（时间、用户状态）**THEN** 改成追加到对话末尾的新消息，不要修改静态前缀。
- **IF** 你需要模型基于长历史做统计、计数、聚合 **THEN** 用代码先算好结论注入上下文（状态栏思路），不要指望模型自己归纳。
- **IF** 你要决定"工作流还是自主 Agent" **THEN** 先优化单次 LLM 调用，再考虑工作流，最后才引入自主 Agent；关键合规流程走工作流，灵活决策切自主。
- **IF** 你要引入第三方 Skill **THEN** 先审查其内容（Skills 是提示注入的新攻击面），安装来源不明的 Skill 前必须检查。
- **IF** Agent 声称任务完成 **THEN** 不要直接信，加提议者-审核者机制或完成验证（"过早声明完成"是长时运行 Agent 的高频失败模式）。
- **IF** 你发现 Agent 决策质量莫名下降但上下文远未满 **THEN** 警惕上下文腐化（Context Rot）——无关内容稀释注意力，做分层压缩而非全量堆砌。
- **IF** 你判断"换更强的模型能不能解决这个问题" **THEN** 先检查：任务数据是否在观察空间内？操作是否有对应工具？接口问题优先于模型问题。
- **IF** 你想给 Agent 加记忆 **THEN** 遵守生命周期闭环：检索→回答→后台提取→来源与策略核验→更新，绝不让未核验字符串直接成为事实。
- **IF** 你的 Agent 要处理敏感数据日志 **THEN** 本地小模型脱敏，不上云（脱敏本身不能成为泄露点）。

## 与逸凡业务场景的关联（曼拾视角）

- **创始人读这本书的最大价值**：不是学会写 Agent，而是建立"能力上限由什么决定"的判断力——当你评估任何 AI 产品、团队、供应商时，第一问应该是"它的上下文和工具设计如何"，而不是"它用的什么模型"。模型是商品，上下文和接口是护城河。
- **团队建设隐喻**：书中"AI 原生团队首先是一场文档化运动"的论断，对曼拾同样成立——信息透明、决策有记录、新成员能通过阅读历史理解演化逻辑，这样的组织天然对 AI 友好，也天然对新人友好。
- **产品决策启发**："评估是进步的尺子"——曼拾任何新功能上线前，先定义怎么衡量，再谈迭代。没有评估就没有进步，这句话在创业里和 Agent 工程里一样成立。
- **警惕"名词流行才行动"**：书中最尖锐的一句话是"如果你每次都要等到业界开始流行某个 Agent 名词才去实践，就已经慢了一步"。对创始人：跟随热词做事永远慢半拍，先于名词实践、让实践定义名词，才是真正的领先。
