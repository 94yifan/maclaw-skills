## B. 规避方案（写成铁律，本轮新增三条）

1. **「随机」先查生成侧定义（对应 A1，最高优先，本轮新增）**：发现同一动作时对时错且无成文规则时，第一步读生成侧规范（模板/payload/schema），确认该字段是否被定义为必填；未定义就先改生成侧，再谈校验。**「随机」是规范缺口的症状，不是执行的症状。**
2. **一致性检查覆盖形态与颗粒度（对应 A4，本轮新增）**：检查清单固定三行——内容对不对、形态稳不稳（数字/头尾带不带）、颗粒度是否同源（到日还是到分）；目的是**找差异项**，不做已知项确认（确认已知项＝零信息）。
3. **收录按「线」核对，不按「条」核对（对应 A5，本轮新增）**：上游剧集化/系列化产出时，逐条核对 «预告 / 正式 / 延展» 是否全部落点；守恒式 `raw = 引用 + 剔除 + 未明引` 未明引必须为 0。
4. **依赖链单点即结构性风险（对应 A7/A9）**：盘点任一主体知识输入的来源占比，单一上游 100% 即列为结构性风险；解法是补独立输入源或定期外部抽样，不是加强形式校验。
5. **提醒窗口到期必须落状态（对应 lanshi 今日做法）**：窗口规则的文本必须写明到期后去哪（升级 / 转待跟进清单 / 显式关闭），写不出即默认丢弃。
6. **沿用未落地项（仅主 session 执行，cron run 内禁止尝试）**：payload 运行内工具禁令（第 8 天）、payload header 必填（今日新增）、交付兜底、header 存在性校验、window 改造一步到位（第 10 天）、SC dreaming cron（第 21 天）、CFO cron failureAlert、飞书云文档存档、跨主体 MEMORY 归档。
