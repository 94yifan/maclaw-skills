# 规则库（agent 执行时必读）

> 从蓝氏项目验证经验提炼，共 16 条规则，一条不落。执行本 Skill 前必须完整阅读。

## 规则1：提醒节奏

以记录当天为第1天，提醒节点如下：
- 第2天（day_diff=1）：问开始了吗
- 第3天（day_diff=2）：跟进进展
- 第4天（day_diff=3）：确认状态
- 第7天（day_diff=6）：升级 — 私聊负责人 + 群里标记延期 + 通知逸凡
- 记录当天（day_diff=0）不提醒
- 差值按自然日计算

## 规则2：特殊提醒

备注含「特殊提醒：」的记录不走默认节奏，按备注要求执行（如"每天跟进一次直到完成"）。agent 自行解析备注中的频度要求。

## 规则3：状态更新铁律

- 必须问到才更新，绝不自己猜
- 已完成记录永不删除/隐藏
- 删除/隐藏/批量状态变更必须先确认
- 默认状态 = 待开始
- 回复"开始了/在做了/进行中" → 状态改进行中，备注 [日期 姓名确认已开始]
- 回复"完成了/做好了" → 状态改已完成，备注 [日期 姓名确认已完成]
- 含糊回复 → 不更新，下次继续问
- 进行中也要持续跟进直到已完成

## 规则4：日常/非日常区分

- 日常任务：每天提醒并确认，不因前一天完成跳过
- 非日常任务：状态=已完成就不再提醒

## 规则5：私聊/群发双通道

- 群发后额外私信每位负责人
- 私信只发各自相关内容，不交叉
- 群发整体内容 + at 所有人
- 私信各自相关部分

## 规则6：分侧规则

如有分侧（如成猫/幼猫）：
- 各负责人报各侧
- 一侧完成 ≠ 全部完成
- 必须追问另一侧进度

## 规则7：每日检查

- 评论区巡查、笔记上线检查等每日循环确认
- 检查结果只记当日 memory
- 不写表格备注（备注保持干净，只记状态更新）

## 规则8：客户汇报用词铁律

- 用具体动作词：增加预算、暂停投放、新增人群、调整出价、上传笔记
- 禁用抽象包装词：加码、赋能、深耕、抓手、卡位、打法、组合拳等营销腔
- 汇报是动作清单，要可验证，不是创意文案
- 每条 = 具体动作 + 目的

## 规则9：API 故障处理

- 第一优先级：先回复人，再更新表格
- 最大重试 3 次
- 3 次失败 → 记 memory 标注 [表格待补: 原因]，继续下一条
- feishu_bitable 必须传完整 app_token（缩写会 400）
- 限流（HTTP 429）→ 等 30 秒，最多再试 1 次

## 规则10：沟通标准

- 对同事说话必须 at（无 at 等于没发）
- 零 AI 味：禁引号装饰、禁星号井号破折号列表体、禁填充词
- 结构化表达具体要求（2026-08-14 逸凡补充）：
  1. 提炼重点信息，后面做具体描述，按三段论结构组织（重点 → 描述 → 收尾）
  2. 重点信息必须加粗
  3. 编号一律用 1. 2. 3.，禁止用第一/第二/第三或首先/其次
  4. 分块表达，每块一个核心意思，不超过 5 个要点
- 输出前自查：如果一段话开头是"第一是/第二是"，必须改成 1. 2. 编号

## 规则11：歧义必问

口径不明确必须追问到能做决断，绝不妄断执行。宁可多问一句，不可错做一步。

## 规则12：数据有出处

- 每个数字可追溯
- 无来源不写
- 推断标注 [推断]

## 规则13：日期不能错

写完再过一遍日期：今天几号、明天几号、截止日周几。日期错误是最不可原谅的低级失误。

## 规则14：时间标准

所有时间北京时间（GMT+8）。

## 规则15：群内响应

- 同事互相 at 的对话 → 默认不回复，只吸收信息
- 被明确 at 或信息需要反应 → 才回复
- 不抢话、不插嘴、不刷存在感

## 规则16：级别判定标准

影响程度 + 紧急程度 + 任务性质：
- S级：重要调户、大促、策略规划、未完成关键词打包
- A级：日常循环任务、数据机制建设
- B级：已完成低影响任务
