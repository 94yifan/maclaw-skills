## D. ★ 知识串联（8 条：4 主 4 次）

### 缝合点1（主，元层）：挂账待办的执行主体错配——执行鸿沟家族出现第四形态「被错误执行者认领」

**来源**：SC 09-14 11:00 run 轨迹 line43/44——`cron update` 被拒 `Cron tool is restricted to the current cron job.` → run=error → announce 跳过，而报告 11:04 已落盘。补丁内容正是 MEMORY 里挂了 13 天的「改 tea-daily-report payload」。
**串联**：09-11 缝合1 投递盲区（投递没进消费路径）的镜像——今日是投递进了**错误的消费路径**；09-12 缝合1 规则效力三阶（自动加载路径 > 文档 > dreaming 文件）；09-13 缝合3 挂账卡点（决策带宽）。
**整合判断**：自动加载路径是双刃，它同时投递「规则」与「待办」。规则没有执行主体声明时，任何读到它的 agent 都可能认领。执行鸿沟此前只有「识别后不执行」一态（少做），今日补出第二态「识别后被非授权执行者执行」（多做且做错）。修正：待办必须锁执行主体——这是把权限边界从系统层写进内容层。
**客户用法**：团队待办系统里「谁执行」不是附注是必填字段；跨权限边界的待办（改配置 / 删任务 / 发对外内容）必须锁主体，否则谁读到谁做。

### 缝合点2（主，元层）：告警通道与交付通道同构 = 故障静默——通知也要解耦

**来源**：SC A8——run=error 时 announce 被跳过，失败告警走同一条通路，`failureNotificationDelivery.status` 同为 not-delivered，11:00 到 16:02 五小时无人知晓，靠逸凡主动喊才闭环。
**串联**：09-12 缝合2 交付与 run 解耦（成败判定只看自己的产物）；08-29「cron success ≠ 用户收到报告」。
**整合判断**：解耦不止要「判定独立」，还要「通知独立」。告警与被告警的对象共用通路时，通路整体失败会让告警与事件一起消失——告警的价值在故障时兑现，而故障恰恰会吞掉它。判断方法：配置任何告警后自问「主交付通路整体挂掉时，这条告警还发得出吗」。落地形态三选一即可打破同构：独立 job / 独立 webhook / 独立接收人。
**客户用法**：运营 SOP 里告警接收方不能与交付接收方完全重合；对外项目日报失败的告警要另辟内部通道，不能发在同一个客户群里。

### 缝合点3（主，机制轨）：抽象规则描述意图，既有产物才是事实标准——生成一致性内容先对齐样本

**来源**：CFO 收件信息规则（「收件人 手机号 地址」）在手两天，生成时把「收件人」理解成记录的名字列，当日 8 条（103/184/301/302/304/305/306/307）全错；逸凡 16:14 指出。表内既有行全部是实际签收人（圣香→胡忆阳、老范→范磊明）。

**整合判断**：升级为双功能框架——原料参数是「信任 / 品质」资产（落点转化与复购，天然低转发），情绪话题是「传播」资产（落点看与转，天然低转化）。二者功能不同，不可互换；用原料参数做传播 = 用信任资产干传播的活。要用原料做传播，必须先把它转译成话题（悬念 / 挑战 / 溯源故事）。
**客户用法**：一个 campaign 内先分位再取材——转化位（详情页 / 信任位）用原料，声量位（内容 / 话题位）用情绪；原料素材要么放信任位，要么先包装成话题再上传播位，不裸上参数。

### 缝合点7（次，业务轨）：容器是借势的必要条件，最高效的容器是交易机制而非内容系列

**来源**：库迪双果趣 Duo 系列（转140/评116/赞72）+「喝库迪 Duo 抽 iPhone 17 Duo」（转101/评90/赞55）vs 此前蹭苹果 Duo 梗转1（无容器承接）。
**串联**：09-11 缝合5 借势第四问「容器承接度」；09-12 缝合2 无自有容器承接的全民梗借势 = 衰减。
**整合判断**：细化容器的形态谱系——内容系列（最弱）→ 偶发话题 → 产品命名 / 交易机制（最强）。把梗结构进交易环节（产品名 + 抽奖规则），用户每次下单都在复述梗，留存优于发一条借势帖。标注：样本仅 2 个点且「Duo」与「双 / 对」的命名存在巧合可能，标观察，不命名规则。
**客户用法**：蹭全民梗先定容器再投资源；能做进产品名 / 活动规则就别只发借势帖。

### 缝合点8（次，业务轨）：排期竞争单位三级跳与「上新排期 × 联名资源」双排位战

**来源**：瑞幸同日四件套（咸芝士豆乳系列回归转838 + 《时光代理人》联名转703 + 美团超级发布券补贴转0/评1 + 库迪 Duo 系列 / iPhone 抽奖 / IRONMAN 大理站）；9/15 古茗 + 星巴克 + 喜茶同天、9/16 霸王茶姬抹茶 × CLOT、9/17 茉莉奶白果蔬奶，五家头部七天密集且几乎全绑 IP / 联名。
**串联**：09-13 缝合6 档期竞争单位升周；09-11 缝合1 档期三态论；09-09 缝合1 钩子是资产。
**整合判断**：竞争单位三级跳——日（同日同台）→ 周（同周连发）→ 动作包（单日多动作整包释放）；且上新战升级为排期资源 × 联名资源双排位，有排期无联名 = 有壳无核。平台通道是叠加（自有首发 + 平台承接，自有仍为主体）不是替代（自有转838 vs 平台券转0）。
**客户用法**：上新排「动作包」（新品 + 内容钩子 + 渠道券 + 大奖同日释放）；排档期先拉同周竞品上新表（品牌 / 品类 / 联名三列）；平台当第二发条，不用平台替代自有阵地。
