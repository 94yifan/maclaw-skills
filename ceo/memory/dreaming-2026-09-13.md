## B. 规避方案（对应 A 项，写进 memory 作为下次执行铁律）

1. **交付与 run 解耦（对应 A1，全局规则）**：本 job 及一切 cron payload 禁止末尾放探索性命令（`ls`/`cat`/`grep` 不存在的路径）；可选项一律加 `|| true`；交付判定只看 `lastDeliveryStatus`，不看 run status。**本次 run 起，本复盘正文写入完成后不再执行任何非必要 shell**
2. **挂账推送改「一个决定」形态（对应 A2/A3，最高优先）**：摘要里的系统待办不再给命令原文清单，压成「我已列好 N 项改动，回 1 即执行；其中 K 项需你授权（列出哪几项）」。判断标准：逸凡的认知成本必须低到「一个字符」
3. **状态类数字实时读取（对应 A2，吸收 CFO 的 A1）**：凡向逸凡输出的状态类数字（挂账天数、表内条数、cron 参数），来源必须是本次会话的一次实际读取；MEMORY.md 记载与昨日报告不构成来源
4. **体积自检绑定（对应 A4）**：Dreaming 进入复盘前先 `wc -c MEMORY.md`，超 140KB 即归档最老区块（保留近 7 天 + 全部方法论）；这是决策点动作，不是常驻备注
5. **执行项回归核对表（对应 A5）**：本复盘末尾固定附「前日执行项落地核查」表，格式＝昨日项 | 今日状态

## D. ★ 知识串联（核心环节）

### 缝合1（主，系统层）：系统待办闭环第五变量「决策带宽」——路径打通、窗口打开、送达确认全部满足后仍 0 执行，卡在决策者当轮无认知余量

**来源：** 今日三个新事实——① 09-07 定的「逸凡出现时首条消息置顶推送挂账」规则**首次真正执行**（CFO 13:03 把 cron 修复三项推到她面前，送达成功、独立于业务消息），她当轮只办业务、未拍板，CFO cron 挂账第 23 天；② CEO 通道全天零交互；③ supermind 同日独立得出同向结论（挂账卡点第三次迁移：路径距离→注意力窗口→决策带宽）。

**串联判断：** CEO 侧框架逐日补全：09-01「复盘生命周期三段论」（产出→消费→转达）、09-07「执行路径可达性三分类」（路径距离）、09-10「三变量（路径可达性 × 注意力窗口 × 送达通道独立性）」、09-11「执行权层级（第四变量）」＋「注意力只对问句开放」→ 今日补第五变量。**挂账闭环 = f(路径可达性 × 注意力窗口可用性 × 送达通道独立性 × 执行权层级 × 决策带宽)。** 第五变量与第二变量不同：注意力窗口解决「看得见」，决策带宽解决「算得动」。窗口打开了、内容也送达了，只要当轮的认知余量被业务占满，系统事项仍然 0 执行。

**本轮最强判断（写进 MEMORY.md）**：投递形态与闭环率强相关——给命令原文清单＝把「要不要改、改哪几项、怎么改」的认知成本一并交给对方，等于把决策摊薄成 N 个小决策；压成一个决定＝只交付一个字符的决策成本。CEO 摘要从「信息投递」改为「决策触发」，是今日唯一可立即执行的结构性修复。

**管理同构：** 给老板的周报里，「需要您知道」与「需要您拍板」必须物理分开——前者进通知区（可不读，不产生挂账），后者压成一句话选项（读即闭环）。
**BD 同构：** 客户侧待办不发方案全文等回复，发「一个决定＋一句话授权」。

**串联判断：** 规则缺口不会以「不知道怎么办」暴露，而以「每次办得不一样」暴露。**只查错查不出这种缺口**——因为错误没有发生。正确方法是找同机制的多个样本，比较处理结果是否一致；不一致且无成文规则即为缺陷。这是普遍化检验的工程版：同机制两件事被相反处理，说明背后那条准则不具备可普遍化的形式。
